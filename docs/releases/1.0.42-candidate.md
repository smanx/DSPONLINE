## 玩家可见变化

- 35 MiB 合法存档即使解析/写入超过 15 秒，同一标签页也不会因自己的租约心跳延迟被误判为外部覆盖。
- “当前为空、候选有效”会明确解释两个选择并推荐候选；两个按钮显示处理中、成功或具体失败原因，活动 writer 可等待后重试。
- 候选只有在写入、逐字读回、revision、checksum 和模式验证全部通过后才清理；清理中断后可安全重试。
- 增产剂缓存增加 100 万预设，自定义允许 1～100,000,000 的十进制正整数。
- 无限矿物的合格 speedrun main 可提交正式速通榜，公开记录显示“无限矿物”；普通模式和其他禁止状态仍拒绝。
- 没有有效纯挂机 journal 时，遗留的时间扭曲 pending wall time 会并入普通离线一次，未提交高倍率预算丢弃；无法自动核验时提供“恢复检查点并快速结算”，取消不改原档。
- 原有动态安全区、移动原子导航、焦点/inert、亮暗对比度、高字号/触控、中文输入和教程 revision 改进全部保留。

## 本地与云兼容边界

- 新 API 向后兼容 1.0.41 Web/Android/Windows 的旧值和旧 DTO；公开速通 DTO 的新增字段会被旧客户端忽略。
- 1.0.42 Web 设置增产剂上限超过 100,000 后，必须由 1.0.42 API 接收；1.0.41 API 会按旧规则拒绝。因此发布顺序必须先升级兼容 API，再切 Web。
- 1.0.41 客户端可读取 v46 新正文但会把超过其旧上限的增产剂设置夹回 100,000；玩家跨设备继续使用旧客户端并再次保存时可能降级该偏好。Release UI/公告应提示使用新客户端。
- 无限矿物速通提交同样要求新 API；旧 API 仍会拒绝。普通银河榜、普通/速通云命名空间、main/手动槽隔离均不变。
- Web 回滚可以保留 1.0.42 API；一旦接受过上限超过 100,000 的云档或带资源标签的新 submission，不应把 API 直接退回不兼容的 1.0.41 验证器。

## 性能影响

- 相对旧 1.0.42 UI 候选，通用启动闭包增加 1,359 B gzip（约 0.74%），菜单闭包增加 7,979 B（约 2.91%）；两者仍通过预算。
- 正常保存只增加同一 IndexedDB 写事务中的一次精确 owner/token 续租，不进入模拟帧循环。冲突恢复增加第二阶段逐字读回和清理事务，只在玩家处理冲突时发生。
- 35.5 MiB 脱敏状态在开发机 Chromium 中提交/读回约 2.8 秒；玩家附件正式检查约 35.9 秒，说明低配设备仍需真实验收，不能承诺固定耗时。
- 时间扭曲适配为启动时一次 journal 读取和 O(1) 状态复制，不改变 Worker 模拟步数。增产剂上限和速通标签不增加每 tick 循环。
