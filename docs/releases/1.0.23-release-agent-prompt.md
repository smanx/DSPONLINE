# 1.0.23 发布 Agent 安全交接提示词

Role: `release`

你负责把开发 Agent 已完成并签名校验通过的 `1.0.23` 候选版本发布到香港节点、上海节点和下载页。不要修改游戏源码；不要把任何私钥、密码、token、keystore 或证书内容写入仓库、日志、命令输出或聊天。

## 输入制品

- 开发提交：`<DEVELOPMENT_COMMIT_SHA>`
- 发布清单：`<MANIFEST_PATH>`
- Web/API 归档、下载页归档和原生安装包必须与清单中的 SHA-256 完全一致。
- 只接受清单中明确标记为 `1.0.23` 的不可变制品，不使用 dirty 工作区的 `dist/`、玩家存档或临时目录。

## 凭据注入

发布机先从安全凭据管理器或本机受保护环境变量加载以下变量。变量值不得回显，脚本失败时也不得打印其内容：

```text
DSP_HK_HOST
DSP_HK_SSH_USER
DSP_HK_SSH_KEY_PATH
DSP_SH_HOST
DSP_SH_SSH_USER
DSP_SH_SSH_KEY_PATH
DSP_ANDROID_KEYSTORE_PATH
DSP_ANDROID_KEY_ALIAS
DSP_ANDROID_KEY_PASSWORD_REF
DSP_ANDROID_STORE_PASSWORD_REF
DSP_WINDOWS_SIGNING_CERT_PATH
DSP_WINDOWS_SIGNING_CERT_PASSWORD_REF
```

`DSP_HK_SSH_KEY_PATH` 必须指向负责人提供的香港 VPS PEM 文件；上海使用独立 SSH 密钥。不要把 PEM 路径、证书路径、密码或密码引用替换成具体值写入本提示词。Android 长期签名 keystore 和 Windows 代码签名证书必须与上一正式版本的证书链一致；任一证书不可读、指纹不一致或密码不可用时立即停止，不得生成新证书冒充升级包。

## 发布顺序

1. 在本地验证清单、版本、构建 ID、所有文件哈希和 Android/Windows 签名；确认 Android versionCode 高于已发布版本，Windows 包的云 API、更新地址和 stable 通道为 HTTPS。
2. 分别连接香港和上海，读取当前 `current` 指针、服务状态、Nginx 配置、磁盘余量和回滚目录。发布前通过 SQLite Backup API 创建并验证生产数据库备份；禁止复制或修改玩家存档数据。
3. 将 Web/API 归档解包到新的版本目录，运行依赖安装和服务测试；不要覆盖旧目录，不要先改 `current`。
4. 先切换香港，再做健康检查和最小只读 smoke test；通过后再切换上海。两个节点必须保持独立，不得互相代理或共用数据库。
5. 将已验证的 Android APK/JSON、Windows EXE/latest.yml 和 Web 下载页归档放入新的下载目录，更新下载页 `current` 前先做完整下载、哈希、Range、缓存头和版本清单校验。
6. 使用原子切换脚本更新公开入口。切换失败必须自动或手动回到原 `current`，不得在生产目录热改文件。

## 1.0.23 必验项目

- 云上传压缩使用持续消费的 gzip 流，不出现压缩死锁。
- CompressionStream 不支持、压缩异常或压缩阶段超时，只允许一次安全的明文回退；用户取消不得发回退请求。
- 网络超时先核对远端 revision、checksum、savedAt 和摘要；已提交才显示成功，状态未知不得显示绿色成功。
- 主存档、手动槽位 1-3、银河页面、自动同步和冲突覆盖上传均能完成；成功后云端 metadata 立即刷新。
- 进入游戏和上传时可以放弃离线运算；放弃不发放离线收益且不会重复结算。
- 使用 1-2 MB 测试存档和经批准的本地合成夹具验证上传，不把真实玩家存档上传到生产测试账号。
- 上传失败或取消不覆盖本地有效存档，不删除备份或快照。

## 发布后报告

报告必须包含：香港/上海目标、旧新 release 目录、Git SHA、build ID、制品与签名指纹、清单聚合哈希、备份路径与校验结果、服务/Nginx 健康结果、下载页 URL 与哈希、smoke test 结果和明确的回滚指针。报告中只能出现指纹、哈希和路径标识，不能出现密钥、密码、token、证书私密材料或玩家存档正文。

若任一发布门禁、签名、备份、健康检查或凭据加载失败，停止发布并报告阻塞原因；不要绕过门禁、放宽上传上限或使用未签名包。
