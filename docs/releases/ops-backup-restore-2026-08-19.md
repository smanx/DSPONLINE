# 2026-08-19 备份与恢复运维加固记录

## 范围

本次只调整香港/上海的备份、恢复演练、节点探针和 systemd 配置。没有构建、上传、发布或切换 1.0.46；Web/API 应用软链接、生产 SQLite、账号、玩家存档、排行榜和下载站均未替换。

## 发现的问题

1. 香港日备份曾把 SQLite Backup API 的明文 staging 直接写到 COSFS。任务运行超过 21 小时仍未完成，同时在线库 WAL 增长到约 3.25 GB。
2. 上海恢复演练脚本引用应用 `/opt/dsp-idle-cloud/current/deploy`；当前应用制品不含该入口，定时任务无法证明密文可恢复。

## 处置

- 先停日备 timer，再终止唯一卡住的备份 service；确认没有进程占用、没有密文或 manifest 后，只删除该次不完整明文临时文件。通过正常 SQLite checkpoint 将 WAL 从约 3.25 GB 收敛到 0，没有直接删除 WAL。
- 将日备 staging 恢复到香港本机，完成一致性快照、`quick_check`、认证加密和 manifest 后，通过固定主机指纹与受限账号传到上海；本机密文保留数为 2。
- 在两端安装独立不可变运维包 `ops-20260819-5487a74`，由 `/usr/local/lib/dsp-idle-ops/current` 原子引用。应用发布或回滚不再改变备份、恢复和节点探针的可执行入口。
- 为备份和恢复 service 增加有限超时及启动中状态；上海恢复私钥通过 systemd `LoadCredential` 注入，未放宽原私钥和父目录权限。
- 保留操作前 unit、drop-in 和受保护环境文件副本，供配置级回滚；未复制或记录任何密钥内容。

## 回滚边界

- 运维配置回滚只恢复对应 unit/drop-in 和受保护环境文件，再执行 `daemon-reload` 与隔离验证。
- 不用数据库恢复来回滚代码或 systemd 配置。
- 当前生产回滚点、事故源快照和最近发布回滚点继续保留；任何旧数据库副本只有在异地对象和独立 SHA-256 已验证后才能解除。
