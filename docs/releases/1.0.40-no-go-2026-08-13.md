# DSPidle2 1.0.40 发布 No-Go 记录（2026-08-13）

> 本文件随 1.0.41 返修分支纳入版本控制，事实来源为 Release Agent 在 `D:\GameDev\DSPidle2-v140-leaderboard` 留下的同名记录。它不是 1.0.40 正式发布记录。

## 结论

精确候选 `1.0.40-58d3e6f986ec` 在真实 Linux/systemd/Nginx 发布门禁中失败，已撤销并永久禁止用于生产切换。1.0.40 没有正式发布：香港、上海 Web/API 最终且当前均保持 `1.0.39-fb54f2148dd6 / 1.0.39+fb54f2148dd6`；上海下载站、Android stable 和 Windows stable 保持 1.0.38；香港 previous-stable 保持不可变 1.0.37。

失效候选的运行时 SHA 为 `58d3e6f986ec098061a0a2109e149e1065a12c48`，Build ID 为 `1.0.40+58d3e6f986ec`。该候选曾通过本地自动化和制品复验，但真实发布控制面失败证明这些结果不足以授权生产。修复必须生成新的源码 SHA、Build ID、归档、manifest、SBOM、provenance 和交接，不能复用任何 1.0.40 制品。

## 实机门禁发现

### 1. handoff proxy 经软链接静默退出

systemd 从 `/usr/local/lib/dsp-idle-release/current/api-handoff-proxy.mjs` 启动。旧 `directInvocation()` 只比较字符串路径，经软链接时与模块 URL 不相等，代理以 0 退出；`Restart=always` 随后触发 start-limit。FakeRuntime 没有覆盖真实 `current` 软链接入口。

### 2. `/run` 生命周期删除待切换状态

release switch 把 pending state 写入 `/run/dsp-idle-cloud/active-start.json` 后停止旧 writer。共享 RuntimeDirectory 生命周期可删除该文件，新 active entry 随即读取尚未发布的 `switch-state.json` 并因 `ENOENT` 退出。pending journal 不能依赖参与 unit 的临时运行目录。

### 3. writer lock 所有权错误

root 运行 `flock --nonblock /run/dsp-idle-cloud/writer.lock true` 可留下 `root:root 0644` 文件。`ubuntu` writer 无法以写方式打开，active unit 每约三秒重试，形成真实重启循环。旧测试没有覆盖 UID/GID、umask、真实 inode 和 systemd 重启策略。

### 4. 旧 API 恢复与备份窗口不兼容

1.0.39 没有 `/api/ready`，失败恢复先等待完整 ready timeout，延迟旧服务恢复。香港旧服务重启还会立即创建约 3.2 GiB 快照；I/O 紧张时 health 和业务请求超时。恢复必须立即识别明确的 readiness 404，并继承低流量备份窗口或启动宽限。

### 5. ext4 大备份复制不适合热节点

两节点 ext4 均不支持 reflink。旧 `preparePreflight()` 在 FICLONE 失败后直接完整复制 3.2 GiB 备份，没有带宽/IOPS 上限。一次未限速 Online Backup 造成 I/O 饥饿；一次过度限速尝试又因长读事务保留并增长约 4.5 GiB WAL。发布关键路径不能无条件复制大库，也不能以手工删除 WAL/SHM 收口。

## 用户影响与生产恢复

- 初次香港在线备份 I/O 窗口记录 575 个 5xx，包括 559 个 504 和 16 个保护性云上传 507。
- 香港灰度与自动恢复窗口记录 82 个 5xx，包括 65 个 503、15 个 504 和 2 个云上传 507。
- 受影响云上传均应在服务恢复后由玩家重试；本地存档未因此修改。
- 最终生产拓扑恢复后两节点新增 502/503/504 为 0；服务和数据库未回滚，排行榜历史和玩家云 revision 未修改。

两节点数据库始终独立，没有跨节点复制、恢复、合并或回滚。Release Agent 没有把生产数据库或玩家存档下载到开发机，也没有使用真实账号做写测试。生产最终保持 1.0.39 Web/API 和 1.0.38 原生 stable。

## 1.0.41 返修硬门禁

1. 所有 CLI 在软链接入口下以 `realpath` 判断直接执行，并实际启动测试。
2. 明确定义共享 runtime 目录所有权和生命周期；停止参与 unit 不得删除 pending state、proxy status 或 writer lock。
3. switch 在启动 writer 前以服务 UID/GID 安全创建锁文件；配置/权限错误退出 78，锁占用退出 75，并设置 StartLimit。
4. pending journal 必须在停止旧 writer 前持久化、fsync、read-back 校验并可重入恢复；成功或失败后 current/state/proxy generation 不得矛盾。
5. 旧版 `/api/ready` 明确 404 时立即走 health 兼容；恢复继承备份窗口，不能触发即时多 GiB 快照，也不能永久关闭备份。
6. preflight 支持已验证预置副本或有界 I/O；ext4 无 reflink、3.2 GiB 合成库、并发写和 WAL 增长必须有测试。
7. 在隔离 Linux 使用真实 systemd/Nginx、真实 UID/GID 和临时 SQLite 覆盖正常、软链接、Nginx reload 失败、preflight timeout、锁权限、new-start、旧版回滚、重复执行和重启恢复；持续探针与新日志的 502/503/504 必须为 0。
8. 生成新的 clean SHA/Build ID 和全部不可变制品；`58d3e6f986ec…` 永久保持 No-Go。

1.0.41 开发侧修复与尚未执行的 Linux 实例门禁见 [1.0.41 候选记录](./1.0.41-candidate.md) 和 [Release Agent 交接](../RELEASE_HANDOFF_1.0.41.md)。
