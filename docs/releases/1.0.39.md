## 发布结论

`1.0.39` 云存档 P0 热修已完成香港、上海 Web/API 正式发布。两地当前均为 `web-1.0.39-fb54f2148dd6` / `api-1.0.39-fb54f2148dd6`，直接代码回滚目标为 `1.0.38-351c649af9ee`。上海下载页、Android stable 和 Windows stable 没有切换，继续保持 `1.0.38`；香港公开 `/canary/previous/` 按用户要求继续固定指向不可变 `1.0.37-853ecdb12795`，没有随代码回滚指针改成 1.0.38。

本版恢复 1.0.38 Web/Android/Windows 生成的合法 GameState v46 稀疏云存档上传。服务端仅在 v46 结构校验的局部读取中兼容缺失的 `belt.lanes/tier/progress=1/1/0` 与 `entity.interactionLocked=false`，显式非法值和损坏 checksum 继续拒绝；上传正文、envelope checksum、云 SHA-256、revision、历史恢复和下载正文不被规范化或改写。普通/速通排行榜复核 revision 也改为按 mode 独立等待和清除。GameState v46、envelope v2、云 schema v7、SQLite layout v2 均未升级。

生产验证没有使用玩家存档或真实账号写测试，没有修改排行榜历史、生产云 revision、数据库内容、下载清单或签名材料。所有写入 smoke 均使用合成账号和各节点自己的可删除备份副本；副本与一次性脚本在候选停止后已删除。

发布顺序为香港 Web/API → 上海 Web/API；上海下载页和 native feeds 不参与切换。两地都先暂停健康、节点和对应异地备份/恢复 timer，再使用固定 `/usr/local/sbin/dsp-idle-switch-release` 原子切换；成功、backup `ready`、`NRestarts=0` 和磁盘收敛后才恢复 timers。

- 香港切换工具约 52.3 秒返回成功；新服务在 uptime 240 秒时确认 startup backup `ready`，根盘回到 79%。20 次本机 health 延迟最小/平均/最大为 `0.745 / 6.657 / 116.771 ms`。

- 最终两地服务均 active、`NRestarts=0`、三个对应 timers active、journal error 0、schema v7/layout v2、backup `ready`。

香港从开始切换计时的 199 条 502/504 全部集中在旧进程停止和 3.17 GB 启动备份收敛窗口，路径为匿名 analytics、presence、public-status、errors 与 health；服务 ready 后 41,452 次请求 5xx 为 0。ready 后观测到 26 次真实 `/api/cloud-save` PUT，26 次均为 2xx、4xx/5xx 均为 0。唯一一次 PUT 400 出现在 `23:14:05`、即旧 1.0.38 切换窗口。上海稳定窗口 5xx 为 0，观察期内没有生产云 PUT；不能据此声称上海已有真实上传流量验证。

- 没有构建或发布 Android/Windows 1.0.39；源码版本元数据不等于 stable 原生制品。现有 1.0.38 客户端无需清缓存或重装即可使用新 API。

- 香港原子切换仍产生了短暂 API 502/504；ready 后归零，但这不是零停机蓝绿发布。未来应评估后端双端口切换以缩短大库启动窗口。
- `/canary/previous/` 是固定 1.0.37 Web-only 应急入口，继续使用当前 1.0.39 API；它不是 API、数据库、主机或网络灾备。
- Windows stable 仍为 `NotSigned`；1.0.39 没有新的原生真机、低配、覆盖升级或长时后台结论。
