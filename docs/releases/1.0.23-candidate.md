## 根因

旧浏览器压缩路径先等待 `CompressionStream` 的 writer 写完并关闭，之后才读取 readable。大请求触发背压后，写端等待读端消费，而读端尚未启动，1 MB、2 MB 和 7.3 MB 存档都可能永久等待。外部 `AbortSignal` 没有打断该压缩流，界面又在服务器确认前使用成功色，玩家会同时遇到“取消无效”和“看起来已经上传”的错误反馈。

开始菜单上传还要处理离线结算、保存校验和云端冲突。此前玩家没有办法放弃数十分钟的离线重放；如果把压缩、网络超时和用户取消混为一种失败，也会造成不安全的明文重试或重复云端修订。

## 协议与实现

- 浏览器使用 `Blob.stream().pipeThrough(new CompressionStream("gzip"))` 并立即、持续读取压缩输出，消除背压死锁；压缩阶段最多 5 秒。
- 浏览器不支持压缩、压缩异常或仅压缩阶段超时时，原始请求不超过 30 MiB 才发送一次明文 JSON；超过上限明确返回 413 类错误，本地存档不变。
- 玩家主动取消始终抛出 `AbortError`，不进入明文回退；离线 Worker、压缩流和网络请求共用取消边界。
- 网络请求超时不视为压缩失败。客户端先读取 `/account`：新 revision 的 `stateChecksum`、`savedAt` 和完整摘要匹配本次 payload 时视为已提交；revision 未变化时使用同一 `expectedRevision` 最多重试一次明文；revision 变化但内容不匹配进入 409；无法核实时报告状态未知。
- 主存档上传只生成和复用一份 Worker 校验 payload。服务器确认前不写回本地主档；确认后使用已验证 payload 保存，避免重复全量解析和 checksum。
- 主存档、十分钟自动同步、手动槽位 1–3、银河页面和冲突覆盖上传使用同一修订保护；成功后刷新云端 metadata。
- 准备、离线结算、生成校验、压缩、发送和等待服务器阶段均显示进行中状态；只有服务器返回并核对新修订后显示绿色成功。
- 进入游戏和上传时都可以放弃离线结算。放弃保留保存时的确定状态、发放 0 秒离线收益，并立即更新本地保存时间，避免下次重复结算该区间。

## 竞态与数据保护

`expectedRevision` 在原请求、远端确认和唯一一次明文重试中保持不变。超时后如果远端已经写入同一 payload，客户端只接纳现有 revision，不再发第二次 PUT；如果远端出现其他内容则转入冲突流程。主动取消不会触发超时恢复路径。云端确认后 metadata 刷新只是只读补充，刷新失败不会把已经确认的 PUT 改成失败；本地写回失败会明确提示“云端已更新、本地未写入”，不会伪装成全部成功。

本实现不修改玩法数据、离线收益规则、生产/物流/量子库存、排行榜、存档格式或服务端体积边界。真实玩家附件只在本机只读副本和路由拦截的浏览器测试中使用，未上传到生产账号。

## 制品和发布边界

最终 clean Git SHA、build ID、manifest 路径、文件数、聚合 SHA-256 和 Web/API 归档哈希由开发交接附上，并以 release manifest 为唯一事实来源。当前开发角色没有读取或使用香港/上海 SSH 私钥、Android keystore 或 Windows 代码签名证书，也没有生成可冒充正式升级的未验证签名包。

发布角色必须从安全凭据环境读取服务器密钥和两个应用签名证书，复验上一正式版本的证书连续性，完成两节点备份、未激活目录校验、原子切换、下载清单/Range/缓存验证和回滚记录。任一签名、备份、清单或健康门禁缺失时停止，不得热改生产目录或创建新证书替代旧证书。

## 剩余风险

- 本机真实浏览器为桌面 Chrome。Android Chrome/WebView 和桌面 Edge 未在实体设备上执行；标准 CompressionStream 路径及不支持压缩回退由单元测试和 Chrome E2E 覆盖。
- Windows 和 Android 正式包需要 release 角色的长期签名环境；本开发会话未验证证书可读性或覆盖升级。
- 远端状态未知时会选择明确失败而不是猜测成功，玩家需要重新打开云存档核对修订号；这是防止覆盖新进度的保守策略。
