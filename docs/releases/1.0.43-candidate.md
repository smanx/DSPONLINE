## 结论

1.0.43 已完成针对 35.004 MiB 玩家存档的兼容热修。根因不是 JSON 序列化，而是 v46 迁移对每条线路重复扫描全部实体，再用 `filter + belts.includes` 二次分区；玩家档约形成 49.23 亿次比较。新实现建立 first-match 实体索引和独立 first-match 物质投递枢纽索引，并用按 occurrence 的 accepted/rejected 单次分区，把迁移复杂度降为 O(E+B)。

文件导入、主菜单云恢复和工厂内云恢复改用短生命周期 Worker 完成 checksum、结构检查和迁移；Worker 不可用、接收 clone 失败或消息异常时回退同一完整同步检查。立即保存只执行一次 verified commit；返回主页只在提交 source 仍覆盖卸载瞬间状态时跳过 cleanup，保存等待期间模拟继续推进则补一次最终保存。
