## 结论

1.0.43 已完成针对 35.004 MiB 玩家存档的兼容热修。根因不是 JSON 序列化，而是 v46 迁移对每条线路重复扫描全部实体，再用 `filter + belts.includes` 二次分区；玩家档约形成 49.23 亿次比较。新实现建立 first-match 实体索引和独立 first-match 物质投递枢纽索引，并用按 occurrence 的 accepted/rejected 单次分区，把迁移复杂度降为 O(E+B)。旧外部候选 `D:\GameDev\DSPidle2-v143-release\1.0.43-a47eb33d0b84` 在完整 Chromium 中暴露当前公告测试仍锁定 v1.0.42，已作废且不得上传、部署或复用；替代候选必须使用新 final SHA 的全新目录和 manifest。

文件导入、主菜单云恢复和工厂内云恢复改用短生命周期 Worker 完成 checksum、结构检查和迁移；Worker 不可用、接收 clone 失败或消息异常时回退同一完整同步检查。立即保存只执行一次 verified commit；返回主页只在提交 source 仍覆盖卸载瞬间状态时跳过 cleanup，保存等待期间模拟继续推进则补一次最终保存。

第二轮完整 Chromium 将一条旧 DEV mirror 竞态改为 IndexedDB 权威重载证明时，发现增产剂缓存上限虽在 UI、模拟与手动存档中允许 100,000,000，但重载迁移仍误截为 100,000。现在 storage 直接复用 engine 的 `MIN/DEFAULT/MAX_PROLIFERATOR_BUFFER_LIMIT`，保留缺失值 600、下界 1 和上界 100,000,000；不升级存档格式。
