# DSPidle2 1.0.39 云存档 P0 热修候选

> 日期：2026-08-11
> 状态：开发门禁通过，尚未部署
> 生产基线：`1.0.38+351c649af9ee`
> 目标：API 优先热修，现有 1.0.38 客户端无需重装

## 故障与修复

1.0.38 客户端的 v46 持久投影会省略可重建默认值，但服务端结构验证仍要求传送带 `lanes/tier/progress` 与实体 `interactionLocked` 显式存在。完整性正确的合法稀疏正文因此会收到 `400 / SAVE_FORMAT_INVALID`。

候选保持“先完整性、后结构”的顺序，只在 v46 结构验证的局部读取中应用：

- 缺失 `belt.lanes` → `1`
- 缺失 `belt.tier` → `1`
- 缺失 `belt.progress` → `0`
- 缺失 `entity.interactionLocked` → `false`

显式 `null`、字符串、非法 JSON/NaN、负数、`lanes/tier=0` 和越界值继续拒绝；显式 `progress=0` 必须保持合法，以兼容 1.0.37 稠密存档。服务端不修改原 payload，不重算 envelope checksum，不改变云 revision、SHA-256、冲突检测、历史或下载正文。

## 稀疏字段审计

`saveProjection.ts` 省略字段与服务端路径逐项核对后的结论：

- 直接冲突并已修复：普通线路 `lanes/tier/progress`、实体 `interactionLocked=false`。
- 可选且已有合法范围校验：`machineCount`、`minerCount`、`resourceDepletionRemainder`、`quantumTarget`。
- 仅客户端运行/诊断默认值，服务端不强制：电网、功率、站点进度/拥堵/游标、喷涂、空输入输出、空路线，以及线路分拣器/优先级/堆叠/监视/累计/拥堵/流量/路由模式。
- 蓝图线路不经过普通线路稀疏化，v46 蓝图的 `lanes/tier/priority` 仍显式存在并严格校验。
- 云摘要、普通榜完整性和速通资格使用 mode、elapsed、totalProduced、metrics、contentPacks、speedrun 身份与 checksum，不依赖上述默认字段。

## 排行榜复核 revision

人工 `restore-leaderboard` 现在分别读取普通与速通 main revision，写入模式化等待阈值。对应模式的新 main 上传或历史恢复只清除本模式等待：

- 普通上传/恢复不提前放行速通。
- 速通上传/恢复不改变普通阈值。
- 隐藏账号可完成复核，但不会自动公开。
- 永久冻结不会被任何上传或恢复解除。
- 旧 `leaderboardResumeAfterRevision` 继续按普通模式读取并保留为回滚兼容别名。

该修复与云上传 400 的原因相互独立，已使用单独 Git 提交。

## 发布前边界

Release Agent 必须从交接文档记录的固定 clean SHA 复验不可变清单，在两节点的生产备份副本上隔离启动 API，并取得明确发布授权后才可灰度。优先只切 API；Web 与原生应用更新不是 P0 恢复前置条件。

回滚只切回旧 API 代码并重启，不恢复数据库。任何 payload 改写、revision 异常、普通/速通串扰、历史恢复错误或排行榜冻结失效都必须停止发布。
