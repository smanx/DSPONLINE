# 1.0.44 玩家反馈：保存 UX 与 durable Worker 不可用链修复（候选）

> 状态：代码修复已在 `codex/1.0.44-save-ux-fix` 分支完成，typecheck + 相关单测通过；待与 1.0.45 空间站开发线集成、E2E 门禁后发布。
> 范围：只改保存 UX 与恢复容错，不改 GameState/云协议/服务端。

## 1. 玩家反馈原文拆解

玩家报告两组问题：

1. **durable 模拟 Worker 不可用链**：
   - “模拟 Worker 不可用，已暂停；刷新后从 recovery 精确恢复”
   - “模拟 revision 与 durable recovery head 不一致，已阻止滚动基线”
   - “自动保存会继续重试，导出文件不会删除或覆盖现有存档。立即导出当前进度”
2. **保存期间不能操作 / 撤销正在进行的操作**：
   - 玩家原话：保存时不能操作应该是做了异步保存不阻塞前端？但保存过程中不能操作的话前端不阻塞有什么用；是否能将“保存不影响操作”做成设置开关让玩家自己选。

## 2. 根因

### 2.1 保存期间操作被拒绝（反馈 2）

`App.tsx` 的 `persistDurablePrimaryCheckpoint` 在 durable 保存进行时置
`durablePrimarySaveInFlightRef = true`，期间 5 个玩家编辑入口统一调用
`rejectPlayerStateEditDuringPrimarySave()`，返回“本次操作未应用；保存完成后即可继续编辑”。
对玩家而言，正在做的操作在保存开始时被拒绝，表现为“撤销了正在进行的操作”。

### 2.2 保存失败时回滚 UI（反馈 2 的加重因素）

`persistDurablePrimaryCheckpoint` 的 catch 分支在保存失败时执行：
`setPaused(latestAuthoritativeCheckpointRef.current, true)` 并把 `gameRef` 回滚到
上一个 checkpoint——即**丢弃保存期间玩家已接受的编辑**并暂停游戏。
这放大了“保存撤销操作”的观感。

### 2.3 revision/head 不一致即阻断（反馈 1 的核心）

保存成功、主档写回之后，代码要求
`simulationStateRevisionRef.current === head.stateRevision`，
否则抛“模拟 revision 与 durable recovery head 不一致，已阻止滚动基线”。
一旦 Worker 出现短暂不可用/恢复时序差，UI revision 与 recovery head 出现一拍的
落后，就会进入该失败分支 → 暂停 + 回滚 + 提示导出。这是 fail-safe 设计，
但缺少“允许 head 暂时落后、下次保存追赶”的正常路径。

## 3. 修复内容（本分支）

### 3.1 新增设备级设置开关

`dsp-idle-network.save.allow-edits-during-save.v1`（默认 false = 保持既有保护）：
- 位于 运营中心 → 设置 → 存储：“保存期间允许继续操作（实验性）”。
- 开启后保存不再拒绝/撤销操作；保存期间的编辑保留在 durable 队列。

### 3.2 保存期间允许编辑（开关开启时）

- `rejectPlayerStateEditDuringPrimarySave` 在开关开启时直接放行，编辑照常进入 Worker 队列。
- `persistDurablePrimaryCheckpoint` 捕获保存时的 `checkpointRevision`，用该 revision 滚动
  recovery head；若保存期间 UI revision 已前进，**不再 throw**，head 落后被标记为
  可追赶状态（下一次保存追平）。
- `simulationStateRevisionRef` 只允许前进、不允许被 head 回拨。

### 3.3 保存失败不再丢弃编辑（开关开启时）

catch 分支在开关开启时**不回滚 gameRef、不 setPaused**，仅提示
“保存失败；当前编辑已保留，可继续游戏或立即导出”。关闭开关时保持原 fail-safe 行为。

### 3.4 文件清单

- `src/game/uiPreferences.ts`：新增偏好 key + read/write 函数
- `src/App.tsx`：开关状态/ref、拒绝编辑放行、revision 追赶语义、失败不丢编辑
- `src/components/OperationsWorkspace.tsx`：设置 UI 开关

## 5. 尚未解决 / 后续（1.0.45 集成时）

- **durable Worker 不可用的自愈**：本修复避免了一致性误判与编辑回滚，但 Worker 真崩溃时的
  自动重建/一键恢复仍是后续项（当前刷新后从 recovery 精确恢复是既有保底）。
- **开关默认值**：当前默认关闭（保守）。若 1.0.45 观察良好，可考虑默认开启。
- **保存期间编辑的 head 追赶**：已设计为下次保存自然追平；需要一次大存档 E2E 验证
  “保存中连续操作 → 下次保存追平 → 刷新恢复”全链路。
