## 发布结论

1.0.41 原始 Web/API 先发布到上海；香港切换原始 1.0.41 后，云存档 revision 裁剪触发同步全库正文扫描，普通上传可放大为数 GB 同步读取并阻塞 API。香港随后发布 Web+API P0 热修，当前不可变指针为 `web/api-1.0.41-2e43f5644241-hk-p0`。上海仍是原始 1.0.41；下载页、Android 和 Windows 没有随香港热修改变。

香港云存档 PUT、DELETE、restore、账号导入/删除和管理员 prune 的维护锁已解除。`/api/analytics`、`/api/errors`、`/api/presence` 的 Nginx 202 telemetry 熔断仍保留，它不属于云存档维护锁。

## 香港 P0 修复

- 在线 revision/user 删除只清理当前事务触及且已证明无引用的正文 blob，不再运行同步全库 GC。
- 启动时按每行最多 161 字符的实际 alias 投影建立逻辑键和 checksum 引用计数；alias 损坏或 SQLite 动态类型不是 TEXT 时自动回收 fail-closed，宁可保留 orphan 也不误删共享正文。
- 显式离线全量 GC 仍执行完整 alias、正文、大小和 SHA-256 校验，语义不变。
- v46 微型黑洞在稀疏投影后仍显式保存 `blackHolePaused` 与 `blackHoleActivationConfirmed`。固定基线没有复现所有运行态被统一暂停，因此未自动开启任何既有黑洞；已经写成 `true/true` 的状态无法无歧义区分主动暂停和历史异常。

## 回滚与残余事项

直接代码回滚目标是原始 1.0.41；1.0.37 仅作为更早的显式 Web 备用。回滚只切换不可变 Web/API 代码，继续使用当前数据库；不得恢复发布前数据库备份、删除云历史或修改排行榜。

剩余事项包括 telemetry 202 熔断、handoff proxy 活动请求计数泄漏、上海尚未合入香港热修，以及已持久化暂停的黑洞不会自动开启。1.0.42 必须以本香港热修源码作为最新运行时基线，并重新生成 SHA、Build ID 和全部候选制品。
