## 1. 版本目标

1.0.40 是一次以“数据不丢、跨端一致、可恢复、可诊断、可持续发布”为中心的大版本。它保留已经完成的银河排行榜本人真实排名修复，并处理 1.0.39 全项目复盘中确认的云存档、浏览器并发、本地存储、服务端持久化、容量、安全、PWA、性能、可访问性、测试和发布工程问题。

本版本的“完成”必须同时满足：

- 每个下列工作包都有实现或经过测试证据支持的明确工程结论，不允许仅标记“以后处理”。
- 每项运行时代码修改都有自动化回归测试。
- 所有数据写入路径都有失败回滚、幂等或冲突处理。
- Web、API、Windows、Android 的兼容边界有可复现证据。
- 完整门禁通过，形成 clean Git SHA、新 Build ID、不可变制品清单和 Release Agent 交接。
- 开发阶段不部署生产、不连接生产数据库做写入测试、不覆盖玩家存档、不修改排行榜历史。

## 4. P0 工作包

### P0-01 Windows/全端大存档云传输契约统一

#### 已确认问题

当前各层限制不一致：浏览器、Electron IPC、客户端请求超时、Nginx 和 API 对请求/响应大小及超时使用不同口径。23～30 MiB 合法存档可能在 Web 可上传、Windows 客户端失败，账号完整导出还可能超过 Electron 响应上限。固定短超时也会把“服务器仍在提交”误判为失败。

#### 实现要求

- 建立单一、可测试的传输能力契约，明确：
  - 明文存档上限；
  - 压缩后请求上限；
  - envelope 开销；
  - 解压后硬上限；
  - 单条云存档响应上限；
  - 账号导出使用的流式协议；
  - 各阶段超时与取消语义。
- Electron 不再使用低于合法云存档上限的 8 MiB 请求限制；请求上限必须至少覆盖 30 MiB 合法正文和 envelope 开销。
- Web、Android、Windows 优先复用 gzip；不支持压缩时保留受同一明文上限保护的兼容路径。
- 大正文通过 ArrayBuffer/Uint8Array 或等价可转移结构传递，避免 IPC 和 Worker 间多份字符串复制。
- 超时按正文大小和阶段动态计算；未知提交结果先通过 revision、checksum 和摘要确认，禁止直接重传造成重复修订。
- 为 Electron 请求分配 requestId，支持从 UI 到 IPC 到网络层的真实取消；取消后不得晚到写回成功状态。
- 原始上传 payload、checksum、revision 和下载正文保持逐字节不变。
- Windows 修复需要新客户端制品；新 API 必须继续服务 1.0.39 旧客户端。

#### 必须测试

- 1、7、8、20、28、30 MiB 以及超限正文。
- raw、gzip、压缩不可用回退、取消、超时后远端已提交和远端未提交。
- normal/speedrun，main/1/2/3，各自上传、下载、历史、恢复和冲突。
- Windows IPC、Web fetch、Android 网络桥接的一致错误码。
- checksum、revision、历史正文逐字节对照；失败不产生半条 revision。
- 低速和高延迟合成网络；不使用真实账号或玩家存档。

#### 完成标准

- 所有合法 30 MiB 内存档在支持的平台可可靠完成上传和下载。
- 超限请求在分配超大对象或进入昂贵解析前明确拒绝。
- 客户端可区分取消、超时、格式错误、完整性错误、容量错误和服务器失败。
- Windows 必须重新打包；Web/API 不强迫旧客户端重新安装。

### P0-02 浏览器多标签页本地存档防覆盖

> 开发状态（2026-08-13）：实现与专项门禁完成；最终发布前仍随完整 1.0.40 候选重跑全量跨端门禁。

#### 已确认问题

每个标签页拥有独立内存缓存和写队列。旧标签页可能在新标签页完成保存后把较旧状态写回 IndexedDB，造成静默回退；单标签页测试无法发现。

#### 实现要求

- 同一浏览器配置只允许一个主写入标签页；其他标签页明确显示只读/待接管状态。
- 优先使用 Web Locks；不支持时使用带 ownerId、expiresAt、heartbeat 和 fencing token 的 IndexedDB lease。
- 用 BroadcastChannel 通知保存、删除、导入、恢复、模式切换和主标签变更；无 BroadcastChannel 时使用 storage/轮询回退。
- 每次提交前比较持久层 revision、savedAt、checksum 和 fencing token；陈旧标签不得覆盖更新存档。
- 主标签关闭、崩溃或休眠后可以在 lease 过期时安全接管。
- normal/speedrun 和各槽位的冲突键必须包含模式与槽位。
- 不自动合并两个 GameState；出现真正分叉时保存双方原始快照并要求玩家选择。

#### 必须测试

- 两个真实 Playwright 页面同时打开、交错保存、暂停/恢复、刷新、崩溃接管和离线重开。
- A 保存新状态后 B 陈旧保存，最终持久状态不得回退。
- normal 与 speedrun 同槽位并行操作不串档。
- 自动保存与手动保存竞争、删除与保存竞争、导入与自动保存竞争。
- 不支持 Web Locks/BroadcastChannel 的回退路径。
- 旧 IndexedDB 无 lease 元数据时幂等升级，原存档逐字节可恢复。

#### 完成标准

- 任意测试调度下都不存在已确认新存档被陈旧标签覆盖。
- 冲突时保留两个可恢复原始版本，不静默选择较旧版本。

## 5. P1 工作包

### P1-01 SQLite 持久化失败的原子可见性

#### 已确认问题

故障注入显示：写入 SQLite 失败时，PUT 可以返回 500，但同一进程随后的 GET 已能看见只存在内存中的新 revision。客户端无法判断数据是否真正落盘，服务重启后可能回退。

#### 实现要求

- 所有变更使用“验证 → 构造候选状态 → SQLite 事务提交 → 发布内存状态”的顺序，或提供等价的完整回滚。
- SQLite 提交失败时，内存状态、公开排行榜、revision、历史、账号控制和审计均回到提交前状态。
- 对提交结果不确定的网络失败提供幂等 requestId/operationId 查询。
- readiness 暴露最近一次持久化成功时间、最近错误类别和数据库可写状态；健康接口不得泄露路径或玩家数据。
- server shutdown 必须等待进行中的事务进入明确完成/回滚状态。

#### 必须测试

- SQLITE_FULL、SQLITE_IOERR、SQLITE_BUSY、只读数据库、磁盘写到一半、进程重启。
- 注册、普通/速通云上传、删除、历史恢复、密码修改、排行榜隐藏/恢复/永久冻结和管理员操作。
- 每个失败点比较响应、内存 GET、重启后 GET、revision、历史和审计。
- 临时 SQLite 和合成账号，禁止生产数据库。

#### 完成标准

- 服务器绝不返回失败却在当前进程短暂暴露未持久化成功的数据。
- 成功响应的数据在受控重启后仍存在；失败响应不产生不可见的半提交。

### P1-02 云容量、历史修订和账号导出治理

#### 已确认问题

单存档可接近 32 MiB；两种模式、多个槽位和每槽 20 个历史修订会使单账号理论占用达到数 GiB。当前账号完整导出会把多个槽位历史正文一次性组装成一个 JSON，存在服务内存、浏览器内存和 Electron 响应上限风险。

#### 实现要求

- 增加明确、可配置且在 UI 可见的每账号、每模式、每槽位和单 revision 配额。
- 上传前可返回当前占用、预计新增、将被修剪的自动历史和剩余空间。
- 自动历史采用可预测的保留策略；不得静默删除手动保护、导入前或恢复前快照。
- 相同 checksum 的历史正文只存一份或提供等价去重；实现不得改变下载正文和 checksum。
- 账号导出改为流式压缩包或 manifest + 分片正文，不再一次性 JSON.stringify 全部历史。
- 新导出包含版本、模式、槽位、revision、时间、大小、checksum 和完整性清单。
- 导入先完整校验到临时区，全部通过后原子写入；失败不修改现有账号数据。
- 旧 JSON 导出继续可导入；旧客户端现有单槽云接口继续可用。
- 若共享正文去重必须改变 SQLite 内部状态结构，须先提供双读、回填、回滚和 layout v2 兼容证明；不得擅自提升 layout 版本。

#### 必须测试

- 账号拥有 normal/speedrun、main/1/2/3、每槽 20 个接近上限历史。
- 配额边界前、恰好边界、超过边界；修剪后仍可下载、重启、恢复。
- 重复 checksum 去重但不同 revision 元数据独立。
- 大账号导出期间服务器内存有界，可取消，可恢复下载，导入往返哈希一致。
- 导入损坏分片、缺清单、模式不匹配和磁盘失败不污染现有数据。

### P1-03 云上传单次权威解析与主线程减负

#### 已确认问题

服务端当前可能经历请求聚合、同步解压、JSON.parse，以及模式、结构、摘要、排行榜指标的重复解析。大正文会阻塞 Node 事件循环并制造多份对象。

#### 实现要求

- 新建单次 inspectUploadPayload 流程或等价边界，一次解析返回：
  - envelope/完整性结果；
  - GameState 版本与模式；
  - 槽位校验结果；
  - 保存摘要；
  - 排行榜计算所需只读投影；
  - 原始正文引用。
- 完整性和 checksum 通过前不修改原始 payload。
- 大 gzip 使用异步 zlib；超过阈值的 JSON 解析/投影转入 Worker 或受控后台任务。
- 限制并发大上传数量并提供公平排队、取消和 Retry-After。
- 响应序列化避免复制完整云正文；下载和账号导出使用流式输出。
- 及时释放临时引用；记录阶段耗时、峰值正文大小、事件循环延迟和拒绝原因，不记录正文/token。

#### 必须测试

- 相同正文只执行一次权威解析；各消费者拿到同一只读检查结果。
- 稀疏 v46、稠密 1.0.37、normal/speedrun、合法/损坏 checksum。
- 并发 1/2/4/8 个 30 MiB 合成上传，观察 RSS、heap、事件循环延迟和公平性。
- 取消、超时、客户端断连、服务器关闭和数据库失败。
- 与 1.0.39 的下载正文、revision 和排行榜计算差分一致。

### P1-04 API 输入边界、CORS、公开数据和安全头

#### 实现要求

- 认证、密码、验证码、反馈和诊断接口使用独立的小正文上限，不沿用云存档的 32 MiB 上限。
- scrypt 前限制密码/账号字段的字节长度和类型，拒绝深层、循环或异常 Unicode 输入。
- /api/errors 和反馈诊断建立字段白名单、深度、数组长度、单字段和总字节上限，并统一脱敏 token、账号、路径和存档片段。
- OPTIONS 明确包含 DELETE；正确设置 Vary: Origin；只允许官方 origin 和必要请求头。
- 未知 origin 不获得跨域授权；同源、Web、Android 和 Windows 兼容路径分别测试。
- 公开排行榜只返回展示所需字段，不暴露原始 accountId/userId、存档 checksum、私有 revision 或复核内部信息。
- 保持旧客户端公开榜兼容；若旧字段属于敏感数据，使用版本化公开投影或稳定匿名 publicId 迁移。
- Nginx 各 location 使用统一安全头 include，避免 add_header 继承被局部覆盖；至少覆盖 CSP、frame-ancestors/X-Frame-Options、nosniff、Referrer-Policy、Permissions-Policy 和生产 HSTS。
- CSP 先在合成候选环境验证，不得直接以宽泛 unsafe-* 永久绕过。

#### 必须测试

- 各路由边界值、超限提前拒绝和 scrypt 未被调用。
- 深层诊断对象、超大数组、敏感字段脱敏。
- GET/POST/PUT/DELETE/OPTIONS，官方/未知 origin，预检和实际请求。
- 首页、静态资源、版本文件、API、下载、错误页的安全头。
- 旧客户端公开榜解析；/me 私有信息只对当前认证账号返回。

### P1-05 Web/Android 会话和备份安全

#### 实现要求

- Web 增加 HttpOnly、Secure、SameSite 会话 cookie，保留 Bearer token 兼容期。
- 明确定义 cookie 路径、过期、注销、密码修改、账号删除、跨站请求和 CSRF 策略。
- 现有 localStorage token 只用于迁移；迁移成功后移除，失败时不把账号锁死。
- Android token 迁入系统安全存储；WebView JS 只持有短期会话句柄或最小必要凭据。
- 审计 Android allowBackup 和 data extraction rules：认证凭据必须排除，玩家本地存档是否备份单独决策并在 UI 说明。
- 不用“清除应用数据”作为迁移方案，不删除现有 IndexedDB 存档。

#### 必须测试

- 旧 Bearer 客户端、新 cookie Web、新 Android 安全存储并存。
- 登录、刷新、过期、注销、改密、删号、撤销全部设备、CSRF 和错误 origin。
- Android 覆盖升级、系统备份/恢复模拟、token 不被复制、存档按策略保留。

### P1-06 发布切换零明显中断

#### 已确认问题

既有发布切换曾观察到约 52 秒服务不可用和 199 个 502/504。大数据库启动备份或单实例停启会扩大窗口。

#### 实现要求

- 发布启动时不在 readiness 前同步执行全库重备份。
- 新 API 在独立端口/套接字完成启动、临时数据库迁移检查和 readiness 后再原子切换代理。
- 旧实例保持服务直到新实例可接流量；失败自动保持/恢复旧 upstream。
- 数据库只允许一个明确写入主实例；切换方案必须防止双写。
- 备份仍是发布前硬门禁，但与新进程启动解耦；回滚只回滚代码，不恢复生产数据库。
- 运维脚本支持 dry-run、故障注入、重复执行和清晰审计。

#### 必须测试

- 合成持续请求覆盖正常切换、新实例启动失败、readiness 超时、代理 reload 失败和回滚。
- 测试窗口中 2xx 连续，目标为 0 个用户可见 502/504。
- SQLite 锁、进行中上传、导出和优雅关闭。

### P1-07 本地快照容量与持久存储体验

#### 实现要求

- 统计 normal/speedrun 各槽位、自动快照、手动快照、保护快照和导入缓存占用。
- 自动快照有明确上限；手动/保护快照达到阈值时提示玩家选择，不静默删除。
- 清理界面按模式、槽位、时间、来源、大小显示，默认不勾选保护快照。
- 请求 navigator.storage.persist，并显示 granted/denied/unsupported；拒绝不影响游戏。
- 写入前使用 StorageManager estimate 做预警；仍以实际事务结果为准。
- 清理、配额失败和浏览器回收后保持至少一个可验证主存档或明确恢复提示。

#### 必须测试

- 小配额、QuotaExceededError、持久权限拒绝、浏览器不支持和高占用。
- 两种模式互不删除；失败操作保留原存档。

### P2-04 服务端长期规模、保留策略与可观测性

#### 已确认问题

在线人数/玩家指标存在全量扫描路径；排行榜可能每请求全排序；访客、日指标等历史缺少明确保留；app_state 周期性整体重写会随账号和历史增长放大。

#### 实现要求

- presence 使用增量计数和过期索引，不在每个心跳扫描全部玩家。
- 排行榜建立可失效的排序快照；普通 main 有效提交、隐藏/限制和复核状态变化时才更新。
- 日指标、访客、错误摘要和审计分别定义保留/聚合策略；安全审计不得因普通遥测清理而丢失。
- 高频状态使用增量 upsert 或等价持久化，避免每分钟重写全部大对象。
- 暴露无敏感信息的请求延迟、事件循环延迟、RSS/heap、SQLite commit、上传队列、排行榜缓存命中和导出任务指标。
- 所有缓存可从 SQLite 权威状态重建，重启不改变业务结果。

#### 必须测试

- 1、150、1,000、10,000 个合成账号基准。
- presence 心跳、排行榜读写、缓存失效、冷启动重建、保留清理和时区边界。

## 10. 性能和资源预算

所有数据先在同一机器、同一 clean SHA、同一合成 seed 下记录基线，再比较候选：

- 60 秒精确模拟不得比 1.0.39 同夹具基线回退超过 5%，完整状态哈希必须一致。
- 离线/纯挂机不增加重复复制；峰值内存和完成时间至少不劣于 1.0.39。
- 30 MiB 云上传期间 UI 保持可取消，Node 事件循环没有无界长任务，RSS 在并发限制下有界。
- 多标签页协调空闲开销不持续高频写 IndexedDB。
- 排行榜缓存前后结果一致，公开读不对每请求全量解析存档。
- 发布切换合成持续流量目标为 0 个 502/504。
- 首屏不提前加载 game-core；首屏 gzip 资源目标下降至少 15%，最低要求是不增长并完成明确拆分。
- 本地与云容量统计不得通过反复解析所有大正文实现；优先复用已验证摘要。

任何性能优化都必须先通过正确性、守恒、checksum 和恢复门禁。性能达标但状态不同视为失败。

## 11. 停止发布条件

出现以下任一情况，1.0.40 不得交给 Release Agent：

- 任一已确认新存档被旧标签覆盖。
- API 返回成功但重启后数据不存在，或返回失败却暴露未提交状态。
- normal/speedrun 或不同槽位串档。
- 原始 payload、checksum、revision、下载正文被静默改写。
- 旧合法 v46/1.0.37 存档无法读取或上传。
- 离线/纯挂机重复结算、收益消失、负库存、负矿脉或物资不守恒。
- 公开接口泄露账号标识、私有 revision、checksum、token 或存档正文。
- 大存档合法范围内仍在某一支持平台被硬编码小上限拒绝。
- 核心门禁失败，或以删除/跳过测试掩盖失败。
- 版本号、Build ID、manifest 或制品哈希不一致。

## 12. 回滚方案

### 代码

- 每个工作包独立 revert；优先回滚代码，不恢复生产数据库。
- 服务端保留 1.0.39 API 兼容路径和旧 Bearer 会话。
- 客户端保留旧传输回退，但不得绕过新完整性和大小上限。

### 本地存档

- lease 元数据与 GameState 分离；回滚协调代码不改写玩家正文。
- 导入、迁移和冲突前创建保护快照；失败保留原始文本及 checksum。

### 云数据

- 默认不提升 cloud schema v7/SQLite layout v2。
- 配额、去重和流式导出变更必须能关闭而不影响既有单槽读取。
- 若最终需要内部数据迁移，先提供双读、幂等回填、校验清单和独立撤回方案；没有用户批准不得扩大范围。

### PWA/原生

- PWA 保留 previous-stable 缓存和不可变旧资源。
- Windows/Android 新制品使用新版本与 Build ID，不能覆盖 1.0.38/1.0.39 既有安装包。
- 原生签名、商店/下载页切换和生产分发由 Release Agent 执行。

## 14. 权限边界

本开发 Goal 授权修改当前 1.0.40 开发分支的源码、测试、合成夹具、文档、构建和本地临时数据库。它不授权：

- 连接香港/上海生产数据库做写入；
- 使用真实玩家账号或真实玩家存档做写入测试；
- 修改排行榜历史、submission 或人工限制；
- 部署 Web/API、切换 Nginx、上传下载站或发布原生正式包；
- 使用或创建生产签名证书、邮件凭据、监控账号；
- 覆盖任何现有发布制品。

最终开发状态必须停在可复核、可回滚的 Release Agent 交接点。
