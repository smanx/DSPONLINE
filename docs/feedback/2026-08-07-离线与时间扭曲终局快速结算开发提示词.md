### 2.3 科研导致离线结算重新变成整段精确计算

玩家补充截图：

> 三张截图附件保留在本机受保护环境，未纳入仓库；前两张记录离线结算耗时异常，第三张记录玩家反馈离线加载约十五分钟。

玩家说明：界面显示的离线模拟时间除以约 5～10，才接近现实等待时间；早上一次加载约 15 分钟。

本地复测：

| 场景 | 当前结果 |
| --- | --- |
| 保持无限科研，探测快速离线路径 | 约 `20.82 ms` 后拒绝，原因是“存在进行中的科研，已使用精确结算” |
| 只暂停无限科研，保留原油/精炼油/氢递归链，离线 `6,984s` | `fast-30s-v1` 约 `4.70s` 完成 |
| 只暂停无限科研，离线 `30,171s` | `fast-30s-v1` 约 `3.86s` 完成 |
| 同一存档精确推进 `60s` | 约 `3.749s`，吞吐约 16 模拟秒/现实秒 |
| 按本机速度推算精确推进 `6,984s` | 约 `7.27` 分钟 |
| 按本机速度推算精确推进 `30,171s` | 约 `31.42` 分钟 |

玩家设备只达到约 5～10 模拟秒/现实秒时，十五分钟以上的等待与上述根因完全一致。

性能剖析中的主要成本约为：传送带 `36%`、物流 `27%`、施工相关合计 `16%`、生产 `7%`、电力 `6%`、量子物流 `4%`。1.0.32 的原油/精炼油/氢递归修复最多只影响施工相关的一部分，并不是快速离线整体失效的触发器；直接触发器是科研硬门禁。

## 三、已确认根因

### 3.1 时间扭曲启动检查点继承过期倍率

当前调用链：

1. `src/App.tsx:1656` 用 `setTimeWarpEnabled(..., true)` 创建纯挂机检查点。
2. `src/game/engine.ts:6335-6347` 的 `setTimeWarpEnabled()` 在启用时继续保留旧 `effectiveMultiplier`、`requiredPowerKw` 和 `allocatedPowerKw`。
3. 存档在停止状态下通常保存的是基础倍率；迁移路径也会把 `effectiveMultiplier` 恢复为基础模拟速度。
4. `src/game/pureIdleMacro.ts:249` 在校准前读取这个旧倍率。
5. `src/game/pureIdleMacro.ts:333` 后续每个宏观结算窗口继续从候选状态读取同一倍率。

结果是：即使真实电网支持 `9x`、`13x` 或更高，宏观会话仍可永久按 `1x` 或基础倍率结算。

现有 `src/game/pureIdleMacro.test.ts:55` 反而断言“宏观会话只按基础速度推进”，因此错误行为被测试固定下来。必须先改测试语义，再修实现。

### 3.2 有限/无限科研被快速路径整体拒绝

当前硬门禁：

- `src/game/pureIdleMacro.ts:267`：检测到 `hasActiveResearch(state)` 后直接抛错。
- `src/game/offlineApproximation.ts:1710-1712`：同步快速离线直接返回 fallback。
- `src/game/offlineApproximation.ts:1821-1823`：异步 Worker 快速离线同样直接返回 fallback。
- `src/game/offlineApproximation.ts:1598-1600`：旧时间扭曲近似路径也因科研回退精确结算。
- `src/game/offlineApproximation.ts:560`：通用近似资格检查仍把科研视为整条路径不可用。

`hasActiveResearch()` 同时覆盖普通有限科技和终局无限科技，所以两类科研都会触发。

### 3.3 快速路径失败后无条件创建全时长精确会话

`src/game/offlineSimulation.worker.ts:117-140` 先尝试 `fast-30s-v1`。只要返回 `fallback` 或 `ineligible`，`src/game/offlineSimulation.worker.ts:141` 就会创建覆盖整个离线时长的 `createSimulationAdvanceSession()`。

这让一个几毫秒完成的科研资格拒绝，变成几分钟到几十分钟的全量传送带、物流、建筑、电力和生产重放。当前 Worker 会分块让出事件循环，但总工作量仍与离线时长线性增长，因此“有进度”不等于“终局可用”。

### 3.4 纯挂机恢复路径主动停住 Worker

`src/App.tsx:2243-2247` 检测到恢复检查点包含科研后：

- 设置 `continueAvailable=true`；
- 不调用 `initializePureIdleMacroClient()`；
- 保持画布冻结；
- 只提供放弃未结算收益后恢复普通模拟的按钮。

这不是安全恢复，而是一个必然丢弃本次挂机收益的死胡同。

### 3.5 UI 没有持久基线，错误模式下产出永远显示 +0

`src/components/TimeWarpIdleOverlay.tsx:134-137` 在没有 `macroSummary` 时，同时把当前状态快照作为 fallback 和 baseline。二者相减必然为 0，所以错误进入精确/恢复状态后，所有“本次产出”都会显示 `+0`。

同时默认标题仍显示“稳定宏观模式”，实际却可能处于精确科研路径、恢复等待或失败状态，玩家无法判断程序究竟在计算还是已经停止。

### 3.6 现有真实存档 E2E 主动清除了科研，掩盖回归

`tests/e2e/v132-pure-idle-macro.spec.ts:220-221` 在运行真实终局存档前手动执行：

```ts
state.research.selectedTechId = null;
state.endgame.activeInfiniteResearchId = null;
```

因此该用例只证明“删除科研后能运行”，没有验证真实玩家状态。修复后不得继续使用这种预处理来证明终局兼容。

### 3.7 1.0.32 的科研边界自愈不等于科研宏观结算

`settleCompletedResearchBoundaries()` 可以幂等完成一个已经达到成本边界的有限科技，并推进队列。这能修复“投入已满但最后完成事件漏掉”的旧档，却不能解决：

- 离线期间持续投入有限科技矩阵；
- 有限科技完成后切换队列并继续研究；
- 无限科技跨越多个非线性成本等级；
- `matrix_compression` 升级后改变后续科研速度；
- 科研奖励、解锁、银河评分和自动研究在宏观窗口中的离散变化。

不能简单删除科研 guard，再让通用仿射合同外推 `level`、`progress` 或 `progressByTech`。这样会绕过真实成本曲线和完成事件，造成免费科技、漏奖励或重复奖励。

## 四、产品目标与不可妥协规则

### 4.1 当前功能的准确名称

- 离线快速结算：`fast-30s-v1`。
- 时间扭曲纯挂机宏观结算：`pure-idle-macro-v2`。

本批改变了算法语义，建议分别升级为：

- `fast-30s-v2`。
- `pure-idle-macro-v3`。

算法版本写入诊断报告和纯挂机恢复记录即可；如果没有改变 GameState 结构，不要仅为算法名称升级 GameState v46 或 save envelope v2。

### 4.2 “终局完全可用”的定义

对所有结构合法的普通工厂存档，无论是否存在以下状态，都必须尝试并完成有界快速结算：

- 普通有限科技正在研究、刚好完成或队列中还有下一项科技；
- 任意无限科技正在研究、自动研究开启、一次跨越多个等级或到达等级上限；
- 建筑制造中心和三条递归制造链正在运行，包括原油、精炼油、氢和副产物循环；
- 量子物流、传统物流、运输机、运输船、翘曲器和在途货物同时存在；
- 传送带、液体/气体、有限矿脉枯竭、库存/输入/输出/托盘容量边界；
- 戴森球、太阳帆、火箭、活动交付、探索任务和施工自动化存在离散边界；
- 玩家从桌面切后台、刷新、关闭进程、Worker 崩溃或重新打开应用。

这些状态可以让某个子系统切换到更保守的算法，但不能让整段离线时间或整段纯挂机时间退回无上限精确重放。

### 4.3 性能优先于数值精度

本批产品决策明确接受数值偏差。规则如下：

1. 数值误差可以记录、提示并触发“保守宏观模式”，但不能再触发全时长精确回放。
2. 目标是让终局存档能用，而不是让数小时或数天的结果与逐 tick 重放逐字段完全一致。
3. 当无法安全确定产量时，优先少结算、降低效率或冻结单个不确定子系统，不能凭空增加资源。
4. 科技成本、物资所有权、离散奖励次数、建筑/科技解锁和存档结构安全不能近似。
5. 普通库存、缓存、产量、物流节奏和戴森阶段结果允许偏差；建议把关键终局指标误差作为诊断目标，而不是资格门禁。
6. 对同一源存档、同一离线时长和同一算法模式，结果仍必须确定。

### 4.4 真实时间预算

离线结算必须使用真实墙钟预算，而不是只限制“模拟秒数”：

- 桌面和正常移动设备目标：终局离线结算在 `30s` 内完成。
- 低端手机/Android WebView 硬上限：`60s`。
- 达到硬上限前必须停止继续精确校准，使用当前已有观测结果完成保守宏观结算。
- 不允许在 UI 上显示“预计还需几万模拟秒”后继续无期限运行。
- 玩家取消后，Worker 应尽快停止；原始检查点必须保持原样。

纯挂机是持续会话，不要求在 30 秒内结束，但要求：

- 开始后立即显示可响应的遮罩和当前阶段；所有重计算只在 Worker 中进行。
- 初始精确校准有真实时间上限；超时后必须使用较短样本形成保守合同，不能卡在“校准中”。
- 每次 30 秒宏观边界的计算成本不得随请求倍率或累计挂机时长线性增长。
- 停止、刷新恢复、后台切换和 Worker 重启都有有界超时，不得让主线程冻结。

### 4.5 唯一允许拒绝结算的情况

只有源存档本身无法通过格式、完整性或基础数值安全校验时，才允许不发放离线/挂机收益。即使如此也必须快速返回明确错误并保留原档，不能卡死页面。

速通排名工厂继续遵守独立的精确计时和排行榜规则，不得在本批中静默改成近似排名。若速通规则不允许该功能，应立即明确提示并返回，而不是冻结或偷偷进入长时间精确重放。

## 五、要求采用的总体算法

实现统一的三级结算策略，离线和时间扭曲纯挂机共享领域能力，但保持各自的墙钟、倍率和恢复语义。

### 第一级：有界精确校准

1. 在 Worker 内存副本上运行少量真实引擎窗口，默认仍可使用 3 个 10 秒模拟窗口。
2. 每个窗口后记录产量、消耗、库存变化、物流变化、科研投入、供电和终局指标。
3. 校准必须服从真实时间 deadline；低端设备来不及完成 30 模拟秒时，缩短为可完成的多段样本。
4. 每段之间让出 Worker 事件循环，检查取消和 deadline。
5. 绝不在主线程同步重放大型存档。

### 第二级：边界感知的宏观结算

把状态分为两类：

- 连续/稳定字段：使用现有守恒仿射合同、净变化率和容量钳制批量推进。
- 离散边界：使用专门账本推进，例如科研完成、无限科技升级、矿脉枯竭、库存满/空、活动阶段和队列切换。

建议建立统一的 boundary handler/ledger 接口，至少能回答：

```text
当前边界还需要多少资源或时间
本次最多能安全推进多远
到达边界后需要调用哪个幂等领域事件
哪些子系统必须重新校准
```

不要继续通过不断增加“有某状态就拒绝整个快速模式”的 guard 来处理复杂性。

### 第三级：保守宏观兜底

当普通仿射合同不稳定、尾验误差过大、边界数量太多或某个子系统无法形成正常合同：

1. 使用多个校准窗口中较低且可守恒的实测速率。
2. 按库存、有限资源、输入、输出和容量上限钳制。
3. 无法证明安全的子系统可以按 0 或降低后的效率处理，但其他可证明安全的子系统继续结算。
4. UI 明确显示“保守宏观结算”及降级原因。
5. 仍须在剩余真实时间预算内完成。

以下行为被明确禁止：

```text
快速合同失败 -> 对剩余数小时/数天创建完整精确 SimulationAdvanceSession
```

短于校准窗口的小段离线时间可以精确结算，但也必须受同一真实时间 deadline 约束；如果终局存档连短窗口都超时，仍要转保守宏观，而不是突破 60 秒硬上限。

## 六、有限科技宏观账本

有限科技不得由通用仿射字段直接外推。为它建立独立、可测试的研究账本。

### 6.1 校准记录

对当前科技记录：

- 科技 ID 和精确成本向量；
- 每种矩阵已经投入的数量；
- 每个校准窗口真实增加的矩阵投入量；
- 科研站实际消耗、喷涂、供电和研究速度影响后的有效投入率；
- 当前队列及下一项可激活科技。

### 6.2 推进规则

1. 根据保守实测矩阵投入率计算到下一科技完成边界的时间。
2. 只推进到边界，不允许 `progressByTech` 超过精确成本。
3. 到边界后调用现有幂等科技完成/奖励/解锁/队列切换逻辑；不要在宏观模块复制奖励清单。
4. 下一项科技激活后，重新校准受科技解锁和速度变化影响的子系统。
5. 如果队列为空，停止科研账本，但工厂其他系统继续结算。
6. 如果实际没有矩阵输入或科研站没有有效供电，科研速率为 0；这属于真实停产，不是快速模式失败。

需要保留：

- `completedTechIds` 去重；
- 完成奖励只发一次；
- `queuedTechIds` 顺序；
- `pausedTechId`、取消和恢复语义；
- 研究站缓存及所有矩阵的物资守恒；
- 完成科技后相关生产倍率、配方、建筑和终局功能正确生效。

## 七、无限科技宏观账本

无限科技成本是非线性的，而且等级变化可能反过来改变生产、采矿、物流或科研速度。不得把 `level` 与字符串 `progress` 当普通数字做线性外推。

### 7.1 精确数量规则

1. 使用 `src/game/infiniteResearch.ts` 的 `getInfiniteResearchCostBigInt()` 作为单级成本真值。
2. 全程使用 `BigInt` 或规范十进制字符串处理累计成本和进度；不要先转成 `Number` 再计算。
3. 建立可复用的累计成本/批量投资 helper，可通过前缀累计、二分查找或分段求和定位可跨越的等级数。
4. 跨级后逐项或按经过证明等价的批量规则结算银河评分、等级上限和完成状态。
5. 保持 `autoResearch=false` 时完成一级即停止；`autoResearch=true` 时才允许继续跨级。

### 7.2 速度变化与重新校准

- `matrix_compression` 每级会改变后续科研速度，不能假设整段时间投入率恒定。
- 其他无限科技可能改变采矿、生产、物流、戴森或能源表现。
- 每次跨越少量等级时，可以在边界后重新校准。
- 当一次离线跨越大量等级时，设置有界的重新校准次数，例如最多 32～64 次；超出后使用分段保守速率和精确累计成本批量推进。
- “重新校准次数达到上限”只能触发保守账本，不能触发全时长精确重放。

### 7.3 科研字段隔离

从通用仿射合同中明确排除至少以下科研离散字段，由研究账本独占写入：

- `research.selectedTechId`
- `research.pausedTechId`
- `research.completedTechIds`
- `research.queuedTechIds`
- `research.progressByTech`
- `endgame.activeInfiniteResearchId`
- `endgame.infiniteResearch.*.level`
- `endgame.infiniteResearch.*.progress`
- 科技完成奖励、解锁和银河评分相关字段

通用合同与科研账本必须通过一个原子协调层提交，避免同一份矩阵被生产账本和科研账本同时消费。

## 八、修复时间扭曲倍率初始化

### 8.1 正确行为

启用时间扭曲并创建纯挂机检查点时，必须先根据当前主控装置、所在电网、常规用电需求、可用发电和请求倍率刷新一次权威供电快照，再开始校准。

要求：

1. 不得继续把停止状态保存的 `effectiveMultiplier` 当成新会话的功率上限。
2. 不要在 `App.tsx`、UI 和宏观模块各复制一份倍率公式；使用引擎现有的电力分配真值或提取一个纯 helper。
3. 刷新倍率本身不得偷偷推进大量模拟时间或重复生产。
4. 足额供电时，实际倍率等于请求倍率；供电不足时，使用引擎计算出的最高稳定倍率；低于时间扭曲最低功率时回到基础倍率。
5. 稳定纯挂机期间如果燃料耗尽、供电变化或科技改变电力，后续校准必须更新实际倍率。
6. `PureIdleMacroSummary.actualMultiplier`、累计模拟秒数、UI 和最终状态必须使用同一个倍率来源。

### 8.2 必须替换的错误测试

现有单测中“90 秒墙钟只按基础速度结算”的断言是错误基线。新增明确夹具：

```text
基础模拟速度：4x
时间扭曲请求：9x
供电：足够支持 9x
现实时间：30s
预期结算模拟时间：270s
```

另加低电测试，验证只能支持 7x 时精确结算 210 模拟秒；不能固定取请求倍率，也不能回到陈旧的 1x。

## 九、离线 Worker 必须改为有界状态机

### 9.1 禁止当前 fallback 调用链

当 `runFastOfflineSettlementAsync()` 返回普通合同不稳定、科研边界、容量边界或尾验误差时，`offlineSimulation.worker.ts` 不得立刻为整个离线时长创建精确会话。

推荐结果类型从当前三态扩展为能表达：

```text
approximate              正常宏观结算完成
conservative             保守宏观结算完成
bounded-exact            短窗口精确结算完成
invalid-source           源存档不安全，未结算且未修改
cancelled                玩家取消，未提交候选
```

不要继续用 `fallback` 同时表达“再试保守算法”和“开始整段精确重放”两种完全不同的语义。

### 9.2 deadline 传递

从 UI 发起点到 Worker、快速结算、精确校准、验证和最终保存，传递统一 deadline/AbortSignal：

- 每个精确小窗口前后检查。
- 每次大型实体/传送带遍历之间检查。
- deadline 剩余不足时跳过额外尾验，转保守宏观并保留诊断。
- 保存时间单独记录，不能把保存失败伪装成结算失败。
- Worker 不可用时，不允许在主线程无界精确模拟；应使用可让出事件循环的有界保守实现，或快速返回可恢复状态。

### 9.3 进度口径

离线面板必须同时显示：

- 已耗现实时间；
- 已结算模拟时间/总模拟时间；
- 当前阶段：校准、宏观、保守宏观、验证、保存；
- 当前算法版本；
- 是否发生降级及具体原因；
- 按最近真实墙钟速度估算的剩余现实时间。

不能再只显示模拟秒数，让玩家误以为“剩余 30,000 秒”就是还要等 30,000 个现实秒，或误以为进度在动就不会等待半小时。

## 十、纯挂机会话、停止与恢复

### 10.1 启动

1. 点击“纯挂机”后立即冻结画布交互并显示可响应的状态面板。
2. 创建只读权威检查点，再在 Worker 副本上刷新供电和校准。
3. 有限/无限科研不得改变初始化分支，不再走“精确科研专用路径”。
4. 初始校准超时后直接使用保守合同，不能停在“正在校准”。

### 10.2 持续结算

- 默认每 30 秒现实时间形成一个宏观结算边界。
- 请求倍率只改变对应的模拟时间，不得让算法工作量随倍率成比例增长。
- `9x`、`14x`、`20x` 应使用同一数量级的宏观计算成本。
- 稳定模式可继续做周期影子校验；极限模式可以减少验证，但两种模式都必须支持科研。
- 影子校验失败只替换为保守合同，不得让整个会话进入 failed/放弃收益状态。

### 10.3 停止

1. 停止后不再接收新的宏观目标时间。
2. 等待当前有界切片结束或取消，并忽略迟到 Worker 消息。
3. 用最后已完成边界生成候选；未完成小段可以保守结算或明确不结算，但不能重复。
4. 运行正式序列化、重载和安全验证。
5. 只有主存档成功写入后，才清除恢复记录。
6. 保存失败时保留候选与恢复记录，并允许重试或导出；不能把原始主存档覆盖成半完成状态。

### 10.4 刷新、崩溃和后台恢复

1. 删除 `App.tsx:2243-2247` 中“检查点有科研就不初始化 Worker”的恢复死路。
2. 旧 `pure-idle-macro-v2` 恢复记录即使包含科研，也必须迁移为新会话并继续结算。
3. 旧记录中若保存了错误的 `effectiveMultiplier=1`，恢复时重新根据权威电网求值。
4. 不要求玩家放弃已过去的挂机时间；恢复日志中的源检查点仍是权威起点。
5. 保留当前页面进入后台后最多 5 分钟高倍率宽限策略；超过的尾段交给新的有界离线结算，而不是旧整段精确 Worker。
6. Web Lock/租约继续保证同一会话只能有一个提交者。
7. Worker 重启次数必须有上限；连续失败后切保守宏观，不进入重启循环。

## 十一、UI 与玩家反馈

### 11.1 模式标签必须真实

状态面板至少区分：

- 正在准备供电快照；

### 11.3 必须显示的信息

## 十二、存档、安全和确定性硬门禁

数值误差可以接受，下列错误绝对不能接受：

1. 任意可见库存、建筑输入输出、物流货物或科技投入出现负数。
2. 出现 `NaN`、`Infinity`、非安全整数或无效十进制大整数。
3. 同一物资同时存在于源库存和宏观候选中，造成复制。
4. 有限科技完成奖励、建筑赠送、解锁或队列推进重复执行。
5. 无限科技成本少扣、多扣，等级或银河评分重复增加。
6. 在途物流货物复制、丢失或到达两次。
7. 取消、刷新、Worker 迟到消息或双标签页导致同一时间段提交两次。
8. 保存失败后清除恢复记录，或覆盖最后一个有效主档。

提交协议必须保持：

```text
权威源检查点保持不变
-> Worker 内存候选结算
-> normalize/结构与数值校验
-> serializeEnvelope(candidate)
-> inspectSave(serialized) 并重新加载
-> 校验通过后原子写入主存档
-> 写入成功后清理恢复记录
```

取消或失败时必须能证明源存档哈希未改变。

## 十三、必须新增或修改的测试

### 13.1 时间扭曲倍率

1. 停止状态 `effectiveMultiplier=1`、基础 `4x`、请求 `9x`、供电足够：30 墙钟秒必须结算 270 模拟秒。

### 13.2 有限科技

4. 到达等级上限后安全停止，不循环、不溢出。
5. 再覆盖会影响采矿、生产或物流倍率的无限科技，验证边界后重新校准。

### 13.4 离线性能与非阻断

使用合成夹具提交到仓库，真实玩家存档只在本机只读运行：

1. 上述 1,910 实体/4,479 传送带存档，保留 `matrix_compression` 研究，不得先清空科研。
2. 离线 `6,984s` 和 `30,171s`，两者都必须走宏观或保守宏观完成，而不是创建覆盖全时长的精确 session。
3. 终局存档离线 7 天和 30 天，桌面目标均小于 30 秒；低端/限速模拟环境硬上限小于 60 秒。
4. 精确校准被故意限速或合同故意失败时，确认切换保守宏观且仍在 deadline 内完成。
5. 对 Worker 不可用、Worker 中途抛错、重复消息和取消做失败注入。

### 13.5 复杂终局状态矩阵

快速结算至少覆盖：

- 原油、精炼油、氢递归制造开启；
- 建筑制造中心有任务、WIP 和副产物；
- 量子共享库存和传统物流路线同时存在；

- 有限矿脉在窗口内枯竭；

- 戴森球、太阳帆和火箭在窗口内变化；
- 施工自动化、活动交付和探索边界。

每一种复杂状态都可以触发保守降级，但不得触发全时长精确重放。

### 13.6 恢复、存档和确定性

1. 开始纯挂机后刷新，保留科研和 baseline，恢复后继续产生非零结果。
2. 旧 `pure-idle-macro-v2` 恢复记录带有限或无限科研，可迁移到新算法。

4. 玩家取消后源存档 SHA-256/状态哈希不变。
5. 相同源存档、相同时长、相同模式重复运行，候选状态哈希一致。
6. 最终结果能序列化为 envelope v2、迁移/加载为 GameState v46，并通过 `inspectSave()`。

## 十四、量化验收标准

全部满足才算完成：

1. 足额供电的 `9x` 测试中，30 墙钟秒结算 270 模拟秒，不再是 30 秒。
2. 上述 `14x` 玩家存档保留 `matrix_compression` 研究时，纯挂机可启动、持续、停止、刷新和恢复；实际倍率由电力决定，不固定为 1x；终局产出与科研进度不是因框架错误而全为 0。
3. 有限科技研究中也能完成同样的启动、停止和恢复流程，完成事件及队列只执行一次。
4. 离线 `6,984s`、`30,171s`、7 天和 30 天均不得因科研或复杂产线创建全时长精确 session。
5. 桌面终局离线目标小于 30 秒；低端/限速环境硬上限小于 60 秒。若未达到目标，开发交接必须给出真实数据和未达原因，不能宣布完成。
6. 普通合同失败、尾验误差超过阈值、边界过多和 Worker 重启失败时，都能进入保守宏观完成或快速安全返回，页面不冻结。
7. 取消、异常和保存失败不会改变权威源存档；成功候选通过序列化、`inspectSave()` 和重载后才提交。
8. 不出现负库存、NaN/Infinity、非安全整数、无效 BigInt、物资复制、科研免费升级、重复奖励或重复时间结算。
9. 同一输入确定性一致；GameState v46、envelope v2、cloud schema v7 保持兼容。
10. 全量测试、构建和指定 E2E 通过，并报告精确通过/失败/跳过数量。

## 十六、建议开发顺序

1. 先补失败测试，固定当前三条回归：足额供电仍 1x、科研拒绝纯挂机、科研触发整段精确离线。
2. 提取权威时间扭曲倍率刷新，修复检查点和恢复记录的陈旧倍率。
3. 建立有限/无限科研专用账本，排除通用仿射科研字段。
4. 增加保守宏观结果与统一 deadline，切断 offline Worker 的无界精确 fallback。
5. 接入纯挂机启动、持续、停止、后台和崩溃恢复。
6. 修复 UI baseline、阶段标签、现实剩余时间和降级原因。
7. 先跑合成测试，再对附件存档的副本做只读基准；根据诊断修正边界，而不是清除科研来让测试通过。
8. 完成全量门禁和开发交接。开发交接必须列出实际耗时、峰值内存、算法路径、误差、测试数量和所有未验证平台。

## 十七、风险、牺牲与回滚要求

### 玩家接受的牺牲

- 长时间离线与高倍率纯挂机不再追求逐 tick 完全一致。
- 不稳定产线可能使用较低的保守效率，结算收益少于理论最大值。
- 物流动画、瞬时缓存、带上货物位置和部分阶段性统计不要求重建到精确瞬间。
- 影子校验失败后可降低精度，不应牺牲可用性。

### 不允许牺牲的内容

- 存档可加载和可回滚。
- 物资守恒与非负整数。
- 科技精确成本、奖励次数、队列顺序和解锁状态。
- 物流货物所有权。
- 玩家取消权与主线程响应。
- 同一时间段只能结算一次。

### 主要工程风险

| 风险 | 缓解措施 |
| --- | --- |
| 无限科技批量跨级少扣成本或重复加分 | BigInt 累计成本 helper、单级对照、随机属性测试、等级上限测试 |
| 科技完成改变倍率后仍使用旧合同 | 完成边界后使受影响合同失效并有界重新校准 |
| 保守合同同时结算库存净增与科研消费，复制矩阵 | 统一原子协调层，科研字段和科研消耗只允许一个账本写入 |
| Worker 崩溃后重复提交 | 权威 checkpoint、session ID、租约、单次 commit token、迟到消息隔离 |
| deadline 到期留下半状态 | 只提交完整边界；中间候选只存在 Worker 内存，超时用最近完整边界进入保守结算 |
| 误差影响排行榜 | 保持服务器现有排行字段定义，记录算法和误差诊断；不得用误差触发无界精确回放 |
| 移动端多份大状态副本造成内存崩溃 | 复用单一候选、及时释放校准切片、避免同时创建快速与精确会话、记录峰值内存 |

回滚时只回滚本批代码和算法入口，不修改玩家存档版本、不删除恢复记录、不恢复旧数据库。必须保留能够读取新旧恢复记录的兼容路径。紧急降级也只能切到“保守宏观”，不得重新启用无上限全时长精确 fallback。
