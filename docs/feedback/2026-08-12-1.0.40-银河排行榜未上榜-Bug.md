# 1.0.40 第 1 项：银河排行榜当前账号误显示“未上榜”

> 记录日期：2026-08-12
> 正式基线：`1.0.39-fb54f2148dd6` / `fb54f2148dd64268ee2c2f39c6774b348e6ea437`
> 开发分支：`codex/1.0.40-leaderboard-ranking`
> 固定实现提交：`24d54c10ce6c04cade5173c1980143928c6f6fd4`
> 状态：开发与完整本地门禁通过；未连接或部署生产环境

## 玩家现象与根因

- 公开 `GET /api/leaderboard` 只返回 Top 100，这是正常的公开榜分页边界。
- 1.0.39 客户端从这 100 条公开记录中查找当前账号，因此真实排名大于 100 时会误显示“未上榜”。
- 尚无有效相邻主云修订时，白糖统计用数值 `0` 同时表达“未知”和“有效零产出”；UI 无法解释真实原因。
- 找不到当前账号的公开条目时，吞吐量又回退到本地 ledger，白糖回退为 `0`，造成“本地指标 + 服务器排名”混合展示。

问题仅发生在排行榜读取与展示层，不是本地生产、云上传、普通/速通槽位或玩家存档损坏。

## 最终修复

### 公开榜保持原协议

`GET /api/leaderboard?category=<category>&seasonId=season_01`

- 继续匿名可读。
- 继续只返回公开 Top 100。
- `entries` 旧结构与排序口径不变。
- 即使请求意外带有登录令牌，也不返回当前账号私有状态。
- 不增加 `self`、账号限制、复核阈值、完整榜数量或私有窗口诊断。

### 新增认证本人接口

`GET /api/leaderboard/me?category=<category>&seasonId=season_01`

- 必须携带有效 Bearer token；未认证返回 `401`。
- 只返回当前账号，且在完整公开 submission 集合中计算真实 `rank`。
- 返回字段至少包括：

```text
status
entry
rank
totalEntries
serverMetrics
latestWindowState
mode = normal
slot = main
latestCloudRevision
reviewResumeAfterRevision
```

- 私有响应使用 `Cache-Control: no-store`。
- `/me` 为只读接口，不写云档、submission、历史修订或排行榜成绩。

### 状态契约

| status | 含义 |
| --- | --- |
| `ranked` | 当前分类已有可用服务器成绩 |
| `hidden` | 账号主动退出公开排行榜 |
| `restricted` | 账号处于排行榜限制状态；存档与云同步不受影响 |
| `revalidation_required` | 等待新的普通模式主云 revision 完成复核 |
| `missing_main_save` | 尚无普通模式 main 云档 |
| `missing_adjacent_revision` | 尚无可组成窗口的相邻普通 main revision |
| `interval_too_short` | 相邻 revision 的模拟时间增量小于 60 秒 |
| `elapsed_not_increasing` | 相邻 revision 的模拟时间没有增加 |
| `valid_zero_production` | 已形成有效窗口，但该窗口生产增量为 0 |
| `unavailable` | 当前正文、计数器或服务状态无法形成可信结果 |

白糖与实际结算吞吐统一返回结构化窗口：

```text
status, valid, value, metricVersion,
requiredSeconds, observedSeconds, remainingSeconds,
productionDelta, fromRevision, toRevision
```

无效或未知窗口的 `value`、`productionDelta` 为 `null`；只有 `valid_zero_production` 才返回有效数值 `0`。窗口在普通 main 排行更新时计算并放入最多 2,048 项的进程内小型缓存；服务重启回填会重新建立缓存，缓存未命中时只读重算，不持久化诊断字段。

### UI 口径

- 当前账号服务器成绩与真实排名只读取认证 `/me`。
- 本地 60 秒最佳值单独标注，不再冒充服务器排行榜值。
- 排名大于 100 显示 `#N · Top 100 外`，并显示完整公开榜条目数。
- 59 秒窗口显示已观察 59 秒、还差 1 秒；缺前序、计时不增长、复核、隐藏和限制均显示具体原因。
- 有效零产出显示“有效窗口，当前无产出”。
- 白糖服务器状态未知时显示 `--`；只有有效零产出才显示 `0`。
- 当前 UI 尚未持久记录本地白糖 60 秒最佳，因此明确显示“本地尚未记录”，不会制造一个本地数值。
- 英文界面的新增状态、动态秒数和本地/服务器口径均已补齐翻译。

## 数据与兼容边界

- GameState 保持 v46。
- save envelope 保持 v2。
- 云 schema 保持 v7。
- SQLite layout 保持 v2。
- 不修改玩家 payload、checksum、revision、历史修订或恢复记录。
- 不给现有 submission 增加窗口诊断字段，不修改已有分数、峰值或提交时间。
- 不修改排行榜历史，不执行人工恢复，不访问生产数据库。
- 只有 `normal/main` 更新普通银河榜；`normal` 手动槽和 `speedrun/main` 在银河榜形成前后都不会创建或覆盖其窗口。

兼容关系：

| 客户端 / API | 行为 |
| --- | --- |
| 旧客户端 + 新 API | 继续读取原公开 Top 100，忽略新增 `/me`，完全兼容 |
| 新客户端 + 新 API | 显示认证本人状态、真实完整排名和结构化窗口原因 |
| 新客户端 + 旧 API | 公开榜仍可查看；`/me` 失败时显示“认证状态不可用”，不会拿本地值冒充服务器值 |

发布时应先更新 API，再更新 Web；Android/Windows 若不更新客户端仍保持旧 Top 100 体验，但云存档和生产功能不受影响。

## 性能与风险

- 公开榜请求没有增加响应条目或认证开销。
- 已登录银河页面每次分类读取会多发一个小型 `/me` 请求。
- `/me` 当前对完整公开 submission 集合执行排序，复杂度为 `O(n log n)`；150 账号回归无可感知问题。账号规模显著增长后，可改为服务端共享排序快照或数据库排名查询，但不能改变排名口径。
- 进程内窗口缓存最多 2,048 条，只保存小型诊断对象；缓存未命中可能只读解析当前与前一修订，首次请求延迟可能高于命中路径，但不会改变结果或玩家数据。
- 本地白糖 60 秒最佳尚无独立持久 ledger 字段；本次选择明确显示“未记录”，避免伪造或混用服务器值。
