# 1.0.40 第 1 项：银河排行榜“未上榜”状态修复

> 记录日期：2026-08-12  
> 开发基线：1.0.39 正式发布提交 `0d022150d441b3288e120f297251cd8af138fdec`  
> 开发分支：`codex/1.0.40-leaderboard-ranking`  
> 状态：实现完成，正在执行 1.0.40 批次回归；未部署生产环境

## 玩家现象

- “白糖产量”和“实际结算吞吐”可能只显示“未上榜”。
- 本地个人档案可能已有很高的实际结算吞吐，但榜单没有本人名次。
- 白糖峰值的 `0` 无法区分“有效统计窗口内确实为 0”和“还没有形成统计窗口”。
- 公开榜可正常显示其他玩家，甚至可能存在本人记录，但当前账号状态区仍无法识别本人。

## 根因

1. `/api/leaderboard` 只返回公开榜前 100 名，前端只在这 100 条记录中查找当前账号。本人已有合法 submission、但当前分类排在 100 名以后时，会被错误归类为“未上榜”。
2. 相邻主云修订计算把以下情况全部压成数值 `0`：
   - 只有第一次普通模式主云同步；
   - 两个相邻修订不足 60 个模拟秒；
   - 相邻修订正文不可用；
   - 模拟时间或累计生产计数回退；
   - 有效窗口内确实没有新增产量。
3. UI 在找不到服务端本人记录时回退到本地档案值，形成“本地显示 196 亿/min，但服务端仍未上榜”的来源混淆。

## 修复方案

- 匿名排行榜响应继续只包含公开前 100 名，不暴露任何当前账号私有状态。
- 已登录的只读排行榜请求额外返回 `self`：
  - 固定声明 `mode=normal`、`slot=main`；
  - 返回本人完整名次，即使在公开前 100 名以外；
  - 返回最新普通主云 revision、已计入 submission revision；
  - 返回隐藏、复核等待、永久限制、内容包、不完整正文等明确资格状态；
  - 分别返回白糖产量与实际结算吞吐的相邻修订窗口状态。
- 相邻窗口仍在普通主云上传/排行榜更新时计算，并把几十字节的诊断结果写入当前 submission 的验证元数据；排行榜 GET 不重新读取或解析大型云存档正文。
- 窗口状态区分：等待第二次同步、间隔不足、历史修订缺失、正文无效、内容包、时间回退、生产计数回退、有效零产量和有效正产量。
- 前端以服务端 `self` 作为当前云账号的权威身份，不使用显示名猜测，也不依赖本地档案 ID 与云账号 ID 相同。
- 本人在前 100 名外时，列表末尾追加“当前账户”行并显示真实名次。
- “我的排名”可显示“等待统计”“待同步”“等待复核”“已限制”“不具资格”等状态，不再一律显示“未上榜”。
- 本地值和服务端值不同时同时说明两者口径；本地指标不会直接写入排行榜。

## 数据与兼容边界

- 不修改 GameState v46、存档 envelope v2、云 schema v7 或 SQLite layout v2。
- 不修改本地存档、云存档 payload、checksum、revision、历史修订、生产累计值或排行榜历史成绩。
- 现有 submission 在服务启动回填或下一次主云同步时只补充 `windowDiagnosticsVersion=1` 及窗口原因；分数、峰值、提交时间和云 revision 口径不变，不属于历史成绩恢复或改分。
- GET 诊断为只读；测试已逐对象确认读取前后云存档和 submission 不变。
- 新 Web + 旧 API：`self` 缺失时继续使用 1.0.39 的前 100 名兼容回退。
- 旧 Web + 新 API：旧客户端忽略新增的 `self` 字段，公开 `entries` 结构不变。
- 只有 HTTPS 或本机开发环境会携带登录令牌请求 `self`；匿名 HTTP 读取仍不发送账号凭据。
- 普通银河排行只读取 `normal/main`，不会读取 speedrun 或手动槽位。

## 新增回归测试

- 匿名读取不返回 `self`。
- 已登录读取返回 `normal/main` 本人状态。
- 本人排名第 101 时，公开 entries 仍为 100 条，但 `self.entry.rank=101`。
- 第一份主云修订显示等待第二次有效同步。
- 59 秒相邻修订显示还差 1 个模拟秒。
- 60 秒有效零产量明确返回 `ready-zero`。
- 60 秒有效正产量返回白糖和实际结算吞吐的服务端数值。
- 复核 revision 阈值显示为 `revalidation-required`。
- 排行榜状态读取不修改云存档或历史 submission。
- 排行榜状态读取不调用大型云存档 payload 读取；直接复用上传时的小型诊断元数据。
- 本地档案 ID 与云账号 ID 不同时仍能识别本人。
- 本人在公开前 100 名外时 UI 显示真实名次和当前账户行。
- 本地 196 亿/min、服务端窗口不足时显示具体差异和剩余秒数。
- 有效白糖零产量显示“确实为 0”，不显示“等待统计”。
