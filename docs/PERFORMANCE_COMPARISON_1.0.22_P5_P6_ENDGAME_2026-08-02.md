# 1.0.22 P5/P6 终局实测报告

> 本报告记录 2026-08-02 在同一台 Windows 设备、同一 Chromium/Chrome 进程和同一终局存档上的新鲜结果。测试存档只读使用，原文件未改写。

## 结论

1. P3 已通过既有保存短路回归，当前默认生效，可以保留。
2. P5 批量线路绘制层没有证明稳定的 FPS 提升。静态最小缩放场景约 `135.31 -> 135.46 FPS`（+0.11%）；运行模拟场景约 `24.12 -> 24.76 FPS`（+2.62%），但 P95/最大帧耗时没有同步改善，仍不能作为无风险正式默认开启依据。
3. P6 没有接入正式实时或离线模拟 Worker。现有 `multicoreSimulation` 只读分区探针不包含物流伙伴、载具派遣、量子边界、在途路线、跨分区写入和固定顺序 delta 合并，因此不能把探针加速当成玩家收益，也不能开启 P6。
4. Android 1.0.22 可覆盖升级所需的长期 keystore 和签名环境本机不可读；Windows 签名环境也未配置。不能生成可验证的双平台 1.0.22 正式安装包。
5. 因此本轮不切换公网，香港、上海和下载页继续保持已发布的 1.0.21。

## P5 FPS 对比

P5 条件为终局模式、实验开关和当前星球线路数不少于 600。静态测试把画布缩到最小缩放（0.25），屏幕内实际绘制 86 条线路，连续采样 12 秒。

| 场景 | P5 | FPS | 帧 P95 | 最大帧 | 长任务 P95 |
|---|---:|---:|---:|---:|---:|
| 静态画布 | 关 | 135.31 | 7.0 ms | 125.1 ms | 2,587 ms |
| 静态画布 | 开 | 135.46 | 7.0 ms | 118.2 ms | 709 ms |
| 正在模拟 | 关 | 24.12 | 333.7 ms | 709.1 ms | 428 ms |
| 正在模拟 | 开 | 24.76 | 347.5 ms | 750.7 ms | 629 ms |

静态帧率变化只有约 `+0.11%`，运行模拟约 `+2.62%`，均低于可作为发布承诺的稳定收益；运行模拟的 P95 和最大帧还变差。启动、Worker backlog 和 React Flow 初始布局会明显影响单次采样，因此不能用长任务 P95 的单次下降宣称 P5 已解决卡顿。

## 完整模拟与守恒

使用现有引擎对原始夹具执行 60 秒观察 + 60 秒验证，共 120 个精确 1 秒步长：

- 平均单步 `57.873 ms`，中位 `53.710 ms`，P95 `73.524 ms`，最大 `112.583 ms`
- 生产 `621.984 ms`，传送带 `3822.925 ms`，物流 `1056.497 ms`，量子 `268.877 ms`，电力 `482.710 ms`
- 物流伙伴匹配调用 `127,200`，候选检查 `23,050`，缓存命中 `100,700`
- 生成路线 `18,081`，量子请求 `24,580`
- 观察期间稳定记录无预测错，原始状态哈希在只读夹具检查前后保持一致
- 原存档只读副本未保存、未上传、未写回

这证明当前单 Worker 精确路径可以完成并保持守恒，但不代表 P6 已经存在一个可切换的并行完整路径。

## 发布门禁

- `npm run typecheck`：通过
- `npm test`：74 个测试文件通过，1 个跳过；652 项通过，9 项跳过
- `npm run build`：通过，1,866 个模块
- Android 签名校验：失败，缺少长期 keystore、密码和别名环境；不能生成覆盖升级包
- Windows 签名校验：失败，缺少 `CSC_LINK` 和 `CSC_KEY_PASSWORD`；只能生成未签名测试包

因此 1.0.22 不满足“P3/P5/P6 全部开启并双端发布”的条件。公网和下载页保持 1.0.21，候选目录和现有回滚目录均保留。
