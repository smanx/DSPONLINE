# 太空电梯与恒星系联合空间站开发计划书

> **已废弃（2026-07-31）**：本方案不再实施。请勿根据本文开发太空电梯、恒星系空间站、八站网络或 v43 旧 hub 结构。后续唯一有效方向是 [量子物流网络开发 Agent 提示词](./QUANTUM_LOGISTICS_NETWORK_AGENT_PROMPT.md)。本文仅作为历史讨论记录保留。

> 文档状态：方案定稿，尚未开发
> 基线版本：DSP极简网络 1.0.16，GameState v42，存档 envelope v2
> 建议目标版本：1.1.0，GameState v43
> 核心目标：以终局巨构玩法把几百座物流塔之间的多对多运输，收束为最多 8 座恒星系空间站之间的聚合物流结算。

## 1. 结论

本功能不是现有星际物流塔的外观升级，而是一套玩家主动建设、逐恒星系启用的终局物流协议。

完整转换后的物流拓扑为：

```text
生产线
  -> 星际物流站 Mk.II / 太空电梯
  -> 本恒星系共享仓库
  -> 宇宙联合空间站
  -> 最多 8 座空间站之间的聚合调度
  -> 目标恒星系共享仓库
  -> 太空电梯
  -> 消费线
```

设计必须满足以下边界：

- 太空电梯模式不得进入传统塔对塔伙伴匹配和 `StationRoute` 派遣。
- 货物数量和运输船数量增大时，不得线性增加运输对象。
- 星系共享仓库使用精确十进制整数字符串持久化，科学计数法只负责显示。
- 所有玩家可见库存保持非负整数；跨 `number` 与大整数边界时先限幅再转换。
- 传统物流模式、已有路线、库存、线路、载具和翘曲器必须完整保留。
- 运行时索引、脏集合、候选队列和性能缓存不得进入 GameState 或存档。

## 2. 当前性能依据

真实终局样本的已测数据：

| 指标 | 当前结果 |
| --- | ---: |
| 实体 | 2,648 |
| 传送带 | 5,746 |
| 物流站 | 416 |
| 活动传统航线 | 720 |
| 平均单模拟秒 | 110.402 ms |
| 物流占引擎时间 | 64.8% |
| 派遣占引擎时间 | 46.2% |
| 传送带占引擎时间 | 22.8% |

因此只改物流时，整体理论极限约为降低 64.8%。本方案的正式目标为：

- 物流阶段耗时降低至少 80%。
- 引擎总耗时降低至少 50%。
- 参考终局存档单模拟秒低于 60 ms。
- 同机同档的等价处理速度达到当前的 2 倍以上。
- 运输船从 100 增长到 1,000,000 时，枢纽结算耗时变化不超过 5%。

如果无界面原型无法达到总耗时降低 30%，停止正式内容开发并重新评估算法。

## 3. 产品目标与非目标

### 3.1 目标

- 为白糖毕业后的玩家提供长期巨构建设和资源消耗目标。
- 让每座星际物流站都能原地升级为太空电梯，不要求玩家重接全部产线。
- 为每个恒星系提供独立、精确、游戏内无限的共享物资仓库。
- 允许已建设空间站的恒星系先使用本地共享仓库，再逐步接入银河网络。
- 最终将跨恒星物流限制为最多 8 座空间站之间的聚合结算。
- 保留运输船、翘曲器、电力、距离和科技的游戏意义。
- 提供独立空间站建设与管理画布，并支持桌面、手机、横屏和大字体。

### 3.2 非目标

- 不自动转换旧物流塔。
- 不删除、重写或近似结算传统物流。
- 不让太空电梯同时参与传统派遣和共享仓库结算。
- 不逐艘模拟银河舰队。
- 不保存跨星系在途货物；货物在 5 秒结算点即时到账。
- 不把模块做成大量独立 FactoryEntity。
- 不在本功能中改造普通生产建筑、传送带或 React Flow 主画布算法。
- 不改变现有“超大型物资出口”和本地活动贡献规则。
- 不赠送空间站或太空电梯。

### 4.2 空间站工地与入口

- 空间站科技解锁后，所有已探索恒星系都能独立、并行开工。
- 玩家在星图或当前恒星系切换栏中点击“开始空间站工程”。
- 开工后，星球切换界面立即增加“宇宙联合空间站 / 建设工地”入口。
- 核心完成后，同一入口转为正式空间站管理画布。
- 每个恒星系最多一座空间站；每颗行星最多一座施工发射平台。
- 同一恒星系所有施工平台共同向本系项目提交材料。
- 施工只按真实材料交付推进，不增加额外等待时间。
- 平台可以提前接收四个阶段仍有缺口的材料，并按阶段顺序结算。
- 空间站完成后平台停止接收施工材料，可以无损回收；尚在平台输入缓存中的物资退回所在行星托盘。

### 4.4 太空电梯升级

- 星际物流站 Mk.I 在第一项太空电梯科技完成后可原地升级为 Mk.II。
- 升级从建筑所在行星物资托盘直接扣料，不制造独立 Mk.II 建筑物品。
- 一个堆叠实体整体升级，但按 `machineCount` 逐台计算成本。
- 升级不暂停或取消当前传统航线，升级后默认仍为传统物流模式。
- Mk.II 不允许降级，因为它保留完整传统模式。
- 升级候选成本按每台计算：钛合金 10,000、框架材料 5,000、量子芯片 5,000、宇宙矩阵 10,000。

升级必须原子核对全部材料。失败不改变建筑、托盘、线路、槽位或路线。

### 4.5 双模式切换

Mk.II 具有两种互斥模式：

```text
legacy   传统物流模式
elevator 太空电梯模式
```

传统模式行为必须与当前星际物流站完全一致。

从传统模式切换为太空电梯模式：

1. 写入待切换状态并停止该站创建新航线。
2. 查找该站作为需求端、供应端、载具所有者或中转点参与的全部传统航线。
3. 等待这些航线按原规则完成，不取消、不退款、不瞬移。
4. 在下一个 5 秒枢纽结算边界完成模式切换。
5. 模式切换完成后，该站从传统候选索引和派遣循环中彻底排除。

等待期间玩家可取消切换，取消后恢复新航线派遣。

从太空电梯切回传统模式：

- 在下一个 5 秒结算边界停止共享仓库访问。
- 共享仓库物资仍留在空间站，不瞬移回物流塔。
- 建筑本地缓存、线路、五槽配置、运输机、运输船和翘曲器保持原样。
- 恢复传统模式后重新进入传统候选索引。

太空电梯模式下，原塔内运输机、运输船和翘曲器继续停放，但不参与任何模拟；切回传统模式后立即恢复。

### 4.6 太空电梯端口

传统模式保持现有五个输入口、五个输出口和五个物流槽语义。

太空电梯模式：

- 五个输入口在视觉和交互上合并为一个大型方形通用入口。
- 通用入口可连接任意数量的独立传送带。
- 每条传送带仍运输一种物品，但不同线路可以运输不同物品。
- 输入物品不占用五个输出槽，送达后自动上传本系共享仓库。
- 五个输出口继续存在，每个输出口配置一种物品。
- 五个输出口必须配置不同物品。
- 每个输出口可连接任意数量线路，但这些线路都运输该口指定物品。
- 第一次切换时，五个输出口按槽位索引继承传统五槽的物品。
- 空输出口连接到输入物品唯一可推断的目标建筑时可以自动配置，否则打开物品选择器。

修改已有线路的输出口物品时：

1. 连续确认两次并显示将拆除的线路数量、传送带数量和线路物资。
2. 确认后只拆除该输出口关联线路。
3. 返还对应等级和并联数量的传送带。
4. 线路缓存和未送达物资完整退回本系共享仓库。
5. 其他输出口、线路和共享库存不变。

### 4.7 本恒星系共享仓库

- 每座已完成空间站拥有一个按 ItemId 稀疏存储的共享仓库。
- 仓库在玩法上无限，不提供仓储模块或容量升级。
- 持久化值使用规范十进制非负整数字符串。
- 显示使用万、亿和科学计数法，悬停、聚焦或手机点击显示完整精确值。
- 技术保护上限为每个值 256 位十进制数字，仅用于阻止恶意或损坏存档，不作为正常玩法上限。
- 普通建筑、传送带和物流塔每次转入转出的数量仍必须先限制为安全整数，再与大整数仓库运算。

每种物品具有跨星系策略：

```text
interstellarEnabled  是否参与跨空间站调度
reserve              本系对外供应后必须保留的数量
target               本系希望通过跨星系调度维持的目标数量
```

默认规则：

- 新物品第一次进入仓库时只供本星系使用。
- `interstellarEnabled=false`、`reserve=0`、`target=0`。
- reserve 只限制跨星系出口，本地太空电梯输出允许库存降至 0。
- target 只触发跨星系请求，不是仓储上限。

### 4.8 五秒结算顺序

所有枢纽物流以持久化模拟时间的 5 秒边界结算。不得依赖墙上时间或画面刷新。

每个结算边界按以下固定顺序执行：

1. 释放到期的全局舰队冷却桶。
2. 读取太空电梯所在行星的实际供电率。
3. 汇总所有通用入口本周期可上传物资。
4. 按本系物流主干和能源预算，比例结算上传并写入本系共享仓库。
5. 统计五路输出线的真实可接收数量，形成潜在本地需求。
6. 使用上传后的库存和潜在本地需求计算各空间站跨星系缺口。
7. 执行跨空间站即时调货并登记舰队冷却，不保存货物在途。
8. 使用调货后的库存向本地输出线路发货。
9. 更新 5 秒窗口吞吐、阻塞原因和诊断摘要。

空间站或联合协议未完成时，跳过不适用阶段。

### 4.9 比例分配与整数余数

以下场景统一使用比例分配：

- 多条通用输入线路竞争本系主干上传预算。
- 多条输出线路竞争同一物品库存或主干下载预算。
- 多个目标空间站竞争同一种物品。
- 多个来源空间站共同满足同一物品缺口。
- 银河能源不足时所有上传、下载和跨星系请求缩放。

基础公式：

```text
floor(totalBudget * request / totalRequest)
```

除法后的剩余整数按持久化公平游标和稳定 ID 顺序逐个补足。不得使用对象遍历偶然顺序、`Math.random()` 或 UI 排序。

输出线路只提取下游当前可以接收的数量，不建立太空电梯额外输出缓存。

### 4.10 物流主干模块

- 每座空间站画布只有一个固定的物流主干巨型节点。
- 节点保存已建模块数量，不为每个模块创建实体或 React Flow 节点。
- 玩家填写增加数量，系统一次性核对本系共享仓库并立即完成。
- 每 10 个已建模块进入下一成本等级，下一等级的单模块成本翻倍。
- 模块可以拆除，按被拆除模块实际成本的 50% 向下取整返还本系共享仓库。
- 模块按后建先拆计算成本，避免利用成本等级套利。

首轮候选容量：

```text
本系每 5 秒主干容量
  = (10,000,000 + 10,000,000 * 物流主干模块数)
  * (1 + 0.05 * 银河物流协议无限科技等级)
```

上传、下载和跨星系收发共用该空间站主干预算。跨星系调货同时消耗来源与目标空间站的剩余主干预算。

候选基础成本，模块 1-10：

- 框架材料 100,000
- 量子芯片 50,000
- 处理器 100,000
- 宇宙矩阵 10,000

模块 11-20 成本乘 2，21-30 乘 4，以此类推。批量建设使用大整数等比求和，不逐模块循环。

### 4.11 能源核心模块与银河能源池

- 每座空间站有一个固定能源核心节点。
- 能源核心不发电，只提高空间站从本恒星系电网接收功率的上限。
- 空间站虚拟负载使用最低消费优先级，普通工厂负载先获得电力。
- 本恒星系所有已殖民行星电网按稳定顺序共同提供剩余电力。
- 联合协议完成前，空间站贡献只供本系枢纽物流使用。
- 联合协议完成后，所有已建空间站贡献汇总为银河能源池。
- 银河能源池是每个模拟步的可用功率汇总，不是持久储能或电池。
- 能源不足时，所有枢纽上传、下载和跨星系运输同比降速。

首轮候选值：

- 每座空间站基础接收上限：1 TW。
- 每个能源核心模块：增加 1 TW 接收上限。
- 空间站基础待机功耗：100 MW。
- 太空电梯基础功耗：每个堆叠单位 100 MW。
- 星系内上传或下载动态能耗：0.1 MJ / 件。
- 跨星系调货动态能耗：1 MJ / 件。
- 第三项太空电梯科技把电梯动态能耗降低 50%。

候选基础成本，模块 1-10：

- 反物质燃料棒 50,000
- 湮灭约束球 50,000
- 奇异物质 100,000
- 量子芯片 50,000

电力规划必须先计算潜在物流请求，再把虚拟负载纳入确定性供电分配，最后按实际获得功率结算货物。不能在货物移动后补写虚假耗电。

### 4.12 星际运输模块、舰队与翘曲器

联合协议完成后：

- 任意空间站可以从全局随身载具栏安装物流运输船。
- 八座空间站安装的运输船汇总为一个全银河舰队池。
- 拆卸时只能取出当前空闲运输船。
- 星际运输模块总数决定全局舰队安装上限和跨星系模块吞吐。
- 全部空间站共享一个精确大整数翘曲器仓库。
- 任一空间站可以从本系共享仓库手动补充或按目标自动补充全局翘曲仓。
- 同恒星系共享仓库内部结算不消耗翘曲器。

首轮候选值：

- 全局基础舰队上限：100,000 艘。
- 每个星际运输模块：舰队上限 +100,000 艘。
- 全局基础跨星系模块吞吐：每 5 秒 10,000,000 件。
- 每个星际运输模块：每 5 秒跨星系吞吐 +10,000,000 件。
- 每艘等效运输船容量复用现有 `getInterstellarCargoCapacity()`。
- 每艘等效运输船派遣时消耗 2 个翘曲器。
- 货物在结算点立即从来源仓库扣除并加入目标仓库。
- 舰队按现有恒星系距离和物流速度计算冷却，冷却结束后回到全局空闲池。

持久化只保存聚合舰队返回桶：

```text
routeKey + returnAtSimulationSecond + vesselCount
```

同一返回时间和 routeKey 必须合并。不得保存逐艘对象或货物在途内容。

单次跨星系调货量取以下限制的最小值：

- 来源超过 reserve 的库存。
- 目标低于 target 的缺口。
- 来源与目标主干剩余容量。
- 全局星际运输模块剩余吞吐。
- 空闲舰队总运力。
- 全局翘曲器可支持舰队数量。
- 银河能源池可支持吞吐。

候选基础成本，模块 1-10：

- 钛合金 100,000
- 框架材料 50,000
- 粒子容器 100,000
- 空间翘曲器 10,000

拆除星际运输模块后若新上限低于已安装舰队数量，必须拒绝拆除并报告需要先卸下多少空闲运输船。

### 4.13 跨星系供需算法

每个启用跨星系调度的物品独立处理：

```text
sourceExportable = max(0, sourceInventory - sourceReserve)
targetDeficit    = max(0, targetTarget - projectedTargetInventory)
```

- 所有合法来源按 `sourceExportable` 比例共同供货。
- 所有合法目标按 `targetDeficit` 比例共同获得物资。
- 不提供空间站来源优先级。
- 没有合法来源时保留目标缺口并显示诊断。
- 货物即时到账，但舰队按来源与目标系统距离进入冷却。
- 如果只建成两座空间站，联合协议完成后这两座即可互联；不要求八座全部完成。

未建空间站的恒星系继续使用传统物流。第一版不增加传统兼容船坞；玩家可以保留部分 Mk.II 在传统模式，直到目标星系空间站完成。

## 7. 确定性与大整数实现要求

- 持久化使用规范十进制字符串，禁止把 JavaScript `bigint` 直接交给 JSON。
- 复用并扩展现有 `normalizeDecimalIntegerString()`、`formatQuantityCompact()` 和 `formatQuantityExact()`。
- 新增纯函数完成加、减、比较、min、比例分配和批量成本求和。
- 每次从普通库存转入 hub 时，移动量必须先是非负安全整数。
- 每次从 hub 转出普通库存时，先以 BigInt 取 min，再转换为安全 number。
- 余额不足、供电不足或输出堵塞时不允许产生负数、Infinity、NaN 或指数形式存档值。
- 比例分配必须在不同对象数组顺序下产生同一稳定结果。
- 5 秒边界由 `elapsedSeconds` 推导，保存重载后不得重复或跳过一次结算。

## 12. 主要风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 大整数污染普通 number 库存 | 只在系统仓库和策略使用十进制字符串；边界移动量限为安全整数 |
| 模式切换造成重复路线 | 过渡期停止新派遣，遍历全部路线角色，安全边界后切换 |
| 通用端口破坏现有线路几何 | 新增稳定端口索引；旧端口配置保留；桌面/手机几何回归 |
| 全局电力引入循环依赖 | 先计算潜在请求和虚拟负载，再分配电力，最后结算物资 |
| 即时货物让舰队失去意义 | 货物即时到账但舰队按距离冷却，船数和翘曲器仍限制吞吐 |
| 模块批量成本逐个循环 | 使用 BigInt 分段等比求和，成本等级每 10 个一组 |
| 空间站无法安全拆除 | operational 核心不允许拆除，只允许停用；模块按规则拆除 |
| v43 回滚到旧客户端不可读 | 正式发布前完成全部门禁；代码回滚不降级或重写玩家存档 |
| 新 workspace 加重主线程 | 懒加载、打开时冻结底层画布、不渲染逐船动画 |
| 先做 UI 后发现无性能收益 | 阶段 0 性能门槛未通过则停止后续开发 |

## 14. 完成定义

只有同时满足以下条件才算完成：

1. 功能不是显示层样例，科技、建设、升级、仓库、模块、舰队、电力和跨星系调度全部真实生效。
2. 旧存档无损迁移，传统物流行为不变。
3. 太空电梯模式不再进入传统伙伴匹配或逐路线模拟。
4. 精确大整数、5 秒结算、比例分配和舰队冷却跨在线、离线、保存重载保持确定性。
5. 桌面、手机、亮色、深色和 80%-200% 字体完成自动化与视觉验收。
6. 性能达到本计划硬门槛，并有真实终局样本证据。
7. 没有部署、发布或替换安装包，除非用户另行明确授权。
