# DSP极简网络 0.9.1 联合空间站活动规格

> 规格日期：2026-07-24
> 产品版本：0.9.1
> GameState：v33（不变）
> 存档封装：v2（不变）
> 云 schema：v7（不变）

## 1. 目标

`0.9.1` 开放首轮“宇宙联合空间站巨构建设任务”，修复超大型物资出口无法从施工托盘部署的问题，并让所有玩家无需账号即可在本地完成个人活动记录。

本版不实现真实贡献上传、账号资格、跨存档去重、服务器确认、奖励领取或宇宙联合空间站本体。这些能力不得通过界面文案暗示为已经开放。

## 2. 活动规则

- 活动 ID 在生产配置中唯一确定。
- 部署验收后单独启用活动，开始时间与结束时间相差精确 72 小时。
- 四项个人目标各为 1,000,000：宇宙矩阵、太阳帆、小型运载火箭、反物质燃料棒。
- 四项全服模拟目标各为 1,000,000,000。
- 个人任务只有四项全部达到目标才完成；超额投入继续保留在本地记录。
- 全服进度继续使用 `server/activity.mjs` 中的确定性时间曲线，不读取玩家贡献。
- 活动界面必须明确标注“全服模拟”和“本地已记录”。
- 活动奖励、真实全服累计和服务器贡献确认均标注为后续版本能力。

## 3. 玩家参与

- 不要求登录、邮箱验证、云存档或排行榜资格。
- 客户端从同源 `/api/public-status` 获取匿名只读配置和服务器时间。
- 香港 HTTPS 与上海 HTTP 都允许读取这个匿名只读端点。
- 上海 HTTP 仍不得注册、登录、上传云存档或传输任何账号凭据。
- 活动配置同步后，客户端沿用 GameState v33 的 `constructionActivity`、`participantId`、`personalDelivered` 和 `pendingBatches`。
- `pendingBatches` 在本版只是可供后续版本读取的本地活动记录，不触发网络请求。
- 本地主存档、三个手动槽、导入导出和现有云存档会继续按原有 GameState 保存这些字段。

## 4. 超大型物资出口

- `galactic_material_exporter` 加入桌面施工托盘和新版手机部署目录。
- “全部”和“戴森”分类均可找到该巨构，搜索完整名称也必须可见。
- 完成宇宙矩阵科技后可以制造；已有 v33 存档不迁移、不重发、不清空施工库存。
- 既有 v32 及更早终局存档仍沿用 v33 迁移中的一次性补发规则。
- 制造成本保持不变：宇宙矩阵 1,000、小型运载火箭 500、框架材料 1,000、量子芯片 1,000。
- 放置后默认暂停；玩家必须在任务页或检查器中显式恢复。
- 未获得有效活动配置时，即使出口被标记为运行，也不得消费输入缓存。
- 活动有效且处于时间窗口内时，四个专用端口的真实整数投入同时更新原银河出口项目和本地个人活动记录。
- 线路、端口 ID、巨构尺寸、React Flow handle 几何与回收保护规则不变。

## 5. 任务入口

- 点击已放置的超大型物资出口，直接打开“生产统计 → 银河”任务页。
- 任务页显示服务器倒计时、个人四项进度、全服四项模拟进度和本地记录总量。
- 任务页列出当前存档中的全部超大型物资出口。
- 每座出口可直接暂停或恢复，也可定位回对应行星与画布设备。
- 桌面、经典手机和新版手机共用同一任务状态与命令，不复制模拟规则。
- 手机按钮命中高度至少 44px；长名称在搜索结果中完整显示，不依赖长按或双击。

## 6. 版本与兼容性

- npm 产品版本从 0.9.0 升至 0.9.1。
- GameState 保持 v33，不新增迁移。
- 存档 envelope 保持 v2，云 schema 保持 v7。
- 不修改模拟随机性、活动批次结构、账号数据、排行榜资格或云存档协议。
- 现有本地存档不得被活动初始化、更新公告或页面跳转清除。

## 7. 生产启用

活动配置不编译进前端，也不随代码切换自动开启。两个节点先以关闭状态完成新制品、服务测试、备份、原子切换和公网烟测，再安装相同活动配置并重启服务。

生产配置必须满足：

```json
{
  "id": "union-station-2026-07-v1",
  "enabled": true,
  "startsAt": "<UTC ISO timestamp>",
  "endsAt": "<startsAt + exactly 72 hours>",
  "personalTargets": {
    "universe_matrix": 1000000,
    "solar_sail": 1000000,
    "small_carrier_rocket": 1000000,
    "antimatter_fuel_rod": 1000000
  },
  "globalTargets": {
    "universe_matrix": 1000000000,
    "solar_sail": 1000000000,
    "small_carrier_rocket": 1000000000,
    "antimatter_fuel_rod": 1000000000
  }
}
```

两个节点使用相同 ID、时间与目标。启用后需确认 `/api/health` 报告活动配置有效，`/api/public-status` 返回相同 revision、开始/结束时间和四项目标。

## 8. 验收

- 材料齐备时可以制造一座超大型物资出口并原子扣料。
- 桌面施工托盘与新版手机建造搜索均可找到并部署该巨构。
- 点击巨构打开银河任务页，任务页可恢复/暂停并定位设备。
- 未同步活动配置时出口输入不会被误耗。
- 活动开始前、进行中、截止瞬间和结束后状态正确，结束后全服模拟冻结。
- 四项全服目标均精确为 1,000,000,000，四项个人目标均精确为 1,000,000。
- HTTP 只读活动状态可用，同时账号传输仍被拒绝。
- 本地贡献保存重载后保持一致，GameState 仍为 v33。
- 更新公告在桌面、390x844、844x390 和 200% 字体下可读、可关闭。
- 正式发布执行 typecheck、完整 Vitest、服务端测试、运维测试、生产构建、完整 Playwright、manifest 校验和双节点烟测。
