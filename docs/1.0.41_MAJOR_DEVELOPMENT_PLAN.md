# DSPidle2 1.0.41 大版本开发与发布前总纲

> 开发日期：2026-08-13～2026-08-14
> 基线：未发布的 1.0.40 开发成果，生产环境仍保持 1.0.39
> 固定运行时源码：`59f37d18feb90b38822ebfd83b76baa19215ccce`
> Build ID：`1.0.41+59f37d18feb9`
> 状态：开发侧完成；真实 Linux/systemd/Nginx 隔离演练、实体设备和正式签名仍是 Release Agent 硬门禁

## 目标与不变量

1. 让超过旧 32 MiB 解压后限制的大存档得到上传前预检、明确诊断和有界服务端保护；保证 48 MiB 合法存档跨 Web、Windows、Android 和 API 可传输。
2. 把云同步、离线结算和排行榜已有底层状态变成玩家可以理解、重试和导出的界面，不以静默丢收益、重传或覆盖旧云 revision 收口失败。
3. 提升桌面和手机端传送带接口命中与连续连接效率，整批连接保持原子、守恒且不自动改配方。
4. 修复中文输入法、移动键盘、横竖屏和父级刷新导致的输入内容消失。
5. 完整修复 1.0.40 No-Go 暴露的发布控制面缺陷，禁止复用 `1.0.40-58d3e6f986ec` 或中间 `1.0.41+96b7adb4cfa1`。
6. 保持 `GameState v46`、envelope v2、云 schema v7、SQLite layout v2、普通/速通模式边界及旧存档字节兼容；不修改排行榜历史和玩家存档。

## 已完成范围

### 大存档云同步与状态中心

- 共享传输契约把保证可用的单存档正文提升到 48 MiB，并分别限制原始正文、gzip、解压后正文、旧包装、响应、并发解压内存和超时。
- 上传前显示原始、压缩、解压后大小、服务端上限和超出字节；32 MiB 以上合法存档不再被旧常量提前拒绝。
- 服务端按“请求数 + 解压后字节”双重调度，gzip 炸弹、超时、取消和队列饱和在写入前拒绝；失败不产生 revision，不改旧云档。
- 状态中心显示模式、槽位、本地/云 revision、最近成功时间、上传/确认/冲突/失败/恢复状态，并提供安全重试、取消、本地/云副本导出和脱敏诊断。
- 当前未实现分块上传；UI 明确显示该能力未启用。服务器端仍保留 64 MiB 解压硬上限和 96 MiB 并发解压预算，不能无限提高。

### 离线结算与排行榜体验

- 普通离线超过 60 秒显示快速、精确、放弃收益三种选择；快速失败展示原因并允许从原检查点重试，精确可安全取消，放弃收益双重确认。
- 显示阶段、已计算时长、预计耗时、结算检查点和最终结算区间/模式/收益/阻塞原因。
- 纯挂机规则不变：只有前台运行享受高倍率，后台约五分钟宽限后转普通离线；不增加屏幕常亮、设备控制或新权限。
- 排行榜继续分开显示服务器认证成绩与本地 60 秒最佳值，显示普通主槽来源、形成下一窗口尚差秒数、同步入口和本地/服务器差异原因。

### 传送带接口与连续连接

- 端口视觉大小和真实命中范围分离；设备偏好提供标准、放大、超大、自动适配，自动为默认，触控目标不小于 56 px。
- 连续连接模式支持 Ctrl+点击继续选择、Enter 原子确认、Esc 取消；移动端有等价确认、撤销和清空按钮。
- 批量预览显示目标、物品、重复/不兼容等原因。10/50/100 条连接只提交一个领域事务；任一非法或材料不足则整批不创建、不扣材料。
- 单条拉线、吞吐、优先级、并联数、配方、物流槽和物资守恒逻辑不变。

### 输入稳定性

- 新增稳定本地草稿和 composition 保护，区分外部初始值同步与用户正在输入。
- 注册、登录、档案、搜索、目录选择器在中文组合输入、blur、弹窗、父级刷新和组件重绘期间不被清空。
- 草稿仅在内存中存在；密码不进入 localStorage、普通草稿、诊断或日志。

### 1.0.40 No-Go 发布控制修复

- 所有发布/运维 CLI 使用 `realpath` 判断直接执行，真实 `current` 软链接入口会启动而非静默退出 0。
- pending journal 移至 `/var/lib/dsp-idle-cloud/release-state/pending-switch.json`，采用 `prepared/publishing/published/recovering` 两阶段状态、文件和目录 fsync、read-back 校验。
- 状态目录固定为 `root:服务组 2750`，状态文件 `0640`；active API 可读不可改。共享 `/run` 使用 `RuntimeDirectoryPreserve=yes`。
- writer lock 由 root 安全创建并验证真实 inode、服务 UID/GID 和 `0660`；锁占用退出 75，配置错误退出 78，systemd 使用 `RestartPreventExitStatus` 和 StartLimit。
- 恢复路径在启动选定 writer 前显式停止所有可能 writer 并验证锁；恢复失败保持 proxy hold 和 durable journal，不宣称回滚完成。
- 旧 API 的 `/api/ready` 只有明确 404 才立即走 health 兼容；503 或不可写状态继续拒绝。
- 恢复必须有有效低流量备份窗口；1.0.41 另有默认 15 分钟启动宽限，防止重启立即复制多 GiB 数据库，同时不永久关闭后续备份。
- release evidence 绑定 SHA-256、大小、mtime、dev/inode、quick_check、schema/layout，并拒绝活跃 WAL/SHM。ext4 无 reflink 且备份超过 512 MiB 时，切换关键路径立即拒绝，要求事先以有界 I/O 生成独立、已校验的 preflight 副本。

## 兼容与迁移

- 没有新增 GameState 或存档 envelope 字段，不执行存档迁移，也不改写旧正文。
- 普通/速通 × `main/1/2/3` 的本地、云端、排行榜和恢复隔离继续沿用 1.0.40 实现。
- 老 Web/Android/Windows 客户端继续使用现有 raw/gzip/legacy 协议；服务端下载正文、checksum 和 revision 保持原样。
- 服务器部署配置需要安装新版 systemd 模板和 `/etc/dsp-idle-cloud/runtime.env`；这是代码部署配置更新，不是数据库迁移。

## 性能与风险边界

- 云上传多出的成本主要是上传前尺寸统计和按字节调度；不会解析第二份权威状态，也不会无限并发解压。
- 48 MiB 保证档相比旧 30 MiB 需要更多网络、临时内存和 SQLite 容量；配额调整为单 revision 64 MiB、单槽 512 MiB、单模式 1 GiB、单账号 2 GiB。
- 连接端口透明命中层只在交互时参与命中；批量连接把最多 100 条写入合并为一次状态发布，降低逐条重绘。
- 没有在本批重写结算引擎、删除缓存、跳过产量或补物资。快速结算仍允许既有近似误差，精确结算和纯挂机守恒规则不变。
