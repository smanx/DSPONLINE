============================================================
三、最终产品方向
============================================================

目标是把升级后的星际物流塔接入“全宇宙唯一共享物资池”，而不是建设空间站。

生产线
  -> 量子物流塔输入
  -> 全宇宙共享库存池
  -> 任意星球/恒星系的量子物流塔输出
  -> 消费生产线

硬性玩法规则：

- 星际物流塔可以原地升级为量子物流塔；
- 建筑升级与接入量子网络是两个独立动作；
- 升级完成后默认仍为传统物流模式；
- 玩家主动接入后，量子塔才访问共享池；
- 所有已接入量子塔，无论星球或恒星系，访问同一份全局库存；
- 量子塔之间货物即时可用，不创建量子塔对量子塔的 StationRoute；
- 输入线路把物资写入共享池，输出线路从共享池提取物资；
- 输出只提取下游当前能接收的数量，不制造无限的本地输出缓存；
- 传统塔继续使用旧物流逻辑；
- 传统塔与量子塔可以长期混用；
- 混用期间必须存在临时兼容桥，不能因为一座塔接入量子网络就让旧产线断供；
- 不新增空间站建筑、空间站画布、建设工地或八站网络。

量子模式保持现有物流塔的物理接口和线路几何：

- 保留现有五个输入/输出端口、槽位、配方和传送带 edge；
- 不删除并重建玩家已有传送带；
- 不引入旧电梯方案的 universal input、elevatorOutputIndex 或五路输出改线逻辑；
- 现有供需槽仍负责决定输入和输出物品，但物资结算对象变为全局共享池；
- 新增线路也必须复用现有端口和端点规则。

============================================================
四、共享库存池
============================================================

GameState 增加一个新的量子网络状态，名称可以调整，但语义必须满足：

interface QuantumLogisticsNetworkState {
  enabled: boolean;
  inventory: Partial<Record<ItemId, DecimalIntegerString>>;
  routingCursors: Record<ItemId, number>;
}

`QuantumNetworkDiagnostics`、活跃物品集合、线路索引、带宽预算和 BigInt 解析缓存只能存在于
`SimulationAdvanceSession` 或量子网络 runtime，不得写入 GameState、存档校验或排行榜哈希。

要求：

- 只有一份 inventory，不按星球、恒星系、空间站复制；
- inventory 使用规范十进制非负整数字符串持久化；
- 运行时可以使用 BigInt 或等价精确整数，但禁止 BigInt 直接进入 JSON；
- 技术校验限制每个物品最多 256 位十进制数字，不能把它当正常玩法容量；
- 共享池数量不受普通建筑缓存上限、物资托盘上限或 32 位整数限制；
- 普通建筑与传送带之间转移时仍先限制为非负安全整数；
- 余额不足、输出堵塞、低电或保存重载都不能产生负数、NaN、Infinity 或科学计数法存档值；
- 未接入量子网络的塔不能读取或写入共享池；
- 新物品第一次进入共享池时必须建立稳定物品索引，不扫描所有目录物品。

共享池结算只能处理活跃集合：

- 输入或输出本周期有申请的物品；
- 共享池库存发生变化的物品；
- 仍有兼容桥尾货的物品。

不能每个模拟步扫描所有物品、所有塔与所有塔配对。

============================================================
五、量子塔带宽与无线科技
============================================================

不要为全网设置一个会随玩家物资数量增长的逐项上限。数量大小只影响一次大整数运算，
不会决定模拟循环次数。全局带宽应由量子塔带宽之和自然形成。

沿用现有 galactic_logistics 无限科技等级 L。现有科技同时提高物流速度和运输载荷，
因此量子带宽使用平方倍率，而不是只乘一次：

  M = (1 + 0.05 * L) ^ 2

当前平衡基准按同一玩家存档内全部已接入量子塔的实际堆叠总数计算：

  globalUploadCap = 5000 件/分钟 * M * 全部量子塔堆叠总数
  globalDownloadCap = 5000 件/分钟 * M * 全部量子塔堆叠总数

上传和下载分别拥有额度，不允许上传占满后把下载永久锁死。额度属于全存档共享预算，
不再按单座塔限制供需；轨道采集器可以使用上传预算，但不额外贡献带宽。

不要额外增加固定的 global hard cap，除非性能和玩法测试证明有必要。若产品需要显示
全局上限，显示上述动态总和即可。

最新终局存档基准（dsp-idle-save-2026-07-31.json，仅用于平衡与测试）：

- 402 个 interstellar_logistics_station 实体；
- machineCount 合计 4,744,191 个实际堆叠单位；
- 720 条活动传统路线；
- 83,796,745 件在途货物；
- 115,018 个活动载具；
- 物流塔上一模拟步实际到货约 1.967B 件/分钟；
- 当前路线额定在途速率约 11.034B 件/分钟；
- 全银河实体生产通量约 79.293B 件/分钟；
- galactic_logistics 无限科技等级为 232，M 为 158.76；
- 按上述公式，单个实际堆叠单位为 63,504 件/分钟；
- 10,000 堆叠实体为 635.04M 件/分钟；
- 全部当前物流塔合计理论带宽约 301.275B 件/分钟（标准难度）；
- 舒缓难度按现有 1.1 物流倍率另乘 1.1。

这些数字不是让 Agent 硬编码到存档，而是用于性能夹具、容量回归和首次平衡。
实现必须把基准常量集中在量子物流领域模块，不能散落在 UI、Worker 和测试中。

============================================================
六、传统塔与量子塔混用的兼容桥
============================================================

这是 P0 可靠性要求。

量子塔接入流程：

1. 升级建筑：原有 belts、stationSlots、inputs、outputs、库存、StationRoute、运输船、
   运输机和翘曲器全部保留，模式仍为 legacy。
2. 玩家点击“接入量子网络”：写入持久化 transition 状态，不立刻删除路线。
3. 对该塔停止创建新的传统路线；已有路线继续按旧规则推进。
4. 建立兼容桥，记录旧路线尾货、来源/目标、物品、剩余数量和确定性到达边界。
5. 在安全的 5 秒结算边界转移该物品的所有权：legacy、bridge、quantum 三者只能有一个
   作为写入者，禁止复制库存后两边同时扣除。
6. 量子输入开始写入共享池；量子输出开始从共享池读取。
7. 仍为 legacy 的塔通过兼容桥向共享池请求或提交物资，不能因为另一端已经量子化而断供。
8. 所有尾货完成并且桥上没有未结算数量后，移除该塔的传统伙伴匹配和派遣索引。
9. 过渡可在提交前取消；取消必须恢复原有 legacy 路线和派遣资格。

兼容桥是临时的，不得成为永久的第二套物流模拟。量子塔完成接入后：

- 不进入 findStationSlotPeers、dispatchStationScope、advanceStationRoutes 的量子路径；
- 不逐艘模拟量子运输船；
- 不为量子塔生成新的 StationRoute；
- 只保留仍服务传统塔的有限桥接合同；
- 所有桥接合同完成后从运行时索引和 GameState 中清除。

若当前旧路线模型无法精确保存尾货到达边界，宁可保留旧路线到完成，也不能瞬移、复制或销毁货物。

运输船与翘曲器处理：

- 传统模式继续按 1.0.16 规则使用；
- 量子模式不逐船运行，不创建航程和距离计算；
- 已安装的运输船、运输机和翘曲器不能被删除或凭空消耗；
- 量子模式下它们进入停放/保留状态，切回 legacy 后恢复；
- 不为了保留旧表现而在量子模式维护一套隐藏的逐船模拟。

============================================================
七、五秒确定性结算
============================================================

量子池以持久化模拟时间的 5 秒边界结算，不依赖墙上时间、画面刷新或 Worker 调度次数。

推荐固定顺序：

1. 推进仍在运行的传统 StationRoute 和兼容桥尾货；
2. 汇总量子输入线路可提交数量，按单塔额度与实际供电率裁剪；
3. 将实际提交量一次写入全局共享池；
4. 汇总量子输出线路的下游可接收量；
5. 按物品、优先级和持久化公平游标比例分配共享池库存；
6. 将实际发货量写入输出建筑，未能接收的数量留在共享池；
7. 生成缺货、缺电、带宽不足、兼容桥等待和输出堵塞诊断。

所有比例分配必须：

- 使用稳定 ID 排序和持久化游标；
- 不依赖对象遍历顺序、Math.random() 或 UI 排序；
- 对除不尽的整数余数进行稳定轮转；
- 在 1 秒、5 秒、60 秒和离线分段调用下得到相同状态哈希。

============================================================
八、存档与服务端
============================================================

从干净的 1.0.16 / v42 设计新的量子网络迁移：

- GameState 新版本只增加量子网络状态和量子塔过渡所需字段；
- 不保留 systemSpaceStations、galacticHubNetwork 或旧电梯字段；
- v42 -> 新版本默认量子网络 disabled、inventory 为空、所有物流塔仍为 legacy；
- 不赠送量子升级、量子材料、共享库存、运输船或翘曲器；
- 旧 entities、belts、inputs、outputs、缓存、StationRoute、载具和翘曲器逐字段保留；
- 迁移必须幂等，重复加载不能改变状态哈希；
- envelope 保持 v2，cloud schema 保持 v7，SQLite layout 保持 v2；
- 服务端客户端状态白名单、结构校验和大小校验同步扩展；
- 内容包物品只有在内容包启用后才能进入共享池；
- BigInt 不得直接序列化；
- 不能用清档、归零库存、删除路线或重建工厂作为迁移捷径。

如果用户提供旧实验性空间站 v43 存档，默认拒绝载入并明确提示不兼容，不能把旧空间站库存
自动合并进量子共享池。

============================================================
九、科技与用户界面
============================================================

只新增一条量子物流科技/升级路径，具体 ID 和成本必须集中在 content.ts 的领域目录，
不得重新引入空间站分支。科技至少要求现有星际物流、空间翘曲、宇宙矩阵和必要的物流无限科技。

升级界面：

- 物流站检查器显示“升级为量子物流塔”；
- 先完成建筑升级，再由玩家点击“接入量子网络”；
- 显示当前模式、共享池访问状态、上传/下载上限、实际吞吐、供电率和兼容桥进度；
- 显示“旧航线尾货数量”和“预计交接边界”；
- 升级或接入失败时必须显示真实原因；
- 不显示空间站、太空电梯、恒星系空间站入口、施工阶段或旧模块节点。

共享池界面可以放在现有物流/统计工作区：

- 搜索物品、查看精确库存和科学计数显示；
- 查看每种物品本周期输入、输出、缺口和分配结果；
- 查看量子塔列表、带宽排行、缺电和桥接状态；
- 数字过大时不能撑坏布局；
- 桌面、手机竖屏、手机横屏、亮色模式和 80%～200% 字体都必须可用；
- 不为了显示共享池创建逐物品 React Flow 节点。

============================================================
十、实现顺序
============================================================

阶段 0：基线恢复与只读性能原型

- 先完成 1.0.16 / v42 基线验证；
- 不修改正式 GameState，建立纯量子池模拟器；
- 使用匿名终局夹具和 dsp-idle-save-2026-07-31.json 的只读统计；
- 对比 402 塔、720 路线与全量量子输入/输出；
- 量子物流阶段目标至少降低 80%；总模拟时间目标至少降低 30%；
- 如果总收益低于 30%，停止后续 UI 和内容实现并报告证据。

阶段 1：量子领域模型与迁移

- 新增独立量子物流领域模块，不继续把完整实现堆回 engine.ts；
- 增加大整数 helper、活跃物品集合、公平分配、带宽和供电计算；
- 完成 v42 -> 新量子版本迁移和服务端校验；
- 未接入量子网络的旧存档模拟性能回归不得超过 3%。

阶段 2：量子塔升级与全局池

- 实现原地升级、模式状态、输入写入和输出读取；
- 实现 5 秒边界、保存重载、在线/离线/分段等价；
- 量子塔从传统伙伴匹配、路径规划和逐路线派遣排除；
- 不删除现有 belts、slots、库存和传统逻辑。

阶段 3：兼容桥

- 实现传统供给 -> 量子需求、量子供给 -> 传统需求和双端同时切换；
- 测试尾货、取消接入、断电、缺货、重复保存、崩溃恢复和无重复扣料；
- 桥接完成后必须释放运行时索引和持久字段。

阶段 4：科技、桌面和手机 UI

- 闭合科技、建筑、配方、升级、图鉴、蓝图、迁移和服务端引用；
- 复用现有物流检查器和统计工作区；
- 不新增空间站工作区或星图空间站入口；
- 完成桌面/手机/亮色/大字体视觉验收。

阶段 5：性能、离线与候选发布

- 完成 1 小时、8 小时、24 小时、7 天、30 天在线/离线/分段一致性；
- 完成 1x、4x、12x 和纯挂机压力；
- 测试 100、10,000、1,000,000 个堆叠单位，以及 100/10,000/1,000,000 艘传统载具；
- 物资数量从 1M 到 1E 时，循环次数不得按数量增长；
- 没有单独发布授权前，不部署、不切下载页、不上传安装包。

十一、测试与验收
============================================================
