# 公开测试版后续路线图

## 决策原则

首个版本已经上线。下一阶段应从“继续增加功能”切换到“让现有版本能被可靠发布、长期保存、诊断和恢复”。下面按依赖顺序安排，不把尚未实现的内容写入项目现状。

## 2026-07-22 公开测试版强化 Goal（已完成）

- [x] 冻结首个公网源码基线、版本标签、可复现构建清单、原子切换与一键回滚。
- [x] 建立隐私友好的运营统计和受保护管理后台。
- [x] 完成 schema v5 账号安全、设备会话、本地账号绑定和云存档冲突选择。
- [x] 完成认证加密异地备份、隔离恢复演练和节点探针的代码与自动化测试；生产密钥、timer 和真实演练报告留到发布窗口安装。
- [x] 完成手机端第三轮：双指缩放、触摸吸附、长按防误触、逐点多选、横竖屏状态保持和自动低性能模式。
- [x] 加入可迁移、可确定性模拟的行星资源丰度、能源环境、运输距离和工业加成，并在星图公开倍率与推荐分工。
- [x] 将渐进教学延伸至红糖、石油链、黄糖、跨星球物流、戴森云和白糖，并支持直接定位停机设备或零流量线路。
- [x] 建立全星球产能总览、缺料/堵塞追踪、设备跳转、目标产量反推和批量配方/物流槽操作。
- [x] 启用 gzip、补充加载与 API 性能采集，完成全量测试、版本发布、生产备份、双节点灰度部署和首轮发布后观察。

完成基线：`v0.2.0` 指向已部署提交 `e6e7daf113dc`；香港与上海运行 `0.2.0-e6e7daf113dc`，云服务 schema v5。九个阶段的发布证据、哈希、备份和恢复记录见 [releases/0.2.0.md](./releases/0.2.0.md)。Brotli 属于后续可选优化，不作为本 Goal 的阻塞条件。

## 阶段 A：冻结并标记首个线上基线

目标：任何人都能从一个 Git 提交重建当前线上版本。

- 整理当前脏工作树，按功能审阅后提交，不删除现有用户或代理留下的有效改动。
- 设定首个公开测试 SemVer，统一 `package.json`、桌面安装包、构建 ID 和 Git 标签。
- 保存前端/后端发布清单、依赖锁文件和部署时间。
- 将本文档与 `develop-dspidle` Skill 作为后续任务的强制入口。
- 建立简短发布说明和已知问题列表。

完成标准：在空目录 `git clone` 后可用锁文件通过测试并生成与发布清单一致的产物。

## 阶段 B：生产数据与安全加固

目标：即使错误发布、磁盘故障或账号攻击发生，也不会丢失玩家存档。

- `/api/metrics` 与 `/api/admin/metrics` 已受管理员 bearer token 保护，公开入口只保留隐私聚合的 `/api/public-status`。
- 双 VPS 密钥、每日异地备份 timer、每月隔离恢复 timer 和首份真实恢复报告已落地；后续按月复查并演练新主机恢复。
- 账号与云恢复安全审计、磁盘/TLS/端点探针已落地；剩余生产告警接收端与日志集中化。
- 邮箱验证、忘记/重置/修改密码、会话撤销、数据导出和账号删除已部署为 schema v5；剩余邮件供应商配置、异常登录告警和后台处置。
- 补充隐私政策、用户协议、数据导出/删除说明。
- 对反馈和错误上报加入垃圾内容限制与管理查看工具。

完成标准：有书面恢复记录；一次全新主机恢复演练可以还原账号和云存档，并验证修订历史。

## 阶段 C：Web 性能与可观测性

目标：大陆玩家稳定快速进入主菜单，问题发生时能够定位。

- JS/CSS 已配置 gzip 并在香港、上海验证 `Content-Encoding`；Brotli 留作真实收益可衡量时的可选优化。
- 主菜单已不再提前下载 React Flow、模拟器和完整存档迁移器；后续继续审计 300 KB 以上资源。
- 外部 HTTPS、TLS、API、磁盘和静态入口探针已通过 systemd timer 运行。
- 前端错误、服务端错误率、P95 延迟、429、云冲突和备份状态已进入受保护后台。
- service worker 已使用确定性 build ID 隔离缓存版本，避免新旧应用壳混用。
- 基于真实访问量评估优选流量包，而不是一次性购买大额流量。

完成标准：记录压缩前后传输量；连续一周可用性和错误率有趋势数据与告警。

## 阶段 D：账号、云存档与排行榜正式化

目标：把当前可用原型升级为可运营系统。

- 本地身份已可显式绑定、换绑或解除云账号，绑定元数据不进入 `GameState`；后续补充首次绑定引导。
- 云冲突界面已支持比较本地/云端时间、运行进度、设备和科技摘要，并明确选择保留方向；后续补跨设备推送提醒。
- 设计赛季结算、封榜、历史榜、昵称治理和管理员撤榜。
- 将关键成绩验证逐步迁移到服务端可重放摘要或权威事件，而非只检查客户端总量。
- 用户规模增长后将单行 JSON SQLite 模型迁移为用户、会话、存档修订、榜单和事件表。

完成标准：多设备冲突和历史恢复有端到端测试；排行榜提交可以追溯到明确云存档和验证版本。

## 阶段 E：稳定性与架构治理

目标：降低改一处坏多处的成本。

- 拆分 `App.tsx` 的模拟会话、画布命令、存档、工作区和输入控制。
- 拆分 `engine.ts` 的电力、物流、科研、戴森和实体命令，保留一个确定性推进入口。
- 将 `styles.css` 拆为有顺序约束的 shell、canvas、workspace 和 responsive 层。
- 按领域分拆 E2E，建立存档 fixture 和少量视觉回归。
- 给内容目录增加生成式 ID/引用检查，减少手工联合类型和目录不一致。

完成标准：核心大文件显著缩小；每个领域有明确所有权和针对性测试，完整回归时长可控。

## 阶段 F：体验与平衡第二轮

目标：让玩家理解瓶颈并愿意长期挂机，而不是只看到系统数量。

- 使用真实玩家存档运行 2/8/24/72 小时平衡审计。
- 调整手搓过渡、科技卡点、电力曲线、物流吞吐和离线回归奖励。
- 13 步渐进教学已覆盖红糖、跨星球、戴森云和白糖；后续只根据真实新手流失数据调整节奏与文案。
- 加强缺料警报到设备、线路和聚焦配方的直接导航。
- 手机第三轮交互已经落地；后续只保留基于真机反馈的可访问性与机型兼容修正。

完成标准：新存档从开局到白糖有可重复的通关时间报告；关键卡点来自设计而不是 UI 不可发现。

## 阶段 G：原创化与正式公测

目标：形成可以独立推广的产品身份。

- 审查物品名称、配方、科技树、文案、图标、世界观和产品名称。
- 设计原创资源生态、行星特性和生产策略差异，但暂不引入黑雾战斗。
- 建立原创视觉资产与声音规范，替换仅用于高还原验证的内容。
- 在商业化或大规模推广前获取知识产权与商标方面的专业意见。
- 完成反馈入口、公开问题追踪、版本更新说明和社区运营规则。

完成标准：产品不依赖玩家对另一款游戏的名称记忆也能理解和传播，内容权属与发布材料清晰。

## 当前推荐的下一迭代

`0.2.0` 已完成发布、数据保护与首轮观察，下一轮建议按以下顺序推进：

1. 接入正式邮件供应商，完成专用测试邮箱的注册、验证、找回和过期链接验收。
2. 补齐隐私政策、用户协议、数据导出/注销说明和公测反馈治理。
3. 连续观察一周真实加载、API、错误、磁盘、证书、备份与恢复趋势，并配置告警接收端。
4. 拆分 `App.tsx`、`engine.ts`、`styles.css` 和 E2E 大文件，降低后续玩法迭代回归成本。
5. 基于真实新手流失和挂机数据进入阶段 F 的数值与教学调优，再决定原创化内容节奏。
