# 1.0.22 候选性能对比报告

日期：2026-08-02（北京时间）  
夹具：用户提供的超终局存档，只读内存副本，不写回、不上传。  
夹具规模：约 5.25 MiB、2,906 个实体、6,340 条传送带、464 座物流站、22 颗行星。

## 先说结论

目前真正默认开启的索引优化，把这份大存档每个模拟步的平均耗时从约 1,544 ms 降到约 189 ms，下降约 87.8%。这是当前玩家能直接得到的收益，且状态哈希、库存和线路守恒一致。

P3 保存重复短路在“状态完全没变、上次保存成功”的重复保存场景中约从 2,025.69 ms 降到 0.03 ms，约下降 99.998%。它只减少重复写入，不会跳过状态变化、失败写入或急救镜像。

P4、P5、P6 仍是实验路径，默认关闭。当前没有证据证明打开它们会给所有玩家带来稳定收益，因此没有为了数字强行开启。

## 为什么 P4-P6 不直接打开

- P4 的增量数据在这份存档中比完整状态更大；协议保留了大小比较和 revision 校验，发现不划算就回退完整状态。
- P5 的正式门槛是终局模式且当前行星至少 600 条线路。探针本身很快，但没有同设备同场景的 FPS、拖动、端口命中和 30 分钟内存证据。
- P6 探针只把行星数据分区扫描后合并校验，没有包含完整物流伙伴匹配、量子边界、在途路线和固定顺序结算。打开它可能改变结果，所以继续单 Worker。
