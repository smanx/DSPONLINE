## 2. 不变量与明确不做事项

- `advanceSimulation()` 对相同状态和秒数必须给出相同结果；活动曲线、物流索引和球壳 ID 生成不得调用模拟期墙上时钟或 `Math.random()`。
- 任何自动写入仍结算非负整数；内部周期、增产尾数和路线进度可以保留小数。
- 降低缓存上限、切换增产剂等级、删除托盘物资、粘贴球壳、迁移无限科技和结束活动都不得静默删除其他状态。
- UI 瞬时选择、球壳复制剪贴板、精确数字弹层、物流性能缓存和触摸指针状态不进入 `GameState`。
- 本批不实现此前的 7 天纯宇宙矩阵活动、全服 1 亿宇宙矩阵或前 50 名颜色奖励。
- 本批不创建 `universe_union_station` 物品或建筑 ID，不赋予空间站生产、功率、物流或数值加成。
- 本批不增加活动贡献 POST API、奖励领取 API 或账号资格表，不把开发数据写入生产 SQLite 或真实云账号。
- 构建、测试和部署不能自动开启活动；正式开关只能由服务端配置显式启用。

### 3.2 v32 → v33 迁移规则

1. `GameSettings.proliferatorBufferLimit` 缺失时补 `600`，非法值限制到 `1～100,000`。
2. 已存在建筑制造中心任务补空 `inventory`；其 `steps`、`stepIndex`、`elapsedSeconds`、目标和累计制造量原样保留。旧任务先继续从托盘取料，不回退已经完成的步骤。
3. 活动状态初始化为空；既有四类出口的等级、当前级交付、累计交付、银河信用、银河评分和调度设置原样保留，历史出口量不写入活动进度。
4. 已完成宇宙矩阵科技的旧档，如果没有已放置的超大型物资出口且施工托盘中也没有该建筑，补发 1 个；不得因重复加载再次补发。
5. 旧终局存档设为 `legacy-network`，继续使用原网络自动出口，直到玩家首次放置超大型物资出口；放置后永久切换为 `building`，避免新旧两条路径双重扣料。新 v33 存档完成宇宙矩阵科技时直接获得 1 个出口建筑并使用 `building`。
6. 无限科技按第 16 节的新曲线结转当前级已投入宇宙矩阵；旧 number 进度先无损转为规范十进制字符串，再以 BigInt 结转。可跨越多个新等级，不得丢失原等级记录或减少银河评分；超过新上限的旧等级写入 `historicalLevel`。四条长期科技达到 Lv.1000、连续体达到 Lv.23 后停止续研。
7. 太阳帆数量、轨道、寿命进度、总发射量和壳面吸附量不变，分别用新常量重新计算在轨功率和壳面功率。
8. 物流路线的 `cargo`、`vehicleCount`、`vehicleStationId`、翘曲消耗、进度和 waypoint 原样保留。
9. 托盘及建筑已有超额库存不裁剪；新递归制造保护只限制后续增长。
10. 迁移最终写 v33；加载器接受 v1～v33并归一到 v33，重复加载 v33 必须幂等。

云存档 payload 仍使用 v2 envelope。服务端 schema 不升级，但 `validateSavePayload()` 对 v33 必须校验新增增产剂上限、无限科技有效等级上限、可选历史等级以及不超过 64 位的规范十进制 progress 字符串，并继续接受合法的 v1～v32 历史上传。

## 5. 移动端放置时画布持续漂移（P1）

### 当前原因

`App.tsx` 的边缘滚动 RAF 只检查是否处于建筑或蓝图放置模式，并持续读取最后一次指针坐标；它没有要求指针仍按下或正在主动拖动。指针停在边缘、捕获丢失或第二指接管后，RAF 仍可能继续改变 viewport。

### 目标实现

- 建立唯一的 `CanvasPointerMotionSession` 瞬时状态，至少记录主指针 ID、是否按下、是否已进入拖动、最后坐标、边缘速度、RAF ID、长按/边缘定时器和捕获元素。
- 只有“主指针按下且移动超过拖动阈值”时允许边缘滚动；单击选择建筑进入放置模式后，普通悬停绝不移动画布。
- 使用一个幂等 `stopCanvasPointerMotion(reason)` 清理入口，统一执行：速度归零、取消 RAF、清除定时器、释放仍持有的 pointer capture、删除活动指针和禁止旧回调重新排队。
- 以下事件必须调用清理入口：`pointerup`、`pointercancel`、`lostpointercapture`、`touchend` 兜底、窗口 `blur`、页面隐藏、`fullscreenchange`、`orientationchange`、进入/离开放置模式、取消、成功放置、蓝图完成、工作区打开、行星切换和组件卸载。
- 第二根手指出现时先终止第一指放置拖动和边缘滚动，再进入现有双指缩放；第二指离开后不得自动恢复旧边缘速度，必须等待新的单指按下。
- 横竖屏切换继续保持世界中心，不把清理动作误当成 viewport 重置。

### 测试与验收

- Vitest 覆盖清理函数幂等、旧 RAF 回调失效和第二指接管状态机。
- Playwright 在经典手机与新版手机分别覆盖：点击放置后指针停边 1 秒不漂移、主动拖至左右边缘会移动、抬起后 1 秒位置不变、取消/完成/失焦/方向切换后不移动。
- 覆盖 390×844、844×390、768×1024 和 1024×768；断言 viewport 数值，不只依赖截图。

主要所有权：`src/App.tsx`、移动画布 hooks、`tests/e2e/mobile-shell.spec.ts` 和触摸回归用例。

## 6. 增产剂耗尽后按基础倍率运行（P1）

### 规则

- 安装状态、选择等级和选择模式是配置；“当前周期获得喷涂”是运行时结果，两者必须分开。
- 配方每完成一个周期才消耗对应喷涂点。点数足够的周期按所选等级和模式结算；不足一个周期时立即按基础速度、基础产量和基础功耗继续。
- 补充增产剂后无需重新选择，下一可喷涂周期自动恢复原等级和模式。
- 三档点数和效果不改：Mk.I `12` 点、Mk.II `24` 点、Mk.III `60` 点；额外产出和加速倍率沿用当前目录。

### 模拟设计

不能只删除 `canMachineRun()` 中的阻断判断。必须建立统一的 `MachineCyclePlan`，同时服务于：

- 电力需求；
- 周期速度；
- 输入可运行周期；
- 输出容量预测；
- 额外产出尾数；
- 喷涂点消耗；
- 生产统计与节点显示。

计划器先计算基础输入/输出上限，再计算可喷涂完整周期数。额外产出模式中，完成周期按“先喷涂、后基础”分区，只有前段周期生成额外产物和尾数；输出容量二分检查必须使用相同分区。加速模式中，将时间片拆成“仍有足够点数的加速阶段”和“耗尽后的基础阶段”，在阶段边界重新计算功耗和可完成周期。批量数学结算替代逐周期循环，避免堆叠机器和 30 天离线时退化。

功率计划必须读取同一周期计划。零点数时倍率严格为 `1`；时间片中途耗尽时只对加速阶段使用增产功耗，不能整段高功耗。前台 1 秒步进、离线 10/30 秒步进与 Worker 分批必须得到等价库存和点数。

### 状态优先级

显示顺序固定为：缺配方/缺科技 → 输出堵塞 → 缺生产原料或燃料 → 断电 → 低供电 → “增产剂耗尽，按基础倍率运行” → 正常运行。增产剂耗尽是运行警告，不计入 blocked machine。

### 测试

- 三档增产剂 × 额外产出/加速两模式 × 单机/堆叠。
- 点数恰好一周期、差一点、时间片中途耗尽、补料后恢复、切换等级退款。
- 输出只够基础产物但不够额外产物时，耗尽后的基础周期仍可继续。
- 满电、低电、断电、缺料、堵塞的状态优先级。
- `advanceSimulation(state, 30)` 与连续 30 次 1 秒推进等价；1 小时和 30 天离线 Worker 等价。
- 统计中的增产剂消耗、产量和功耗只统计实际获得喷涂的周期。

主要所有权：`src/game/engine.ts`、`statistics.ts`、`FactoryNodes.tsx`、`GamePanels.tsx`、生产管理与相关测试。

## 7. 供应塔与需求塔起送百分比分别生效（P1）

### 调度规则

对每个候选载具所有者分别计算：

```text
ownerSlotIndex = owner === demand ? demandSlotIndex : supplySlotIndex
minimumCargo = cargoCapacity * owner.stationSlots[ownerSlotIndex].minimumLoad
```

- 需求塔出动车辆取货时读取需求槽；供应塔出动车辆送货时读取供应槽。
- 路由策略、翘曲预算和目标容量仍由需求槽决定；本需求只改变载具所有者的起送门槛。
- 两端都有空闲载具时按稳定顺序逐个所有者派遣。第一条路线建立后立即更新货物预留、忙碌载具和翘曲器预算，第二端只能使用剩余量。
- `stationRouteReady()`、运行状态、星际诊断和吞吐预测必须与真实派遣使用同一 owner-slot helper，不能出现 UI 显示可发而引擎不发。

### 测试矩阵

- 供应 10% / 需求 100%，只有 50% 货物：仅供应塔车辆发车。
- 供应 100% / 需求 10%：仅需求塔车辆取货。
- 两端都满足时可各自出车，但总 cargo 不超过可用库存和目标空位。
- 行星运输机、星际运输船、跨恒星翘曲、返航、取消、供电中断和旧 `vehicleStationId` 缺失迁移。
- 对相同状态重复模拟，route ID、owner、cargo 和最终哈希稳定。

主要所有权：`src/game/engine.ts`、`stellarIndustry.ts`、物流单元测试和物流 E2E。

## 8. 增产剂缓存上限全局设置

### 当前容量审计

喷涂物品目前借用普通生产输入容量：

| 建筑堆叠 | 当前实际范围 |
| --- | ---: |
| 单台 | 120～600 件 |
| 10 台堆叠 | 1,200～6,000 件 |
| 100 台堆叠 | 12,000～60,000 件 |
| 现有生产建筑总安全上限 | 每种输入最多 1,000,000 件 |

### 最终设置

- 新字段 `settings.proliferatorBufferLimit`，默认 `600`。
- 预设按钮：`120`、`600`、`3,000`；自定义只接受十进制正整数 `1～100,000`。
- 只限制已安装喷涂机实体中“当前选择等级对应的增产剂物品”输入缓存；内部已转换的喷涂点数不占件数上限，点数效果不变。
- 有效容量为 `min(普通输入额定容量 × 堆叠数, proliferatorBufferLimit)`。该设置逐实体生效，不是全网络共享 600 件。
- 调低后保留当前输入物品和内部点数；超额期间传送带、手动转入和自动补充均停止，库存回落后恢复。
- 切换等级继续把旧等级物品和未消费状态按既有安全退款路径返还，不受新上限截断。
- 设置位于运行设置的两项建筑缓存设置旁，桌面、经典手机和新版手机复用同一验证器。

### 验收

覆盖最小/最大/预设、空值、小数、负数、指数、非数字、单机和 100 堆叠、降限超额、升限恢复、换星球、主存档/三槽/导入导出/云同步以及离线补料。服务端 v33 云存档校验拒绝缺失或越界字段，但继续接受 v32。

## 10. 超大数量统一紧凑显示（P1 UI）

### 公共 API

新增纯函数模块和共享展示组件，禁止各工作区继续复制 `formatAmount()`：

```ts
type QuantityInput = number | bigint | DecimalIntegerString;

formatQuantityCompact(value: QuantityInput): string
formatQuantityExact(value: QuantityInput): string
formatQuantityScientific(value: QuantityInput): string
<QuantityValue value={value} unit="kW" />
```

格式规则固定为：

- 绝对值 `< 10,000`：完整分组整数，如 `9,999`。
- `10,000～99,999,999`：使用“万”。
- `100,000,000～9,999,999,999,999,999`：使用“亿”。
- 绝对值 `>= 10^16`：四位有效数字科学计数法，如 `1.235e+16`。
- 缩放值 `<10` 最多两位小数，`10～99` 最多一位，`>=100` 不显示小数；使用截断而非向上舍入，避免未达到目标时提前显示为整万/整亿。
- 移除尾随零；保留负号；非有限值由调用方显示 `--`。
- 永远不使用 `W` 表示“万”。功率写作 `1.2万 kW`，其中 `kW` 是单位。
- BigInt 和十进制字符串不得先转为 `number`；科学计数法直接从十进制位数截取，确保 Lv.1000 科研成本的完整值和紧凑值都不会丢位。

### 精确值交互与布局

- 桌面悬停和键盘聚焦显示完整精确值；`title` 只能作为兜底，主路径使用可访问 tooltip。
- 手机点击数字本身打开小型精确值浮层。数字触发器必须 `stopPropagation()`，不能触发托盘拿取、排行跳转或卡片主操作。
- `aria-label` 始终包含完整值和单位。
- 数字使用 `font-variant-numeric: tabular-nums` 和稳定 `inline-size/min-inline-size`；进度、单位、按钮和图标不得因位数变化横向跳动。
- 百分比、日期、版本、ID、倒计时和普通小数速率不经过数量格式化器。

### 覆盖清单

顶部矩阵栏、桌面物资托盘、新版手机物资、光标载荷、建筑输入/输出/燃料、物流槽、制造与施工成本、科技与无限科技成本、戴森数量、统计库存/累计值、离线收益、银河出口、活动四项进度、排行榜和存档摘要必须全部审计。排行榜现有 `k/M/B` 格式改为同一中文单位规则。格式化测试额外覆盖 `Number.MAX_SAFE_INTEGER` 两侧以及四条无限科技的 Lv.500/Lv.1000 十进制成本。

### 领域命令

UI 在操作或确认时生成逐物品的精确请求数量；领域命令按 `min(请求数量, 当前真实库存)` 再限制，既避免负数，也保证最终删除量不会超过玩家确认时看到的预览。确认期间新进入托盘的物资留在托盘。所有删除数量为整数：

- 当前数量 `<2` 的物品在“删除一半”中跳过；只有当选中集合中至少有一项可删除时按钮才启用。
- 全部删除：预览时记录选中物品的当前托盘数量。
- 空请求、错误星球或零删除量返回原 state 引用。

### UI

- 桌面托盘与新版手机物资页都有“管理”入口；进入后行项目标从拿取切换为复选框，退出管理清空瞬时选择。

- 删除一半在确认前显示预计删除总数和不满足 2 件的跳过数。
- 单个物品全部删除可以直接执行；多选全部删除或任何经“全选”产生的全部删除必须二次确认。
- 确认框显示星球全名、物品种数、预计总数量和物品明细；明细过长时前 8 项加剩余项计数，但精确总量必须可见。
- 存在光标载荷时仍可管理托盘，但普通拿取动作关闭；删除命令绝不处理光标物品。

### 测试

覆盖非活动星球保护、搜索后全选全部、1/2/3 件向下取整、多选确认时库存变化、临时超额库存、活动输入、建筑/线路/在途/随身载具不变，以及经典/新版手机 200% 字体下按钮可点击。

### 粘贴算法

1. 校验目标恒星系已解锁、戴森球计划科技完成、层数 `<8`；模板包含壳面时还要求壳面科技。
2. 校验半径 `5,000～50,000`、节点不超过 24、角度间隔合法、所有框架/壳面引用闭合且不存在自连接和重复边。

5. 节点和框架 `completedStructurePoints=0`，壳面 `absorbedSails=0`；所需结构和容量按目标半径重新计算。
6. 直接追加到目标系统 `layers` 尾部并设为 active layer；目标已有层和总工程量不变。
7. 任一校验失败时返回结构化错误，state 和 `nextId` 均不改变。

### 先测量后修改

在优化前给模拟基准增加可选 profiler，分别记录：

- `copyState`；
- 站点索引构建；
- peer 匹配；
- 星际路径和路线经济计算；
- 派遣；
- 路线推进；

基准工厂分别包含 10、50、100、500 座塔，混合行星/星际、5 槽、多物品、两端载具、中转、翘曲和空闲载具。每档预热 3 次、测量至少 10 次，记录中位数、P95、peer 扫描次数、路线经济调用次数、创建路线数和最终状态哈希。不得先写一个毫秒目标再伪造达标；先保存同机同构建基线。

### 运行时索引

在 `SimulationAdvanceSession` 内创建不持久化的 `SimulationLookupContext`：

- `entityById`；
- 按星球和恒星系的站点集合；
- 按 `scope + location + itemId + supply/demand` 的槽位索引；
- 按载具所属塔的忙碌数；
- 按供给塔/物品的已预留出货；
- 按需求塔/物品的在途数量；
- 路线 topology/economics 缓存。

`findStationSlotPeer()` 改为从物品和模式索引取候选，排序规则仍保持路线可达、槽优先级、时长和稳定 ID 顺序。相同供需、物品、owner 和路径的路线允许合并为一个 `vehicleCount > 1` 的批量路线；取消、返航和翘曲退款仍按总载具数准确结算。

### 验收标准

- 优化前后所有物流单元 fixture 和确定性哈希一致。

- 将每塔载具从 0 增到满载但保持全部闲置时，核心循环次数不能与载具数量线性增长。
- 10/50/100/500 档都记录内存、路线数和状态复制耗时；缓存不进入保存 payload。

## 15. 递归制造允许临时超过托盘上限（P1）

### 建筑制造中心

- 每个 `ConstructionAutomationJob` 持久化自己的 `inventory`。材料步骤优先从 job inventory 消耗，不足部分再从所在星球托盘原子扣除；所有中间产物和副产物先写入 job inventory，不受托盘上限阻断。
- 任务规划和实际执行使用相同库存顺序，不能出现规划认为可完成、执行却因副产物满仓卡在 100%。
- 最终建筑步骤前先模拟：扣除建筑材料后剩余的 job inventory 是不可继续使用的副产物。确认安全保护允许后，再一次性扣料、把副产物写入当前星球托盘、增加施工库存并结束任务。
- 副产物写托盘属于保护性返还，可形成临时超额；普通机器、物流和配送枢纽仍受托盘上限限制。
- 如果任务在制品总数会超过 `1,000,000`，或某副产物会让托盘超过“该星球单物品上限 + 1,000,000”，整步不执行，保留所有输入并显示物品、当前值、预计值和保护上限。
- 已经高于保护值的迁移库存不删除；只禁止任何让该物品继续增加的递归步骤，允许能降低或不增加该物品的任务继续。

### 绿色小锤子及其他规划器

`craftConstructionWithUpstream()` 已经使用临时规划库存原子替换托盘，继续保留该结构，但在提交前应用同一副产物安全检查。失败时计划返回 `safety-limit` 和具体物品，不修改托盘、总产量或施工库存。普通直接手搓不绕过托盘规则。

### 测试

- 钛合金相关链在精炼油/氢托盘已满时完成目标，不停在 100%。
- 中间产物被后续步骤从 WIP 消耗，不重复从托盘扣除。
- 多输出配方、多个制造中心、暂停/恢复、断电、目标取消、中心回收、保存加载和 30 天离线。
- v32 正在进行的任务迁移后继续完成；原托盘、stepIndex 和 elapsedSeconds 不变。
- 安全阈值前一件可完成、下一件原子阻断；没有负数、删除或重复产出。

- 矩阵压缩、矿脉极限利用、银河物流协议、恒星能量驯化：最高可研究和最高有效等级均为 Lv.1000。

- 各科技根据实际收益采用 4.5%～5.2% 的小幅差异；差异使用整数千分比，不能依赖浮点指数。

| 科技 | 每级倍率 | 整数比 | 最高级 | 设计理由 |
| --- | ---: | ---: | ---: | --- |
| 矩阵压缩 | ×1.051 | 1051/1000 | 1000 | 同时提高科研和全部普通生产，成本略高于基准。 |
| 矿脉极限利用 | ×1.048 | 1048/1000 | 1000 | 只强化固体采矿，增长最低。 |

| 连续体演算 | ×1.045 | 1045/1000 | 23 | 等级短且效果在 30 天封顶，保持较低增长。 |

对目标等级 `L`：

```text
cost(1..10) = 当前正式数值
cost(L) = roundToNearest10(cost(L - 1) * numerator / 1000), 11 <= L <= maxLevel
```

连续体演算 Lv.23 的新成本为 `80,330`，达到后离线额度为 30 天。

### 大整数存储与结算

Lv.1000 成本远高于 `Number.MAX_SAFE_INTEGER`。无限科研当前级投入改为规范十进制字符串持久化，运行时用 BigInt 运算：

- JSON 中只保存无符号、无前导零、非指数形式的十进制字符串；零固定为 `"0"`。
- 研究站输入缓存仍是安全范围内的普通整数。每次实际消费后把消费量转成 BigInt，再加到 progress。
- 剩余成本、完成判定和跨级结转全部使用 BigInt；任何路径都不能把完整成本转成 number。
- 进度条使用整数基点，例如 `progress * 10_000 / cost`，再转换为 0～100%；不直接做超大数浮点除法。
- `remainingResearchCosts()` 只向模拟暴露当前输入缓存可消费的安全 number 分块，精确剩余值由大整数 helper 提供给 UI。
- 云校验只接受最多 64 位的规范字符串。当前 Lv.1000 最大成本不足 30 位，保留余量但防止恶意超长 payload。

### 投入结转

- 原等级记录永不丢失；上限内继续写入 `level`，超过新上限的部分写入 `historicalLevel`，实际倍率只读取有效 `level`。
- v32 的 number progress 当前受 20 亿上限约束，可先 `floor` 后精确转换为 BigInt 十进制字符串，不损失已有投入。
- 对当前级 progress 使用新成本循环结转：只要投入大于等于新成本，就扣除成本、等级加一并按正常公式增加银河评分；剩余投入进入下一等级，直到投入不足或达到等级上限。
- 结转使用 BigInt、稳定科技顺序和最多 1,000 次的明确循环上限；迁移重复运行不再次加级或加分。
- 四条长期科技旧档 `level > 1000`、连续体旧档 `level > 23` 都把原等级转存为 `historicalLevel` 并保留 progress；有效 `level` 分别限制到 1000/23，不再允许续研。UI 同时显示历史等级和有效上限。
- 离线科研、自动续研、排行榜摘要和银河评分必须覆盖结转后的状态；迁移前后宇宙矩阵总投入守恒。

### 17.4 活动配置与服务器时间

服务端新增只读活动配置模块，并扩展 `/api/public-status`。生产默认 `enabled=false`；配置缺失或非法时保持关闭并在健康诊断说明原因。

建议使用一份 JSON 配置而不是散落常量：

```json
{
  "id": "union-station-2026-01",
  "enabled": false,
  "startsAt": "2026-01-01T00:00:00.000Z",
  "endsAt": "2026-01-04T00:00:00.000Z",
  "personalTargets": {
    "universe_matrix": 1000000,
    "solar_sail": 1000000,
    "small_carrier_rocket": 1000000,
    "antimatter_fuel_rod": 1000000
  },
  "globalTargets": {
    "universe_matrix": 0,
    "solar_sail": 0,
    "small_carrier_rocket": 0,
    "antimatter_fuel_rod": 0
  }
}
```

示例中的全服 `0` 是无效占位，不能启动活动。正式全服目标必须由运营配置为正整数，代码仓库不提供线上默认值；测试可注入每项 1,000,000 的临时 fixture。

配置加载器还必须强制 `endsAt - startsAt = 259,200,000 ms`，并要求本活动四项个人目标都严格等于 `1,000,000`。任一物资缺失、重复、非整数、非正数或时间不合法时整项活动保持关闭，不能部分采用配置。

公开响应包含 `serverNow`、配置修订、开始/结束时间、四项目标、四项模拟累计和状态 `scheduled/active/ended`。客户端成功获取后建立 `serverNow - Date.now()` 的运行时偏移，用它持续渲染倒计时；该偏移不直接进入模拟。`GameState` 另存一个只由服务器校准的 `activityClockMs`，每个确定性模拟步显式推进：

```text
stepStartMs = state.activityClockMs
stepEndMs   = stepStartMs + simulatedSeconds * 1000
activeMs    = overlap([stepStartMs, stepEndMs], [startsAtMs, endsAtMs])
state.activityClockMs = stepEndMs
```

开始前台或离线推进前，用最新服务器时间对 `activityClockMs` 做单调向前校准，绝不向后回拨。暂停游戏时模拟和个人投入停止，但 UI 倒计时继续使用运行时服务器偏移；恢复前先校准活动时钟，不能通过暂停延长活动。未暂停旧档的离线秒数按保存时活动时钟逐步推进并在截止边界停止计入，Worker 请求显式携带同一时钟上下文。首次从未取得有效配置时不消费活动物资，只显示“等待服务器时间”；不能在模拟函数内部读取浏览器墙上时钟。

### 17.5 模拟全服进度

四项不读取实际个人交付。时间归一化：

```text
u = clamp((serverNow - startsAt) / (endsAt - startsAt), 0, 1)
```

默认完成时点和结束倍率：

| 物资 | 达到 100% 的活动时点 | 结束累计 |
| --- | ---: | ---: |
| 宇宙矩阵 | 82% | 118% |
| 太阳帆 | 86% | 114% |
| 小型运载火箭 | 90% | 110% |
| 反物质燃料棒 | 94% | 106% |

为了产生波动但保证单调，使用正速率积分曲线：

```text
rate(x) = 1
        + 0.24 * sin(2π * (3x + phaseA))
        + 0.10 * sin(2π * (7x + phaseB))
```

最小速率为 `0.66`，不会倒退。phase 由 `SHA-256(activityId + itemId)` 确定；对 `rate` 从 0 到 x 积分并归一到 `[0,1]`。达到各自完成时点前映射到 `0～100%`，之后用同一类曲线映射到最终超额倍率。累计值使用 `floor(target * progress)`，相同活动 ID 和服务器时间在任一节点得到相同结果。

总体展示为四项各自 `min(delivered/target, 1)` 的平均值；只有四项都达到目标才标记建设成功。活动结束后用 `endsAt` 冻结值，不再随请求继续增加。

### 17.6 本地个人进度与待确认批次

- 新活动 ID 首次激活时个人四项从 0 开始，旧银河出口累计绝不计入。
- 首次加入时在模拟外使用 `crypto.randomUUID()` 生成并持久化 `participantId`；批次 ID 由 `activityId + participantId + itemId + sequence` 组成。存档复制仍可能复制该 ID，账号级去重按本批延期处理。
- 每次实体出口转换产生或合并一个本地 pending batch；物资扣除、项目交付、个人累计和批次增加在一次 state copy 中提交，任何异常都返回原 state。
- 断网后配置快照和可信时间锚仍可继续确定性推进，待确认量随存档、手动槽、导入导出和云存档保存。

- 无账号也能完成本地任务。跨存档、回滚、复制槽位和账号级去重留到奖励服务阶段；当前 UI 不承诺免费建筑资格。
