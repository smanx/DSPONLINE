## 3. 已实现范围

### 核心玩法

- 不使用机甲角色，鼠标或触摸指针承担采矿、拿取、拖放、建造和跨星球托运。
- 以 React Flow 为无限画布，支持节点移动、框选、批量操作、蓝图、线路编辑、小地图、画布书签和持久化生产区域标记；区域可命名并设置背景色与边框色，不参与生产模拟。
- 采矿、熔炼、制造、化工、科研、电力、行星物流、星际物流、戴森云、戴森球和银河终局形成完整流程。
- 六色矩阵、科研队列、五条无限科研、四类银河出口项目和八章战役任务已经落地。
- 当前工作区包含 8 个恒星系、22 颗行星和 16 种行星生态模板。一次性新建种子确定恒星参数、星区坐标、生态、普通与稀有矿、海洋、潮汐锁定、矿储、风光地热、轨道产率、航程、设备专长和殖民成本；加载存档不会重新抽取。
- v29 固定为澜渊 II、赤砂 I、牧云 II 保留原油，其中赤砂为高储量、牧云为中等储量；风暴 I 仍由种子概率决定。v28→v29 只在对应资源不存在时补充确定性油井，不覆盖旧油井、矿储、建筑或线路。
- 恒星亮度真实进入太阳能、各恒星系独立戴森云/戴森球功率和射线接收；跨恒星物流支持直达、优先中转、强制中转、中转枢纽优先级、1-4 个/船翘曲预算及按二维星区坐标计算的多跳航程。
- 生产库存对玩家使用整数结算，设备内部保留不可见的周期进度。
- 内容目录当前包含 78 个物品、78 条配方、32 类建筑、61 项科技、13 项成就和 32 个战役任务。

### 操作与分析

- 线路采用直接传送带连接，支持多输入、多槽物流站、自动物品/配方匹配、连接预览、吞吐预测和成功/失败反馈。默认会锁定施工托盘中已解锁且有库存的最高等级，耗尽后自动降级；已有并行线优先复用原等级，也可手动指定 Mk.I/Mk.II/Mk.III。
- 四向分流器的优先模式按高（2）→标准（1）→低（0）逐级分配，同级线路轮流均分，只有高等级线路堵塞或达到吞吐上限后才向下一等级回退。
- 生产统计、网络诊断、跨星球物流诊断、工业规划、效率曲线、挂机压力测试和自动性能报告均有界面入口。
- 统计中心新增统一的全星球生产管理视图：按行星、设备族、物品和运行状态筛选设备，汇总各行星节点、产能与效率；缺料可沿输入线追踪到上游设备和原矿来源，堵塞可定位输出线与下游缓存，问题行可以直接跳转到对应设备或连续网络。
- 生产管理结果集支持跨行星批量改配方和批量套用指定物流槽模板；只修改兼容设备或站点，保留未指定槽位，并将被替换的缓存退回设备所在行星。目标物品可以直接生成完整产量反推方案。
- 配方图鉴支持搜索、正反查、聚焦配方以及完整链和两层链展示。
- 施工托盘支持两行精简模式、批量扩建和 Ctrl 固定 `+1` 连续扩建；检查器可快速增加单台设备。
- 新工厂在母星物资托盘获得铁矿石、铜矿石和石矿各 100；以后每项科技首次完成时，其直接解锁的普通建筑各赠送 2 个，建筑制造中心等巨构明确排除。旧存档迁移不会补发开局矿物或重复科技奖励。
- 施工托盘小锤子可递归使用已解锁的手工配方补齐上游材料，完整规划成功后才原子扣料并短暂显示实际消耗；灰色锤子仍是可操作按钮，单击会定位第一个当前可手搓的上游材料，或明确报告缺科技、缺原矿和无手工配方，不再使用双击。
- 基础制造搜索工具固定置顶，建筑制造与物品手工分别保留最近 3 条搜索；建筑制造和物品手工中的可手搓缺料都能直达对应配方；自动整理支持独立的一步位置撤销。
- 紫糖阶段的建筑制造中心可按目标库存自动从所在行星托盘制造建筑，绿糖和白糖科技提高上限与速度；画布使用真实约 2× 宽高、独立巨构边框、等级、状态和制造阵列效果，端口坐标不依赖 CSS 缩放。黄糖阶段的三输入物资配送枢纽会把线路送达物品直接转入所在行星托盘。
- 矿脉、原油涌泉和海洋节点上的采集设备可按指定数量或全部回收；资源节点、剩余矿储、输出缓存、线路及线路货物保持不变，设备返还施工托盘。
- 闲置物流运输机和运输船使用全局随身载具库存，显示在底部施工托盘，可随玩家跨星球并从任意兼容物流站装卸；旧行星托盘中的闲置载具会无损迁移。
- 每颗行星独立保存单种物资托盘上限，可在 1,000 至 1,000,000 间设置。降低上限不会删除已有超额库存；满仓后的光标、设备和配送枢纽余量会留在来源处，手搓与任务奖励也不会先扣料或吞掉产物。
- 已堆叠普通建筑可逐台 `-1` 回收；星际物流站可从所在行星托盘自动补充翘曲器；新建到物资配送枢纽的输入线默认低优先级；生产区域支持四边和四角缩放，手机与画布缩放下均保持可操作。
- `0.5.0`（2026.07.23）版本公告首次进入时展示一次，并可从主菜单设置或游戏内设置重复查看；已读状态与游戏存档相互独立。
- 渐进教学包含从手动采矿到蓝糖、石油红糖、黄糖、星际物流、戴森云、临界光子和白糖的 13 个里程碑；已有目标设备或零流量输入线会显示停机原因并可直接定位。
- 桌面和手机横竖屏均有专用布局与抽屉；手机支持单指平移、双指缩放、56px 合法端口吸附、长按快捷菜单、逐点多选，并在横竖屏切换时保持世界中心、缩放、选择和面板状态。第二根手指可从建筑或线路上接管画布，并取消第一指尚未提交的拖动、连线、采矿、放置和长按。
- 所有粗指针设备默认关闭常驻节点/线路动画、粒子和重阴影；低内存、低核心或持续低帧率设备进一步降低模拟与画布发布频率、启用可见节点渲染和紧凑 LOD，并默认折叠小地图。模拟仍累计真实经过时间，不改变产量或存档规则。
- 内容包支持校验、依赖、启停、运行时注册和存档使用保护；蓝图支持 JSON 导入导出。

### 存档与在线服务

- 当前工作区与线上 `GameState` 均为 v30；存档封装格式保持 v2，加载器可将 v1-v30 归一到 v30。v28→v29 增加确定性外星系原油并把旧 2/10 秒自动保存偏好归一为 30 秒；v29→v30 增加星际站翘曲器自动补充配置。旧库存、实体、线路、科研投入、蓝图、在途路线、行星档案、旧油井和戴森计划均保留。
- 自动保存选项为 30/60/120 秒，默认 30 秒；切后台、`pagehide`、卸载和返回主菜单会立即保存。手机端存档摘要扫描降至 30 秒，全屏工作区或网页后台期间冻结底层画布快照更新。
- 本地主存档、槽位和快照不再持久化 `productionHistory`，内存统计曲线仍照常运行并在刷新后重新积累。主存档先写入、读回并校验，成功后才通知界面；配额异常只会清理自动快照并重试一次，最终失败会持续提示玩家立即导出。
- 本地主存档有校验和和上一份有效备份；自动快照最多 2 份、至少相隔 5 分钟，手动快照和 3 个手动槽位不会被自动清理。手动槽位与快照删除均要求连续两次确认并显示目标摘要。
- 离线模拟默认最多 7 天，可由终局研究逐级提高到 30 天。
- 当前工作区和线上云服务均为 schema v6，提供邮箱验证、旧账号邮箱绑定、忘记/重置/修改密码、30 天设备会话及撤销、账号数据导出与注销；v3/v4 旧账号迁移后保持已验证状态。
- 新账号验证邮箱后才能写入云存档或排行榜；正式代码支持腾讯云 SES 审核模板 API，并保留通用 webhook 作为回退。前端从健康接口读取邮件能力：发送器未启用时，注册、邮箱绑定、重发验证和找回密码会标注“正在开发中”，现有账号登录、四槽云存档及已验证账号的自动同步不受影响。缺少完整 API 凭据或模板 ID 时不会伪装发送成功，线上邮件发送器仍未启用。
- 本地身份可以显式绑定或解除云账号，绑定元数据与 `GameState` 分离，不会改写本地工厂。
- 玩家进入工厂后发送匿名心跳；服务端只保存本机匿名 ID 的 SHA-256 哈希，并按节点统计累计、今日和最近 120 秒在线玩家。运营中心每 30 秒刷新这些聚合数据。
- 浏览器会按隐私分桶上报页面加载、LCP 和静态传输体积；运营后台显示 P75 档位，不保存原始时序、完整 URL 或玩家存档内容。
- 账号、改密、会话撤销、数据导出、注销和云修订恢复写入隐私最小化安全审计，只保留动作、时间、匿名化账号/IP 和客户端类别。
- 云端为每名玩家保存互不覆盖的主存档和手动槽位 1/2/3，各自维护修订、历史和冲突状态；手动云槽与本地手动槽一一对应，不会替换正在游玩的主工厂。邮箱验证后，主存档每 10 分钟检查并自动上传；失败只记录状态，不影响本地保存，检测到双端变化时会暂停并要求玩家选择。排行榜仍只校验主存档。
- 服务端生产存储为 SQLite，每 6 小时备份一次，部署配置保留最多 30 份。

## 6. 已知风险与技术债

### P0：发布与数据安全

- 云服务仍是单进程、单 SQLite 文件架构；认证加密异地备份和恢复演练已经形成首个闭环，但仍需持续检查 timer、30 天密文保留期和每月恢复报告。
- 腾讯云发信域名与地址已经完成验证，正式代码已支持 SES API；正式环境仍缺少完整的审核模板 ID 和最小权限 CAM 凭据，因此新注册和邮件找回仍会返回 `503 EMAIL_SERVICE_UNAVAILABLE`。已有已验证账号的登录与四槽云存档不受影响。
- 账号系统已有设备会话撤销，但尚未实现异常地点检测、登录告警和后台人工账号处置。
- 排行榜校验属于“云存档关联 + 指标约束”，不是服务端权威模拟，不能抵御有针对性的作弊。
- 上海入口是 HTTP，代码已禁止云登录；不能为了兼容旧地址而放开明文凭据传输。

### P1：性能与运维

- 两个节点已对 JS/CSS 启用 gzip，hashed asset 保持 immutable；Brotli、真实用户一周趋势和更细的资源预算仍可继续补充。
- `src/styles.css`、`src/game/engine.ts`、`tests/e2e/game-flow.spec.ts` 和 `src/App.tsx` 已经成为超大文件，修改冲突和回归成本较高。
- Web/服务端已有可复现清单、原子切换、健康检查和固定路径回滚工具，但仍缺少从提交到双节点灰度发布的 CI 流水线。
- 节点探针已覆盖外部可用性、API、磁盘和 TLS，管理员后台能读取状态；可选告警 webhook 与集中日志仍未配置。上海磁盘在 `0.5.0` 验收时约剩 6.7 GiB（文件系统使用率约 89%），需要优先观察发布目录、日志和备份增长。
- 当前环境没有连接 Android 或 iPhone 真机，也没有 ADB 工具；`0.5.0` 已完成 Chrome 触摸仿真、正式域名横竖屏烟测和玩家本地验收，但仍缺少 Android Chrome 与 iPhone Safari 各连续 30 分钟的耗电、温度和真机帧率记录，不能用桌面模拟结果冒充。

### P1：产品与合规

- 当前物品、配方、科技和流程以《戴森球计划》高还原原型为目标。公开推广或商业化前，应做名称、美术、文案、数值和世界观的原创化审查，并取得专业法律意见。
- 当前是公开测试版，不应把“功能很多”误认为“生产运营成熟”。隐私政策、用户协议、数据删除流程和公开反馈机制仍需补齐。

### 明确不在当前范围

- 黑雾或战斗系统暂不开发。
- 原创玩法扩展应排在稳定性、数据保护和发布工程之后。
