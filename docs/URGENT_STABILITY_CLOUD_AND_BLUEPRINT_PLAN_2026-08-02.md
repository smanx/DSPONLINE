### 1.1 已记录的用户证据

- 云存档：多个终局存档触发“云存档格式无效或体积过大”，代码核验确认入口请求体上限为 `8 * 1024 * 1024` 字节。
- 浏览器崩溃：极限存档约 2,906 个实体、6,340 条传送带、464 座物流站，存档正文约 5.5 MiB。
- F12 补充：出现 React `#185 Maximum update depth exceeded`，堆栈进入 React Flow `setEdges`；Service Worker 同时反复报告 `Response body is already used`。
- 蓝图界面截图：2048x1080 亮色模式下同时显示四列完整卡片。卡片的旋转和镜像区域占据主体高度，配方、需求与底部操作继续向下延伸，底部施工托盘进一步遮挡有效区域，首屏难以找到部署入口。
- 巨构蓝图截图：来源微型黑洞连接装置处于“销毁通道运行中 · 3/3”，但通过蓝图部署的新装置固定为暂停状态，需要玩家逐台再次确认和启动。

## 2. U-03 今日必须修复：蓝图默认精简界面

### 2.1 问题根因

当前 `BlueprintWorkspace` 会让每张蓝图卡片同时渲染以下内容：

1. 名称和设备/线路摘要。
2. 全部建筑构成标签。
3. 矿脉唯一性说明。
4. 0/90/180/270 度旋转控制。
5. 水平镜像控制。
6. 所有配方覆盖下拉框。
7. 所有外部接口。
8. 完整施工需求和物流载具目标。
9. 导出、部署和删除操作。

这些功能本身都需要保留，但不应在蓝图库列表中的每一张卡片上同时展开。问题属于信息架构和响应式布局缺陷，不是简单缩小字号就能解决。

### 2.2 默认精简模式

- [ ] 蓝图工作区标题栏增加“精简 / 详细”分段控制，使用现有 Lucide 图标并提供工具提示。
- [ ] 没有历史偏好的设备第一次打开时默认选择“精简”。偏好只保存在设备级 UI 设置中，不进入 `GameState`、蓝图文件或云存档。
- [ ] 精简卡片保持稳定高度，桌面目标约 `150-190px`；卡片内容变化不得让同一行其他卡片跳动。
- [ ] 卡片首行只显示蓝图名称、设备/资源锚点/线路数量以及兼容状态。
- [ ] 建筑构成只显示前 2-3 项，其余显示为“+N”；悬停或打开详情后查看完整列表。
- [ ] 用一行状态摘要显示“可直接部署”“缺少建筑”“行星不兼容”或“包含矿脉锚点”，不常驻展开整段矿脉说明。
- [ ] 卡片底部固定显示主操作“部署/排队部署”，无需在卡片内部滚动即可点击。
- [ ] 导出、删除和打开详情使用图标按钮；删除仍需二次确认，图标必须有标题和无障碍名称。
- [ ] 精简列表不常驻显示四向旋转、镜像、配方参数、外部接口、逐项施工需求和载具目标。

### 2.3 详细模式与单项详情

- [ ] 点击卡片、详情按钮或切换详细模式后，打开单个蓝图详情，而不是同时展开全部卡片。
- [ ] 桌面优先使用独立右侧详情栏或覆盖式详情面板；手机继续复用现有“列表 -> 详情”路由。
- [ ] 详情中保留重命名、旋转、镜像、配方覆盖、外部接口、施工需求、载具目标、导出、部署和删除的完整功能。
- [ ] 同一时间最多展示一个蓝图详情，避免 19 张蓝图同时产生大量下拉框、按钮和布局测量。
- [ ] 关闭详情后恢复原列表滚动位置、筛选状态和精简/详细偏好。
- [ ] 切换蓝图方向或配方后，列表摘要和详情立即同步，不创建两套互相覆盖的状态。

### 2.4 响应式布局要求

- [ ] 1920x1080、2048x1080 和 2560x1440 下可自动显示 3-5 列精简卡片；主操作保持完整可读。
- [ ] 1366x768 下至少能完整看到一行蓝图卡片及其部署按钮，工作区内容不能进入底部施工托盘命中区域。
- [ ] 768-1279px 使用 2-3 列或紧凑列表；不足以容纳按钮时换行，禁止文字相互覆盖。
- [ ] 新版手机保持单列列表和独立详情页，所有主要点击目标不小于 44px。
- [ ] 覆盖 80%、100%、125%、150% 和 200% 字体倍率；200% 时允许退化为单列，但不能隐藏部署和关闭按钮。
- [ ] 蓝图工作区自己负责纵向滚动，页面主体和底部施工托盘不得同时抢夺滚轮或触摸滚动。
- [ ] 亮色和深色模式均需验证选中态、禁用态、缺料态、危险操作和文字对比度。

### 2.5 行为边界

- [ ] 本次只修改展示和设备级偏好，不改变蓝图 v2 格式、蓝图 revision、部署成本、施工订单或库存扣除规则。
- [ ] 点击部署后必须关闭或收起蓝图工作区，回到当前行星画布并进入蓝图放置状态；不能因为视图模式改变丢失旋转、镜像或配方覆盖。
- [ ] “部署”和“排队部署”的现有兼容性判断保持一致；精简模式不能绕过行星限制、唯一建筑、矿脉匹配或科技门槛。
- [ ] 导入面板按需展开，关闭后不永久占用蓝图库首屏高度。
- [ ] 卡片键盘焦点顺序固定为名称/详情、主部署、导出、删除；详情关闭后焦点返回原卡片。

### 2.6 今日完成定义

- [ ] 默认精简模式可以在全新设备偏好下稳定复现。
- [ ] 截图中的 2048x1080 场景打开蓝图库后，每张首屏卡片都能直接看到部署或排队部署按钮。
- [ ] 19 张蓝图、0 张蓝图、单张超大蓝图、包含矿脉锚点、多个配方覆盖和多个外部端口均不溢出。
- [ ] 精简/详细切换不修改蓝图内容；保存、刷新、导出和重新导入后蓝图数据完全一致。
- [ ] 完成类型检查、生产构建、蓝图聚焦 E2E，以及桌面 1366x768、2048x1080、手机竖屏、手机横屏和 200% 字体截图核验。

## 3. U-01 云存档超过 8 MiB

### 3.1 短期恢复方案

- [ ] 将应用服务器、Nginx、桌面桥接和测试环境的云存档请求边界统一提高，建议第一阶段接受最多 32 MiB 的单个原始请求。
- [ ] 客户端上传前显示原始字节数和服务端允许值；超过限制时不得发起必然失败的请求。
- [ ] 服务端继续区分格式无效、完整性失败、压缩失败、解压后过大和账号配额不足，禁止统一显示“存档损坏”。
- [ ] 大请求仍受登录、路径级频率限制和单账号并发限制；同一账号同一时刻只允许一个云存档正文写入。
- [ ] 数据库写入必须使用临时修订、完整校验和事务提交，失败时保留上一份可用云档。

短期目标是让当前 8-20 MiB 的真实存档恢复上传能力。只提高限制不能一劳永逸，也不能解决未来实体数量持续增长。

### 3.2 长期压缩传输与存储

- [ ] 定义独立于 save envelope 的云传输包装格式，记录压缩算法、原始字节数、压缩字节数和原始正文校验和。
- [ ] 优先评估 gzip；典型 JSON 预计压缩 `70%-90%`，上传时间预计下降 `60%-85%`，具体比例必须用真实终局存档测量。
- [ ] 服务端限制“压缩体积”和“解压后体积”，流式解压并拒绝压缩炸弹；不得先无上限解压到内存。
- [ ] 服务器保存压缩正文或分块正文时，云历史、冲突比较、排行榜摘要、导出和恢复必须继续读取同一份已验证状态。
- [ ] 老客户端仍可上传未压缩 envelope v2；新客户端能够读取旧云档。传输格式升级不应强迫升级 `GameState.version`。
- [ ] 设置单槽、单账号全部修订和服务器总容量告警；达到配额时只清理超出保留策略的旧历史，不得删除当前主档或手动槽位。

### 3.3 云存档验收

- [ ] 覆盖 7.9 MiB、8.1 MiB、16 MiB、31.9 MiB 和超出新限制的固定夹具。
- [ ] 覆盖普通正文、压缩正文、截断正文、错误校验和、伪造原始尺寸和高压缩比攻击输入。
- [ ] 本地导出、手动导入、网页上传、Windows 上传、Android 上传及跨端下载的状态哈希一致。
- [ ] 上传中断、服务器重启、数据库繁忙和客户端重复提交不会覆盖上一份有效云档。
- [ ] 发布前创建并验证生产 SQLite 备份；香港和上海节点分别检查请求限制，不允许只修改其中一层。

## 4. U-02 极限存档崩溃与终局性能治理

### 4.1 已确认的性能证据

- Edge 70 秒内，强制 GC 后 JS 堆由约 `29.7 MiB` 增至 `502.8 MiB`。
- Edge 总工作集由约 `644 MiB` 增至 `1.44 GiB`。
- 每秒出现多次 `250-330ms` 主线程长任务；30/60 秒自动保存产生约 `2.0-2.1s` 阻塞。
- Chrome 147 同样持续增长，说明根因属于应用；Edge 在该样本上慢约 `30%-45%`。
- 极简 Worker 连续传输同一份 5.5 MiB 状态 70 次，强制 GC 后增长为 0，排除浏览器 `postMessage` 自身固定泄漏。
- 将完整 UI 状态发布从每秒一次降低为每五秒一次，35 秒净增长由约 `258 MiB` 降至 `54.9 MiB`，内存压力下降约 `79%`。
- 临时禁用全局传送带观测，35 秒净增长由约 `258 MiB` 降至 `177 MiB`，内存压力下降约 `31%`。

堆采样的主要来源：Worker 全量 `GameState` 约 148 MiB、传送带观测复制约 76 MiB、节点/线路视觉签名字符串约 15 MiB、存档缓存字符串约 10.6 MiB。以上是诊断样本，不代表每台设备的固定占用。

### 4.2 玩家设置：终局优化·极限模式

#### 产品定位

- [ ] 在“设置 -> 运行设置”增加独立总开关，名称固定为“终局优化·极限模式”。
- [ ] 副标题明确写为“牺牲动画、装饰与非关键实时刷新，保持模拟结果不变”，不得只写含糊的“提高性能”。
- [ ] 该开关是设备级偏好，建议使用独立本地键 `dsp-idle-network.endgame-extreme.v1`；不进入 `GameState`、本地/云存档、蓝图、排行榜或跨设备同步。
- [ ] 现有“性能模式”“减少动态效果”和“生产画面刷新频率”继续保留。极限模式开启时只在运行时覆盖它们的有效结果，不改写玩家原来的选项；关闭后自动恢复玩家原设置。
- [ ] 第一次开启时显示一次简短确认，逐项列出牺牲内容；以后使用普通切换开关，不反复弹窗。
- [ ] 开启期间在顶栏或性能状态区显示小型仪表图标和“极限模式”工具提示，避免玩家忘记自己为何看不到动画。
- [ ] 复用当前性能报告的推荐逻辑，在大型工厂持续低帧率时提示玩家开启，但不得未经同意自动开启。

建议首次开启说明：

> 开启后会把非关键画面刷新降低到约每 5 秒一次，关闭线路货物流动、粒子、阴影和装饰过渡，只实时观测可见或选中的线路，并更早使用精简建筑外观。生产、物流、科研、耗电、时间、库存和存档结果不会改变。

#### 应纳入总开关的体验降级

| 功能 | 极限模式行为 | 用户牺牲 | 必须保留 |
| --- | --- | --- | --- |
| 非关键状态发布 | 最长每 5 秒刷新一次 | 普通库存、供电和统计数字不再逐秒跳动 | 玩家操作结果、选中对象、错误提示和保存状态即时更新 |
| 传送带表现 | 关闭货物流动、粒子、发光、阴影和持续动画 | 线路看起来静止、装饰感降低 | 线路颜色、方向、选中、高亮、堵塞和连接预览 |
| 线路流量观测 | 只采样视口内、选中或开启监测的线路 | 视口外线路没有实时流量读数 | 打开详情或定位后立即开始采样 |
| 建筑细节等级 | 更早进入 `medium/compact`，低缩放隐藏次要文字 | 远景建筑信息更少 | 放大或选中后显示完整状态和操作 |
| 统计与告警展示 | 未打开面板时只维护摘要；打开后按 5-10 秒刷新 | 大列表不再连续变化 | 警报数量、严重故障和玩家主动刷新 |
| 全屏工作区 | 打开科技、蓝图、统计等工作区时冻结底层画布 | 背景工厂不再继续播放动画 | 模拟本身照常运行，关闭工作区后追上最新快照 |
| 装饰动效 | 关闭非必要过渡、扫描光效和呼吸动画 | 页面切换更直接，视觉表现简化 | 焦点、按下、加载、危险和成功反馈 |

#### 不应由该开关控制的项目

以下内容没有必要放入玩家开关，或者放入后会制造数据风险：

- **必须对所有玩家生效的 Bug 修复**：React 更新循环、Service Worker clone 时序、缓存无上限增长和无变化重复提交。
- **必须对所有玩家生效的无损优化**：稳定对象引用、当前行星索引、后台保存、状态增量协议、相同结果的闭式批量计算和验证通过后的 Canvas/WebGL 渲染后端。
- **不得改变的正确性规则**：模拟时间、生产倍率、物流吞吐、电力、科研、戴森工程、量子库存、建筑制造、离线收益和物资守恒。
- **不得关闭的安全能力**：自动保存、存档校验、急救镜像、云冲突保护和错误报告。极限模式不能通过延长或关闭自动保存换取流畅。
- **不相关的服务器能力**：云存档 8 MiB 边界、压缩传输、账号配额和服务器备份。
- **不适合作为普通玩家选项的实验架构**：Worker 数量、线程分区、状态协议版本、隐藏星球结算算法和调试 profiler。多核应自动选择或使用开发者开关，不能让玩家承担确定性风险。

#### 极限模式验收

- [ ] 开启和关闭不修改 `GameState` 序列化结果；相同初始状态和模拟秒数的状态哈希完全一致。
- [ ] 开启后普通画面发布间隔稳定接近 5 秒，但放置建筑、连接线路、修改配方、暂停和保存反馈不得等待 5 秒。
- [ ] 关闭后恢复开启前的刷新档位、性能模式和减少动态效果设置，不留下强制覆盖。
- [ ] 极限模式在 Edge、Chrome、Electron、Android WebView 和新版手机 UI 均可识别；手机横竖屏切换不丢失设备偏好。
- [ ] 设置说明、首次确认和常驻状态标记都明确表达“牺牲视觉，不改变模拟”。

### 4.3 P0 紧急止血

- [ ] 修复 Service Worker `response.clone()` 时序：必须在响应正文可能被消费前同步取得克隆，再异步写缓存。
- [ ] 为 React Flow 节点测量、线路派生和 `setEdges` 增加同帧合并、内容相等短路和更新深度保护。
- [ ] 增加大工厂极限性能档：完整画面状态最长每 5 秒发布一次；玩家命令、选中对象、错误和保存状态仍即时确认。
- [ ] 关闭视口外线路动画、粒子、阴影和全局实时观测，保留选中线路与连接预览。

预期：整体主线程压力下降 `60%-85%`，内存分配压力下降 `75%-85%`，稳定运行时间提高约 `4-10 倍`。代价是普通库存数字和线路动画最多延迟约 5 秒；该阶段仍不能保证无限运行。

### 4.4 P1 当前行星观测轻量化

- [ ] `BeltFlowSampler` 只处理当前行星；极限模式只处理可见、选中或显式监测的线路。
- [ ] 观测结果保存为 UI 专用 `Map<id, observation>`，不得通过复制全部 `state.belts` 创建新的完整 `GameState`。
- [ ] 历史采样按视口和行星切换及时清理，并设置固定容量，禁止 UI 缓存无限增长。
- [ ] 线路诊断复用当前行星实体索引，不因鼠标移动或普通 React 重渲染重新扫描全状态。

预期：该阶段派生和分配下降 `50%-90%`，整体主线程再下降约 `15%-35%`。代价是视口外线路不再保持逐秒流量动画。

### 4.5 P2 React Flow 增量渲染

- [ ] 将建筑和线路签名拆分为拓扑 revision、运行 revision 和选择 revision，停止构造大型拼接字符串。
- [ ] 未变化节点和线路复用原对象引用；全部引用相同则继续复用原数组，不调用 `setNodes/setEdges`。
- [ ] 视口平移只更新 `viewportRef`；仅跨越 LOD 档位或移动结束时更新 React 状态。
- [ ] 对齐线、端口命中和线路几何使用空间索引；移动一个建筑只失效相邻端点与相关线路。
- [ ] 为 React `#185` 增加生产诊断计数，记录一分钟内节点测量、`setEdges` 和 `updateNodeInternals` 次数，但不上传玩家状态。

预期：移动和缩放计算下降 `40%-70%`，无关节点重渲染下降 `70%-95%`，GC 压力下降 `15%-35%`。风险是缓存失效遗漏导致界面短暂显示旧线路，因此必须保留可关闭的旧派生路径。

### 4.6 P3 保存后台化

- [ ] 在权威 Worker 内生成一致存档快照、序列化、校验并写 IndexedDB；主线程只接收完成确认和摘要。
- [ ] 自动保存使用单任务合并：保存进行中只记录最新 revision，完成后至多再保存一次。
- [ ] 状态 revision 未变化时跳过重复自动保存；云同步只在本地保存读回校验成功后排队。
- [ ] 页面关闭使用最近一次已验证急救镜像；等待中的异步保存不能覆盖更新的 revision。

预期：自动保存造成的主线程停顿下降 `90%-98%`，约 2 秒阻塞的目标是主线程低于 100ms。风险是关闭页面时后台任务尚未完成，必须通过 revision、确认握手和急救镜像防止回退或丢档。

### 4.7 P4 Worker 权威状态与增量协议

- [ ] Worker 继续持有唯一权威 `GameState`；主线程通过带单调序号的领域命令提交放置、连接、配方、库存和设置操作。
- [ ] Worker 每次返回已应用命令号、当前 revision、全局摘要、当前行星投影和变化 ID，不再每秒返回整份状态。
- [ ] 完整状态只在首次加载、导出、恢复、诊断和安全回退时传输。
- [ ] 暂停、恢复、切换星球、保存和内容包更新建立明确同步边界；旧 revision 响应不得覆盖新状态。
- [ ] 新旧协议在隐藏开关下双路径执行，使用状态哈希和物资守恒 oracle 对照后再切换默认。

预期：GC 后持续内存增长下降 `90%-98%`，主线程 CPU 下降 `70%-90%`，可用工厂规模预计提高约 `10-30 倍`。这是最高风险阶段，错误可能造成重复结算、状态回退或库存丢失，不能与其他玩法改动合并发布。

### 4.8 P5/P6 超大终局扩展

- [ ] 传送带数量达到阈值后改用 Canvas/WebGL 批量绘制；React Flow DOM 只保留可见建筑、选中线路和交互预览。
- [ ] 非当前星球只保留聚合运行摘要，切换星球时才加载详细画布投影；持久存档仍保存真实状态。
- [ ] 堆叠建筑、燃料、量子物流和隐藏星球生产优先使用闭式批量结算，禁止按物品数量逐个循环。
- [ ] 多 Worker 只在基准证明计算收益高于传输与合并成本时开启；当前 8 Worker 探针的传输合并中位数约 9.23ms，高于量子阶段约 3.12ms，不应直接上线。
- [ ] 桌面可试验 2/4 Worker；手机默认 1 Worker，避免内存、温度和耗电恶化。

Canvas/WebGL 线路层预计降低线路绘制 `60%-90%`，隐藏星球聚合预计降低对应模拟成本 `50%-90%`。牺牲是低缩放和非当前星球不再逐条显示实时货物流动；库存、生产结果和确定性不得牺牲。

## 10. U-04 巨构蓝图记忆玩家启用状态

### 10.1 与既有需求的关系

这项需求和路线图中已经记录的“蓝图记忆物流塔量子网络目标状态”属于同类问题：蓝图不仅应保存建筑类型和位置，还应保存玩家明确配置、且会影响部署后行为的目标状态。

本项是新增需求，专门处理巨构或特殊建筑的启用/停用意图。第一批固定范围为截图中的 `micro_black_hole_connector`。不得未经逐建筑审计，就把所有巨构的任意运行字段整体复制进蓝图。

### 10.2 状态语义

- [ ] 在 `BlueprintEntityTemplate` 增加可选的玩家意图字段，例如 `operationEnabledOnDeploy?: boolean`；最终命名可以按领域细分，但不能直接把完整 `FactoryEntity` 写入蓝图。
- [ ] 创建蓝图时，如果微型黑洞满足 `blackHolePaused === false && blackHoleActivationConfirmed === true`，记录“部署后自动启用”；否则记录“部署后保持停用”。
- [ ] 蓝图记录的是玩家期望状态，不是截图瞬间的临时运行状态。缺少输入、线路堵塞、无电、当前利用率、故障提示和本模拟步是否正在转运都不得进入蓝图。
- [ ] 来源巨构在蓝图创建后再暂停或启动，不反向修改已有蓝图；蓝图详情可独立显示并修改“部署后自动启用”。修改后增加蓝图 revision，已创建的待建订单继续使用不可变旧 revision。
- [ ] 旧本地蓝图、旧交换文件和缺少该字段的蓝图统一按安全默认值“部署后停用”处理，不能猜测旧来源状态。

### 10.3 微型黑洞部署行为

- [ ] 直接部署自动启用蓝图时，新实体落地即设置为可运行状态，不再要求玩家选中建筑后逐台点击“启动微型黑洞”。
- [ ] 缺料灰模订单保存同一目标状态；主体材料补足并原子建成后立即应用，不能在排队过程中丢失。
- [ ] 如果装置已启用但暂时没有输入线路，状态显示“等待连接物资输入”；后续接线后自动开始销毁，不需要再次启动。
- [ ] 如果蓝图记录为停用，新实体必须保持停用。玩家之后手动启动时继续执行现有危险操作确认流程。
- [ ] 蓝图部署只继承启用意图，端口 `totalDestroyed` 必须从 `0` 开始，`currentItemId` 只由新线路或新输入重新识别，不能复制来源装置的累计销毁量和历史物品。
- [ ] 蓝图中的线路、端口索引和物品类型继续按现有规则部署；自动启用不得绕过线路端点校验，也不得销毁没有通过合法线路进入的物资。

### 10.4 危险操作保护

微型黑洞会永久删除物资，因此“自动启用”不能成为恶意导入蓝图的静默破坏入口：

- [ ] 精简蓝图卡片和详细页都显示醒目的“部署后自动启用 · 永久销毁输入”状态，不把它藏在二级文字里。
- [ ] 玩家从自动启用蓝图进入一次部署会话前，集中显示一次危险确认；确认后该次连续放置的装置落地即生效，不再逐台确认。
- [ ] 取消部署、切换蓝图或关闭页面会结束本次确认范围；下次重新部署再次确认。确认属于瞬时 UI 安全状态，不进入存档或蓝图交换文件。
- [ ] 从外部导入的自动启用蓝图必须走同一确认，不能信任交换文件中的任何“已确认”字段。
- [ ] 蓝图文件只能表达“希望自动启用”，不得持久化或导入 `blackHoleActivationConfirmed` 这类安全确认字段。

### 10.5 不应直接复制的其他巨构状态

- **时间扭曲装置**：不能因蓝图部署自动进入纯挂机并冻结玩家界面；只复制建筑本身，是否开始纯挂机仍由玩家主动操作。
- **建筑制造中心**：不能整体复制正在进行的递归任务、WIP、累计产量或隐藏缓存；目标库存和启停需要另行设计后才能加入蓝图。
- **宇宙物资出口或活动巨构**：不能复制累计提交量、任务进度和服务器贡献，只能在专项审计后考虑复制本地输入模式。
- **物流塔量子目标**：继续使用已经规划的 `quantumTarget` 语义，不与本次巨构启用字段混成一个不透明的通用对象。

### 10.6 导入、保存和迁移

- [ ] 蓝图导出和导入往返保留自动启用布尔值；只允许支持该语义的建筑携带该字段，其他建筑出现时返回具体字段错误或安全忽略并报告。
- [ ] 新字段是可选字段；旧蓝图缺失时保持关闭。若实现因此升级 `GameState.version`，迁移只补安全默认值，不重建实体、线路、蓝图 revision 或施工订单。
- [ ] 保存 envelope 和云 schema 不因一个蓝图可选字段单独升级；本地、云端和跨设备往返后目标状态保持一致。
- [ ] 蓝图不可变版本快照必须包含该字段，避免玩家修改蓝图库条目后改变已经放到画布上的灰模订单。

### 10.7 必须通过的回归

- [ ] 活跃且已确认的微型黑洞 -> 创建蓝图 -> 直接部署：新实体立即可运行，合法输入在下一次结算被销毁。
- [ ] 暂停微型黑洞 -> 创建蓝图 -> 部署：新实体保持暂停，输入不得被销毁。
- [ ] 自动启用蓝图 -> 缺料排队 -> 多次补足 -> 建成：启用意图全程保留且只应用一次。
- [ ] 旧蓝图和缺字段交换文件部署后保持暂停，不发生意外销毁。
- [ ] 自动启用导入蓝图在进入放置前出现危险确认；取消确认不修改库存、蓝图或施工队列。
- [ ] 来源累计销毁量大于安全整数时，新实体仍从 0 计数；端口历史、缓存和当前物品不泄漏到新实体。
- [ ] 旋转、镜像、连续放置、撤销/重做、保存重载和跨端导入后状态一致。
- [ ] 自动启用与手动启用路径销毁相同数量，状态哈希确定，传送带物资不重复扣除或凭空消失。
